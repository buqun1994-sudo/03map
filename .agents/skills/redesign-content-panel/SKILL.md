# 内容区视觉审计与返工

## 触发与目标

当任务涉及内容区 UI 看起来不对、视觉复刻、状态缺失、控件质感、媒体卡、Dock、顶栏、车控按钮或系统滑条时使用。本 Skill 只做可追溯的审计和小步返工，不把网页设计规则直接套到 Android 车机。

必须先输出诊断，再修改代码；除非用户明确要求立即修复，否则先等待确认。用户明确要求“完成审计并开启目标功能”时，可以在诊断后继续实施，但仍要保留审计记录和变更范围。

## 必读输入

1. `AGENTS.md` 和 `docs/README.md`。
2. `docs/product/产品需求基线.md`。
3. `docs/architecture/内容区主链.md`。
4. `docs/plans/SVG内容区复刻施工方案.md`。
5. `docs/testing/验证矩阵.md` 及最近的内容区验证记录。
6. `docs/code-map/主链索引.md`。
7. 任务涉及的正式源码、资源、测试和构建脚本；以磁盘内容为真值。

## 设计系统适配

- **字体**：采用外部 skill 的批准字体倾向：Geist、Manrope、Poppins、Geist Mono；禁止把 Roboto、Arial、Helvetica 等当作设计选择。Android 若目标 APK 没有对应字体文件，必须先确认可用字体资源或记录 fallback，不凭字体名宣称完成。数字和状态值使用等宽数字／tabular 语义，避免车机读数跳动。
- **尺寸**：采用外部 skill 的封闭 spacing／radius 令牌，不随意创造间距；所有令牌先换算到实际 Android dp/sp，再以 141 DPI 车机截图校准，不把 SVG 像素直接当 dp。
- **颜色与背景**：深浅主题都是真实目标。禁止无依据的背景渐变和紫蓝 AI 渐变；允许真实媒体封面驱动的唯一全局氛围背景，必须随媒体身份、播放状态、主题和生命周期正确停播／回退。
- **图标**：外部 skill 的图标库建议不适用于本项目；用户可见图标继续只能来自已登记的原厂资源，资源来源和 hash 必须闭环。
- **网页交付项**：hover、网页 focus、404、SEO、meta、legal links、cookie consent 和营销 CTA 不属于车机内容区审计；只有存在对应 Android 语义时才审计等价的按下态、无障碍描述、错误态和返回路径。


按以下顺序检查，并为每项标记：通过、问题、待验证；同时记录文件和方法、证据等级、影响和最小修复建议。

1. **物理边界**：内容层是否只挂在既有地图 Activity 根布局；是否误改 `SplitPanelController`、地图 Surface、125% 密度、包名或签名。
2. **数据与 owner**：UI 是否只投影 Store／Snapshot；是否在 Renderer 中伪造车控、媒体、充电或持久化真值；点击成功是否错误地当成状态成功。
3. **整体结构**：顶栏、页面、控制卡、媒体卡、Dock、来源弹层是否符合产品基线；快捷页与 Dock 是否共享同一快捷项清单；不得用占位控件撑密度。设置可以作为共享快捷项出现在快捷页和 Dock，禁止额外铺设独立“设置暂不可用”横条。
4. **视觉令牌**：浅色参考态使用 `#F4F4F4`、`#E9E9E9`、白色表面、`#27303B` 主色和 `#666666` 辅助字；深色态必须有对应的完整层级，不能把浅色图简单反相。两种主题都要检查背景、表面、文字、选中态、阴影和对比度；默认参考画布 `640×1080`，实际字形和控件以 141 DPI 车机密度校准；四列锚点与媒体／Dock 固定区域必须有截图证据。
5. **表面层级**：填充、选中底、柔和阴影、局部分隔线分离；禁止公共描边函数给所有控件强制加边框；媒体卡和 Dock 不得多层套框。
6. **排版和几何**：时间默认按内容区几何中线；里程不加“续航”前缀；单行状态不重叠；字号、density、触摸热区分别验证。
7. **交互状态**：默认、按下、选中、拖动、待确认、成功回流、失败／超时回弹、空媒体、无能力、主题切换和生命周期暂停／恢复都要有明确表现。
8. **动效**：采用外部 redesign-skill 的有重量缓动，不使用默认 `ease` 或 `linear`；页面和明显状态转场使用 `cubic-bezier(0.32,0.72,0,1)`，必要时约 `700ms`，进入视口的内容使用 `IntersectionObserver` 等价的宿主机制并约 `800ms`；微交互不低于 `200ms`。Android 车机没有网页滚动事件时，只把相同时间曲线和渐进原则映射到 View／Animator，不引入网页 API。暂停或销毁时取消回调和动画。
9. **资源**：图标只能来自已登记的原厂资源；资源路径、原始哈希、包内资源和 manifest 可追溯；不得用 SVG 示例图标或临时占位代替。
10. **可访问性与工程质量**：内容描述、触摸热区、状态反馈、UTF-8、最小编译和测试探针保持可维护；不得引入未登记依赖或网页专属规则。

## 当前允许的目标功能

只有已有产品／架构文档和正式端口支持的功能才能开启：

- 快捷页与 Dock 共享的快捷项，包括车锁、三类座椅控制和设置入口；设置未就绪时只在点击反馈中提示，不额外铺设横条。
- 车锁、主驾通风／加热／按摩都是圆角方形多状态按钮；座椅档位只经既有 Store／Port 命令链回流，按摩不得重画为纵向滑条。
- 纵向滑条只用于屏幕亮度和媒体音量；仅在系统能力证据和现有 `ContentSystemSlider` 端口成立时开启，不得伪造车控或越权调用系统全局 API。
- 五种媒体来源的原厂图标与显示名、来源弹层。
- 单层横向媒体卡、真实媒体空态和 Dock 层级。

“开启”必须同时满足：源码实现、状态 owner、资源／配置、自动化或宿主探针覆盖、静态检查通过。没有真实能力证据的控件只能显示未就绪状态，不能通过占位 UI 宣称完成。

## 修改边界

优先原位修改 `ContentRenderer.java`、`ContentTheme.java`、`ContentIconView.java`、`ContentRuntime.java`、现有 Store／Adapter 和对应测试。新增 Java 类型前必须证明原位扩展不足，并完成最小编译。不得修改：

- `SplitPanelController.smali`、两条地图 Surface 或地图分屏几何。
- 包名、签名身份、车控 Binder 常量、权限路径和历史悬浮分支。
- 原始 APK、密钥、完整设备日志、截图和临时解包目录。
- 与目标无关的网页字体、Tailwind、SEO、hover、404 或营销组件规则。

每轮只处理一组同源问题；不要借审美返工重写数据主链或迁移技术栈。

## 验证与交付

修改后依次执行：

1. `git diff --check`。
2. `node scripts/check-project-docs.mjs`、`node scripts/check-skills.mjs`、`node scripts/check-code-map.mjs`。
3. 与改动对应的内容资源／DEX检查和本机内容宿主测试。
4. 能构建时从正式 `source/` 执行项目规定的构建脚本并核对包身份；未获安装／车机授权时不安装、不写车控。
5. 视觉改动必须提供 `640×1080` 关闭／展开态或等价宿主证据，并记录固定锚点、状态、残余风险。

交付报告必须分为：已修复、已验证、待验证、明确未做；引用文件和方法，不能用“整体试一下”代替证据。

## 设计值适配原则

以产品基线和 `docs/plans/SVG内容区复刻施工方案.md` 确定整体构图；同时积极采用外部 redesign-skill 的字体倾向、排版节奏、封闭 spacing／radius 令牌与有重量动效，经 Android 实际字体资源、141 DPI 和双主题运行截图校准。浅色 SVG 不是唯一主题，真实媒体封面驱动的氛围背景必须保留。网页专属 API、Tailwind 实现、长滚动 reveal、外部图标库和固定单主题色值不进入 APK。
