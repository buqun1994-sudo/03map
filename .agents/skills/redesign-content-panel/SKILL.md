# 内容区视觉审计与返工

## 触发与目标

内容区视觉返工、状态补全或目标功能开启时使用。记录问题、实际证据和最小修复；用户已要求修复或完成目标时，诊断后直接实施。仅要求 review、方案或只读分析时按该范围输出。

## 输入与当前入口

1. 根 `AGENTS.md`、`docs/README.md` 和 `docs/product/产品需求基线.md`。
2. `docs/architecture/内容区主链.md`、`docs/code-map/主链索引.md` 中与目标相关的章节。
3. 涉及的正式源码、资源、测试、构建脚本和最近验证记录；验证动作见 `docs/testing/验证矩阵.md`。
4. 当前正式 UI 在 `source/amap-9.5.0.600013/content-compose/`；旧 `ContentRenderer` 及旧视觉计划只提供历史线索，不能覆盖当前产品行为。需要 SVG 对照时读取对应设计和计划中仍适用的部分。

## 判断与施工

- **整体画面：** 比较顶栏、页面、媒体卡、Dock 和来源层的结构、文字重量、留白、填充、阴影及关键状态，不只摘取颜色或局部尺寸。产品基线和用户本轮要求决定设计，外部 Skill 的字体名单、封闭间距、禁止渐变及固定时长不作为额外约束。
- **真实尺寸：** 区分 px、dp、sp、系统密度和地图 125% 配置；按当前设备证据检查可读性、触摸热区及窄幅布局，不固定继承历史 141 DPI。字体以实际 Android 资源和可读性选择，说明 fallback，不禁止 Roboto 或系统字体。
- **状态与职责：** UI 投影 Store / Snapshot，车控、媒体、来源和系统能力分别消费实际状态；命令发送不直接判成功，反馈包含待确认、拒绝、断连、超时和回弹。保持唯一业务状态与地图几何来源，必要的依赖修改随用户目标完成。
- **资源：** 用户已要求的原厂图标与动效保留来源、路径和哈希；示例图标或静态截帧不能被称为已接通的原厂能力。新增依赖按真实构建兼容和版本 / SHA 锁定要求验证，登记与施工同步。
- **交互：** 检查按下、取消、连续点击、拖动、菜单、翻页和生命周期；动画可以中断、停止和恢复，不用外部默认时长替代实际手感与当前产品语义。
- **功能：** 已有入口沿既有 Store / Port / Adapter 接入；用户提出新功能时可同步扩展和验证，不因文档尚未预先登记而阻止施工。未接通能力显示真实未就绪状态，不能用模拟回流宣称实车完成。

优先修改代码地图定位到的当前 owner，可按职责新增类型或调整依赖，完成对应编译与验证。地图几何、包身份、车辆协议等是否修改由任务和实际依赖决定，不设永久“不能碰”清单。用户现有改动保留，输入归档与历史证据不冒充新包结果。

设备验证依用户目标和 `docs/security/安全与密钥边界.md` 的具体个人风险执行；普通保留数据安装不另设许可，已要求的控制验证不逐操作重新授权。

## 验证与交付

1. 执行 `git diff --check` 和三项仓库自检。
2. 运行与改动相关的内容资源、DEX、状态、宿主或渲染检查；需要交付 APK 时从正式源码走 `scripts/build-content-apk.sh`，核对同一包身份。
3. 视觉改动实际查看对应密度、画布与关键状态的 Android 绘制帧；本机证据、车机运行和用户审美判断分别如实报告。
4. 交付说明实际修复、验证结论、证据位置和未完成的具体原因，给出剩余最小现场动作；报告格式按任务复杂度选择。
