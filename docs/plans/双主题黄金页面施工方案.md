## 一、施工目标与边界

1. 在高德 `9.5.0.600013`、125% 全屏输入派生的**同一个 APK**内，完成左侧内容区约 `1/3`、右侧真实高德地图约 `2/3` 的浅色／深色黄金页面。首帧、分屏收放、三种地图视角和导航能力沿用既有主链，不重做地图。
2. 黄金页面覆盖现有默认 `lyrics` 页的正式空态、顶栏、媒体／空调控制卡和固定车锁加五槽 Dock；同轮将已可见的 `shortcuts` 页采用同一套视觉组件，保证页面切换后不回到另一套粗糙样式。保持 `shortcuts → lyrics` 和默认 `lyrics`，不把快捷页改成默认页。
3. 同轮解决已实机反馈的两个直接破坏黄金页面的问题：页面／控制卡露出相邻项，以及媒体氛围背景只在歌词页出现。它们分别由独立可视 viewport 和内容宿主全局背景层处理，不用遮挡条、固定截图或重新计算地图几何掩盖。
4. 参考图中的设置页只用来定义日后可复用的分类、选中、分段控制与滑条视觉样板。本轮**不新增完整设置页、原厂车辆控制、泊车、车机 Launcher 或车控权限**；当前设置入口不能假装已经可用。
5. 用户的优先级是**尝试复用车机原有动态图标**，不是一看到静态证据不足就停工。先做兼容性试验，再决定在同 APK 中的可靠承载方式；最终不能把未跑通、截帧或私有组件依赖说成“已复用动态图标”。

## 三、视觉系统与可验收参数

1. **共同骨架：** 顶栏 → 当前页面 → 控制卡 → Dock；内容底色覆盖该四层的下方。内容／地图边界为安静的 `1dp` 表面分界，可见手势条的触摸与位置仍由地图主链拥有。页面、控制卡、Dock 都使用同一组背景、表面、文字、分界与状态语义。
2. **首轮候选令牌：** 浅色背景 `#EDF2FA`、主卡 `#F6F8FC`、主字 `#202633`、次字 `#5B6474`；深色背景 `#17191D`、主卡 `#25282D`、主字 `#F4F6FA`、次字 `#ADB5C2`。其余提升层、分界、强调／警告／错误／不可用色从 `ContentTheme` 同步派生，不在卡片里散写常量；浅／深不是反相。主题过渡沿用当前 `240ms`，仅高德主题回调能改变主题状态。
3. **空间与可点击性：** 以实际内容 viewport 的 `dp` 宽度为输入，首轮候选边缘留白 `16dp`、卡片间距 `8dp`、主卡圆角 `16dp`、次级按钮圆角 `12dp`、图标内容框 `28–36dp`；可点击热区每边至少 `48dp`。顶栏沿用现有 `72dp`、控制区现有 `126dp`、Dock 现有 `88dp` 作为起点；若目标设备字体放大或实际高度产生遮挡，只调整同一组令牌／组件合同，不逐控件临时缩字。内容宽度低于 `360dp` 时快捷项从两列退为一列；大于等于 `360dp` 时仅在单项扣除间距后仍有 `144dp` 时用两列。
4. **文字层级：** 主要状态 `20–22sp`、卡片标题 `15–17sp`、辅助信息 `12–14sp`；数值与单位明确分层。主字对所在背景对比至少 `4.5:1`，关键图标／选中边界至少 `3:1`；无状态或不可用信息仍须可读，不靠单独降低整体 alpha 到不可辨认。歌词无数据时用“暂无歌词”及用户可执行的下一步，不写“下一轮接入”或伪造曲目信息。
5. **视觉节制：** 浅色靠背景／卡片明度差及 `1dp` 细边界建立层级，深色靠三阶明度而非大片纯黑和强阴影；状态色只用于正在播放、已选中、充电等有真实状态的部位。媒体播放且有真实专辑封面时，氛围背景位于顶栏、页面、控制卡和 Dock 下层；无封面或停止播放回到主题底色，不把封面染色写进歌词页局部。
6. **截断门槛：** 顶栏时间、电量、车内温度不得互相压住；曲名一行省略，来源／歌手一行省略，数值与单位不裁掉。页面和控制区任一稳定态下，相邻页／卡露出面积为 **0px**；过渡中仅当前手势预期可见，Dock 与地图边界不跟着错位。目标屏幕的截图标注值由实测 `px / density` 回填，不能倒用理想照片像素。

## 四、图标盘点：先探索，再确定运行方式

本机忽略区 `.tmp/icon-inventory-20260928/` 已静态发现 `com.android.systemui.plugin` 的 Lottie 风格 `assets/ico_*.json`；示例文件带 `fr`、`ip`、`op`、`layers`，含关键帧，部分有表达式或预合成。另有 `com.chery.carsettings` 的 `.pag` 和资源。`com.android.launcherMB`／`com.android.systemui` 解包中能看到 Lottie 播放类，**高德正式源码中未见该播放类**。这些是静态线索，不等于高德 APK 可跨包直接调用 OEM View，亦不等于每个 JSON 都要常驻循环。车机来源、许可与包内分发边界必须由施工方按当前授权核对；不提交原始系统 APK 或整包解包目录。

| 现有 UI 语义 | 优先试验的 OEM 资产（均为上述忽略区 `plugin-decoded/assets/` 下的 JSON） | 状态与待证实点 |
|---|---|---|
| Dock 车锁 | `ico_lock.json`、`ico_lock_close.json`、`ico_lock_open_f.json` | 已锁／解锁／状态未知；动画方向与主题颜色要在目标设备看实际帧 |
| 媒体播放 | `ico_media_play_f.json`、`ico_media_pause_f.json`、`ico_media_pause_play.json`、`ico_media_prev.json`、`ico_media_next.json` | 播放／暂停切换、不可用；验证静态稳定帧与单次过渡，不因 Store 重发每次重播 |
| 座椅通风 | `ico_skin_seat_ventilate_l_off.json`、`ico_skin_seat_ventilate_l_1.json`／`_2.json`／`_3.json` | `-1` 不可用；`0` 关闭；`1–3` 档；档位须来源于快照，左右座椅不能混用 |
| 座椅加热 | `ico_skin_seat_heat_l_off.json`、`ico_skin_seat_heat_l_1.json`／`_2.json`／`_3.json` | 同上；该组有预合成，先确认解析器能渲染所有帧／依赖，再接入 |
| 座椅按摩 | `ico_skin_seat_massage_l_bk.json`、`_bk2.json`、`_bk3.json` | 颜色／档位语义未实机确认；先看 0–121 帧效果和原厂调用，再映射，不按文件后缀猜 |
| 快捷／设置 | `ico_home_applist.json`、`ico_home_small_app.json`、`ico_home_carset.json`、`ico_sys_setup.json` | 图形语义、浅／深色、稳定帧；与 `shortcuts`／`settings` ID 不可仅凭同名推断 |
| 电量／空调 | `ico_battery_charging.json`、`ico_charge.json`、`ico_ac_cool.json`、`ico_wind_hi_dock.json` | 仅在真实充电、空调状态可对应时动画；不可用不假演充电或吹风 |

**试验顺序：** ① 在独立忽略副本里尝试同 APK 的最小 Lottie 解析／播放，先验证一个无预合成图标和一个有预合成座椅图标，检查浅／深色、首帧、最后稳定帧、切状态及停播；② 检查现有高德包有没有可利用的合法播放能力，或在 Java/D8/API 21 构建链内引入受控、可维护的兼容播放实现，比较包大小与启动、滑动时帧耗；③ 仍无法稳定播放时保留问题和对照证据，讨论单独资产适配方案。不要把“Android 上另一个包带 Lottie 类”当成高德内可用，不复制 OEM 私有整类库或通过跨包类加载制造运行依赖；也不能用截图截一帧冒充动态图标。最后一个动作是**交付判定**，不是前置禁止探索的门禁。

图标绑定用 `ContentRegistry` 稳定 ID、`ContentState` 的主题／档位／播放／锁定／可用状态派生；同一语义的浅／深色资源或换色策略必须实机验证。仅在状态**变化**时按资源定义播放一次或进入经证实的循环段；页面隐藏、地图收起、Activity 暂停／销毁时停止／释放，重新挂载从当前 Store 快照恢复稳定状态。功能未知仍可展示图标，但须有明确不可用状态且不发车控命令。若个别图标卡住，先隔离该项，其他视觉组件可继续施工；黄金页不能宣称该图标已动态复用。

## 五、物理路标与执行步骤

**唯一正式代码入口**：`source/amap-9.5.0.600013/`（输入 APK 身份见 [基线清单](../code-map/基线清单.md)，原始解包提交 `ac6033c`）。`apk-work/` 只供试验；本轮可维护 Java／Smali／资源最终回写正式入口，并只从正式入口构建。新建 Java 文件若经试验证明必须存在，目标目录是 `content-src/com/autonavi/amapauto/content/`，包名、文件头、依赖和 Java 8／API 21 约束**逐字从 `ContentIconView.java` 或 `ContentRenderer.java` 复制**；目标类型的职责必须先明确为“图标加载与生命周期”或“共享视觉令牌”，不能混入 Store／地图几何。新建后立即核对 package、类型、构建脚本的 `find *.java` 包含关系并运行 Java 最小编译，未通过不得继续扩写。优先原位扩展既有类型，不为一页增设一套并行架构。

1. **获取目标设备尺寸和基线截图（只读／低成本）**：通过项目统一设备发现入口，记录屏幕 `px`、`density`、现有 `content_host` 可视宽高、浅／深色当前展示和地图边界；与用户已有“漏相邻页”的反馈同屏对齐。没有在线设备也继续静态方案和资产试验，但运行结果保留“待实机”，不可凭参考照片宣称完成。
2. **先修内容 viewport**：`ContentRenderer.buildPages()`、`buildControls()`、`updatePanelWidth()`、`pageWidth()`、`pageLayoutParams()`、`cardLayoutParams()`、`renderPage()`／`renderControl()` 和内部 `ContentPager.dispatchTouchEvent()`／`onInterceptTouchEvent()` 为落点；令 `viewportWidth = panelWidth - 2 × 内容边缘留白`，每个稳定页／卡恰占其独立 viewport 宽，裁剪在 viewport 而非条目背景，吸附偏移由 viewport 步长派生。分屏宽度变化和全屏收起时重算，当前 ID 不改变。施工前 `pageWidth = panelWidth - 28dp` 加 `10dp` item margin 的结构需重新核对，不能靠把第二页涂成背景色遮挡。拖拽响应、吸附和平滑过渡同一进度路径，用户已反馈僵硬；先用目标设备调整动画，默认一次吸附 `180–260ms`、释放预测窗口不大于 `350ms`，不修改地图手势吸附值。
3. **视觉令牌和组件**：`ContentTheme.light()`／`dark()`／`interpolate()` 管主题角色；`ContentRenderer.buildTopBar()`、`buildMediaCard()`、`buildClimateCard()`、`buildDock()`、`buildShortcutsPage()`、`buildLyricsPage()` 与 `applyThemeTree()`／`applyThemeToView()` 消费令牌。同一组件跨两色保持信息结构；`renderTopBar()`、`renderMediaState()`、`renderTile()`／`renderDockState()` 实现正常、选中、不可用，而不是以页面索引或 Android 系统主题猜状态。设置入口保持当前语义，若不能进入真实设置就清楚标“暂不可用”，去除用户可见的施工 Toast 文案。
4. **媒体氛围背景**：`ContentMediaAdapter` 从真实 `MediaMetadata` 读封面时，先通过 `ContentPorts.MediaSnapshot` → `ContentStore.acceptMediaSnapshot()` → `ContentState` 形成统一快照，再由 `ContentRenderer.build()` 在顶栏／页／卡／Dock 下创建内容区**唯一**背景。图像采样与模糊不可在主线程反复执行；以媒体身份／封面变化去重，页面切换不重新计算。播放中且封面有效才显示；暂停、停止、切源无封面、权限不足立即回退主题背景；不得伪造封面或把来源 URL 写进页面。现有快照只有标题、歌手、播放状态，没有封面字段，故这一步是端口／状态／适配器的贯通修改，不是给歌词背景加渐变。
5. **图标接入试验与替换**：`ContentIconView.setIcon()`／`onDraw()` 及 `ContentRenderer.createShortcutTile()`／`createDockButton()`／`createControlButton()`、`renderMediaState()`、`renderTile()`／`renderDockState()` 为现有路径；优先保持现有逻辑 key 的外部合同，再将已验证资源映射到适配层。不能让页面类直接打开 `.tmp/` 路径、通过其他安装包的私有资源 ID 加载，或引入第二套 `themeMode`。替换一组就做最小编译与样机观察，最后再替换下一组。原有 Canvas 绘制只有在该项有明确交付说明时才暂存，不能悄悄被称为 OEM 动态资产。
6. **生命周期与地图耦合审查**：`ContentRuntime.attach()`／`detach()`、`onAmapThemeChanged()`、`onDividerChanged()` 是唯一入口。地图几何的 `SplitPanelController.applyDividerX(F)V`、`map_surface`、`ui_surface` 与高德 native 视口保持原样；内容 `updateDivider()` 只消费统一位置。新图标／封面缓存解绑须与 `ContentRenderer.destroy()` 对称，不能让动画持有失效 Activity。

**绝对不碰：** 包名、签名身份、125% 密度链、原始输入归档、历史 `480×480` 悬浮链、native 地图相机修正、车辆属性和写入端口、原厂系统 APK；未经本轮授权不做卸载／清数据／降级／Release 安装／车控写入。第三方图片只用于取样与评审，不纳入 APK 资源。

## 六、测试闭环（带层级和证据）

后续施工必须通过本节标记“必须通过”的项目；任一失败就只报告候选和阻断，不能称为黄金页完成。优先逐组件最小检查，再走整包和实机；不以截图静态模拟替代运行。

| 层级 | 必须通过的动作 | 可观察结果／证据 |
|---|---|---|
| 静态／编译 | 新增或调整的 Java／资源从正式源码编译；资源路径、package、DEX 注入与 `ContentTheme` 调用一致；`git diff --check` 与仓库三项自检通过 | Java／D8／APKTool 无错误；Git 只跟踪可维护源码和文档；图标来源、主题与状态映射可追溯 |
| 包级 | 运行 `bash scripts/build-content-apk.sh`，核对包名、版本、签名、对齐、双 DEX、`.so` Deflate、候选 APK SHA-256 | 同签名且允许 `adb install -r` 的完整候选包；无签名材料或身份冲突则记录阻断，不换证书绕过 |
