# 车控真值驱动重构方案（2026-10-03）

本轮由用户反馈触发：ripple 已通过现场测试；深色快捷选中仍为旧颜色；方向盘按钮不能点击；主驾加热在1档后无法进入自动；加热图标不能稳定跟随日夜主题。补充要求：深色Dock和媒体基础色须与快捷非选中态同色，颜色字段各自独立。先定位源码因果，再按以下职责重构。当前车机发现失败，正式包现场读写结果保留为待验证。

## 1. 已定位原因

1. `ContentPorts.VehiclePort` 默认能力把方向盘排除，并把加热限定0..3，另外拒绝从auto4退出；正式Adapter只把自动操作放在`requestResearchSeatLevelCandidate()`中。`ContentStore.isSeatCycleControlAvailable()`按下一目标判断点击可用，实际造成方向盘永久禁用、加热1档下一目标auto4时禁用。此前替身放行auto与正式默认拒绝auto的测试，验证了两套不同能力，不能证明正式交互完整。
2. Store、预览Controller与UI ripple策略分别维护档位和循环；新模式需多处同步，缺少共享的纯领域定义。transport连通、字段有效、具体协议可执行、请求待确认本应分别描述，历史验证等级却被硬编码成永久产品门禁。
3. `ContentTheme.primaryContainer`同时承载快捷选中、深色滑条填充和来源选中。快捷选中仍#484848；Dock使用另一个#303030字段，媒体按下还走E2/5C字段；Dock和媒体深色base仍#232323。不能通过改一个共享字段顺带改所有角色。
4. `OemIcon`将业务触发key、资源/主题配方和已播放帧耦合：相同档位下主题更换Vector，`playedKey==key`分支只检查asset，静态asset均为null时不会采纳新resource。资源一致时又会复用旧composition，动画配方与主题失效需要各自处理。冷资源保留上一帧的必要能力不应阻挡静态主题更新。

## 2. 真值与职责

```text
共享 VehicleControl 定义（稳定ID、合法模式、循环、自动模式、开关边界）
  ├── Store 用户意图/请求准入
  ├── UI 名称与ripple边界派生
  └── Preview 相同产品循环

原厂协议字段 → VehicleProtocol归一化 → VehicleSnapshot → 唯一ContentStore actual
用户意图 → 唯一target/requestId → VehiclePort → Adapter串行执行协议计划
实际readback → 确认/失败/断连/超时 → Store清target → UI投影

高德主题 → 独立组件颜色令牌 → 静态Vector/动画配方 → 当前可见帧
```

- 新增不依赖Android、Compose或厂商编号的`content-model`库，由UI与runtime共同消费。模式编号保持现有快照兼容；合法值、next、auto与0↔on判断只有一份定义。
- Port能力表示已实现的目标协议与当前连接；读字段有效性仍独立。去除无依据的永久research分支与产品禁用，所有已实现目标经同一正式命令链。车辆是否接受由真实回读与错误回流决定，不以queue成功确认。
- 原厂读取/写入编码仅由协议owner维护。本轮核对`SeatSettingsFragment.lambda$initHotLayout$4`的pos4自动入口写复合`0x212=8`，自动状态`0x282`只有读取；删除旧候选双写。方向盘原厂分档控制器在1档后写`0x21c=4`，自动状态`0x2a5`保持只读。自动active有效时主档位可随环境发热变化，归一模式仍为AUTO。同包未现场验证的命令如实标记，不以测试替身冒充车机闭环。
- Store保持单一pending和请求代数、6秒超时、拒绝/断连回弹；actual只由Snapshot更新。循环解析和目标锁存在同一锁内；实际模式与Store准入能力也在同一锁内发布不可变快照。Binding只路由稳定控制ID并消费该快照，Mapper只投影actual/target/能力，不复制循环或厂商协议。
- 网格、Dock与媒体各自有独立颜色字段：深色快捷base、Dockbase、mediabase各独立声明#1A1A1A；深色快捷selected、Dockselected、媒体pressed各独立声明#303030。浅色Dockselected、媒体pressed各独立声明#E9E9E9，与快捷base同色但不相互引用；浅色快捷selected保持#E4E4E4，Dock/媒体base保持白色。滑条与来源保留各自颜色字段，不再搭载快捷selected。
- 共享定义同时区分模式上限与手动档位上限；`maxManualLevel`从合法循环派生，自动编号不参与手动Lottie档段计算。
- 按用户最新说明，通风与加热的相互处理由原车系统负责。应用只发送所点击按钮的目标并解码各自回报，不新增互斥、先关闭另一功能、补偿写入或跨控制验收专项。
- 图标的业务动效触发与资源/主题配方分离。静态资源立即投影当前主题；主题变化不重播档位动画；异步新动画未就绪保留旧有效帧，加载就绪原子切入，取消/后台仍回稳定图标。

## 3. 实施与证据

1. 先固定共享领域定义与构建包含关系，再让正式Store/Port、UI和预览逐项改为消费；协议实现接入已核对的原厂语义。
2. 回归必须经过默认正式端口：方向盘完整循环与加热1→auto→off，不能只测试另行放开的candidate替身。覆盖非法/未知、单pending、拒绝、断连、超时与迟到失败。
3. Android实际帧验证同一Composition内日→夜→日：加热关闭/手动/自动、方向盘静态Vector、已播放动画末帧；检查资源和实际像素，不只比较Tint/ID。保留ripple起中末、CANCEL、边缘热区与生命周期用例。
4. 独立颜色字段分别取像素，并用不同测试调色板验证无角色串用；双主题、141/212/320dpi最低回归保持。
5. 相关单测与Lint通过后，由正式源码走强制签名构建，核对资源/DEX/签名/原生库。重新发现合法车机，在线时保留数据安装、启动与最小日志；离线如实报告未安装，交付当前签名包和明确现场最小项。

产品事实更新产品基线；owner更新内容区主链；入口更新代码地图；本轮执行结果单独进入验证记录，旧记录保留历史身份。
