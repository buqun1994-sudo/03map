# 内容区多指方向手势最终施工方案（2026-10-10）

**状态：2026-10-15已按本方案接入正式源码，源码回归／签名构建与同包设备边界由[本轮验证](<../testing/内容区多指手势接入验证-20261015.md>)维护。** 本文仍是识别规则与施工参数的唯一入口；两份[技术研究](<../research/内容区多指方向手势技术方案-20261010.md>)／[开源核对](<../research/内容区多指手势成熟开源算法核对-20261010.md>)保留证据，不覆盖本文决定。功能默认值与用户配置由[设置项清单](<../product/设置项清单.md>)维护，不再作为需求待补项。

## 1. 技术决定

- 基础依赖固定为工程已有的 **AndroidX Compose Foundation 1.7.6**。使用其公开`calculatePan`、`calculateCentroidSize`、`calculateZoom`、`calculateRotation`与`awaitEachGesture`；不另写触点中心或多点平均位移算法。已核对该版本官方源码，直接调用真实AAR的8组辅助函数测试通过，证据见[开源核对第6节](<../research/内容区多指手势成熟开源算法核对-20261010.md#6-本轮实际官方依赖核验>)。
- 方向采用已核对的RNGH向量归一化／点积方向锥方法，输入为本组累计**位移**；只比较上／下／左／右四个单位方向。不接入RNGH运行时、Fling速度门槛或方向位掩码组合。
- 在内容区建立一个统一识别核心、一个Compose输入适配器和一个业务路由。组件不各自再识别同一多指命令。
- 第一版只输出 **2／3／4指 × 上／下／左／右，共12类离散结果**，一次正常手势最多提交一次。不做连续调节、长按多指或双击多指。
- 库选择、坐标身份、组装／冻结／取消及提交规则固定。施工测试修正实现缺陷；现场标定只修改本文统一列出的参数，不重新比较方案。

## 2. 输入范围与模块职责

输入落点为[ContentPanel](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentPanel.kt#L144>)根`BoxWithConstraints`的祖先Modifier，使用该父节点局部坐标及真实可见区域。指数量是**本内容输入序列中按下的全部触点数量**，不能从其中挑选一个2／3／4指子集。所有组内触点须始于可见内容区；组内触点在有效MOVE越界则取消。内容区之外的独立输入不纳入本组。

[SplitPanelController](<../../source/amap-9.5.0.600013/smali/SplitPanelController.smali#L595-L599>)仍负责地图收放条输入与唯一Divider几何，内容多指识别不安装地图全屏拦截层。窗口／几何／生命周期取消由[Host](<../../source/amap-9.5.0.600013/content-compose/host/com/icar03/content/host/ContentComposeHost.kt>)及现有呈现门禁提供。

新增文件名称固定如下（此时尚不存在）：

| 新增模块 | 职责 |
|---|---|
| `MultiFingerGestureCore.kt` | 纯Kotlin会话状态、ID集合、位移及不可变结果；无View／Compose协程／业务调用，接收标准化输入帧与官方计算指标 |
| `MultiFingerGestureModifier.kt` | Pointer Input Initial／Final适配、调用官方多点函数、触点类型与坐标检查、消费、子控件取消、finally清理 |
| `MultiFingerGesturePolicy.kt` | 统一参数、四轴方向锥、逐指一致性与变换拒绝规则；不包含车辆功能映射 |
| `MultiFingerGestureRouting.kt` | `(fingerCount, direction)`到已明确业务事件的唯一映射及最终资格检查；无直接Binder或车辆协议调用 |

以上放入当前正式`content-compose/ui/com/icar03/content/ui/`目录，测试归入现有`ui-preview/content-ui/`测试模块。输入帧包含会话内非递减uptime时间、当前／前次按下状态、PointerId、坐标和事件类型；以ID查点，禁止保存index作为长期身份。新按下与抬起使用状态变化判定，抬起后ID复用属于新触点。

仅在正常、可交互的快捷／歌词内容页准入。设置、来源浮层、独立登录窗口、模态遮挡、页面或地图转场、宿主停止及几何未就绪时拒绝；进行中出现这些变化则取消。使用最新资格和会话代际，不以每次媒体快照重组作为pointerInput的重启键。

## 3. 统一参数：施工默认值已定

这些是本项目第一版的施工默认值，**不是已完成车机标定的结论**。统一放入Policy；回放边界由同一参数驱动，不在各控件分散常量。

| 参数 | 固定默认值／比较规则 |
|---|---|
| 落指组装窗口 | 从首指DOWN起 **150ms**；时间相等允许加入，超过不允许；新增指不延长窗口 |
| 首指保持单指资格 | 首指未超过当前`viewConfiguration.touchSlop`且子控件尚未取得单指拖动／长按所有权 |
| 组装中再加指允许的既有位移 | 现有各指从上次整体基准起的位移长度均不超过 **24dp**；超过则拒绝此次多指会话，不能降档触发 |
| 群组主轴累计位移 | **至少48dp** |
| 每指同向主轴累计位移 | **每指至少24dp**，相同方向且均处于方向锥内 |
| 四轴方向锥 | 每个轴两侧各 **30°**；归一化点积必须严格大于`cos(30°)`；边界与轴间模糊区域拒绝 |
| 各指主轴位移差异 | 最大值 **不超过最小值的2倍**；比较前每指已满足正向24dp，避免除零 |
| 允许累计缩放 | 相对最后加入触点时的基准保持 **0.85～1.15**，含边界；超出记录该组越限，锁定后立即取消 |
| 允许累计旋转 | 相对同一基准的累计角度绝对值 **不超过12°**；超出记录该组越限，锁定后立即取消 |
| 速度／整段时长 | 不设必须甩动的速度下限，不套用Fling的800ms总时限；正常慢滑可识别 |

距离使用内容区LocalDensity转换为px，不复用高德地图125%密度。仅接受Touch触点，**有限坐标与可见边界校验用于建立基准的DOWN及完整MOVE，不检查正常释放帧的坐标**；重复ID、时间回退、非法状态及零半径退化的多点组取消。保持固定群组的MOVE上用官方函数积累pan、zoom和rotation；每次合法加入触点重建整组起点，同时清零pan／rotation、zoom归1。逐指位移仅为按ID相对起点的减法，用于共同移动与异常离群检查。

四轴结果在冻结时以最终平均位移所在方向锥确定，并要求每根手指同时通过上述距离、方向及比例规则；不取整段峰值或只看一根手指。**早期MOVE未达到48dp／24dp、方向暂不清晰或各指短时不同步，只继续观察，不因此提前取消**；这些是冻结时的有效性门槛。缩放／旋转超限是该组的沿途拒绝条件，不能结束前转回来后重新变成有效命令：组装期记录当前暂定组的越限标志，合法加入新指重建整组基准时一并清除旧组标志；锁组或提前UP时若最终组已有越限标志则拒绝，锁定后越限立即取消。无完整有效MOVE样本不识别；不平滑、夹紧或猜测驱动异常坐标。

## 4. 会话状态与事件顺序

状态为`Idle → ObserveSingle → Assemble → Track → Frozen → Idle`；拒绝／取消后进入`Drain`等待本序列全部释放。会话同时保存`hasOwnership`：**仅合法第二指到来并成功接管后才置true**。未接管的观察／排空不消费、不取消子控件；已接管的冻结／排空持续消费。正常释放可在组装期提前结束，不强制等足150ms。

1. **Idle／ObserveSingle：** 只从新的单指DOWN开始观察。首指触摸不延迟、不消费，保留现有单指点击／滑动。通过Initial观察位移，Final检查**位置变化是否已被子控件消费**及明确的拖动／长按所有权；按钮正常DOWN消费和按压候选不等于单指拖动占有，不因此阻止早期多指升级。单指已取得拖动／长按或已越slop，则本序列不再升级。输入中途启用不把已经按住的触点当新手势。
2. **Assemble：** 在首指150ms窗口内合法第二指到来且资格仍有效，父层取得整次多指所有权，立即取消按钮／滑条／歌词／Pager候选，持续消费本序列。允许第三／第四指按窗口和24dp规则加入；加入时为所有现有ID同一时刻重建起点，丢弃之前不完整群组位移。MOVE指标可以记录，但组装中不提交任何类别。
3. **Track：** 用输入uptime判断窗口；后续帧时间超过首指+150ms时，在处理新增指之前锁定原组2／3／4个ID。无需后台轮询或每帧定时任务。锁定时保留最后加入指后已取得的完整MOVE轨迹，不再次清零。锁后任何新DOWN（即使复用原ID）、丢ID、五指或异常序列均取消；不升级或降档。每个合法完整MOVE更新最后完整快照、变换指标及逐指累计量；距离／方向／比例留到冻结时判定。
4. **首次组内UP：** 优先识别正常抬指状态变化，结束组装并固定最终指数组合。**整个释放帧的坐标不参与分类、边界检查或变换计算**；结果只根据最后一组完整有效MOVE冻结。这样不会把同一UP帧内余指的异常坐标再算入结果。组装期提前UP也执行这条规则；没有完整MOVE或不满足门槛则冻结为“无结果”。
5. **Frozen／Drain：** 已接管会话继续消费至所有触点离开；未接管的Drain只观察至全抬，不消费或取消原单指控件。余指移动与抬起不改变结果，不启动另一组手势。新指加入、CANCEL、资格／几何／生命周期变化立即丢弃冻结结果；新指即使复用已释放ID也视为取消。此阶段不采坐标作为新位移。
6. **最后正常UP：** 只有存在冻结有效结果、整段无取消且最新门禁／代际仍有效，才形成一个不可变结果；**先清空核心会话，再向路由交一次结果**。路由再次检查最新资格，拒绝不重试。识别、接管及首次UP均不提前执行业务；最终提交次数最多1。
7. **取消清理：** `finally`必须覆盖每次`awaitEachGesture`的block以及适配器退出；不能只在最外层协程结束才清理，因为会话取消可能被框架捕获并开始下一次等待。取消／异常清除未提交结果，不能把CancellationException当正常UP。仍有有效输入通道时Drain至全抬；宿主销毁后旧会话失效，恢复只接受全新DOWN。取消或未识别的已接管序列不补成点击、歌词滚动或余指fling。

同一帧有新增与退出触点属于成员替换，取消，不进入正常首次UP冻结。释放帧虽不采坐标，身份／按下变化／取消类型／资格仍必须验证。Frame处理优先级固定为：外部取消与成员替换 → 正常首次UP／释放处理 → 窗口到期锁组 → 合法新增指 → 完整MOVE。

## 5. 子控件仲裁与唯一业务出口

- 根祖先Initial pass采样并接管，Final pass只核对本次单指所有权／取消；只在尚未由单指占有的早期序列升级。消费不是停止投递，现有自定义子手势必须观察接管资格并退出。
- [QuickControls](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/QuickControls.kt>)／[DockQuickControls](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/DockQuickControls.kt>)取消草稿、浮层及待提交资格；不得由余指UP提交档位。
- [WallpaperLyrics](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/WallpaperLyrics.kt>)及Panel内Pager不继续多指拖动或产生fling；普通单指已开始的序列不再升级为多指命令，按原有单指控件合同处理。
- [BoundaryPressFeedback](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/BoundaryPressFeedback.kt>)取消按压资格和反馈；[PageTapObserver](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/PageTapObserver.kt>)保持多指不算空白tap；跨子控件落指由同一个根核心识别。
- 业务沿现有Panel／Binding／Store或MapPresentationPort出口。为手势标明输入来源，按拖动语义不播放CLICK；按钮与无障碍点击的既有音效合同保留。没有独立车辆协议或Divider写入路径。
- 十二项映射已由用户在2026-10-15确认：默认二指右滑进入沉浸式全屏、二指左滑退出，其余无；各项可在手势设置独立选择三种动作。仅支持全屏的页面允许执行，当前为歌词页；偏好与默认值唯一owner见[设置项清单](<../product/设置项清单.md>)。未绑定项不执行业务，不安排车辆动作或增加正式调试控件。

## 6. 固定施工顺序与验收

1. 建立Policy、纯核心和输入帧；从第一天就按150ms／48dp／24dp／30°等默认值编写边界用例。
2. 接Compose适配，直接调用官方函数；将此前8组真实辅助函数fixtures纳入可维护测试，并加入纯核心序列测试。
3. 接根Modifier及子控件取消，跑真实Panel输入与普通单指回归。先证明识别／仲裁，再连已明确业务映射。
4. 按[验证矩阵](<../testing/验证矩阵.md>)完成相关编译、定向回归、正式同身份签名与同包车机最小触摸验收。修复前一阶段暴露的问题后再向下一阶段推进，不以辅助函数通过替代整套验收。

| 固定核验范围 | 通过条件 |
|---|---|
| 12类平移；快慢；落指错开；第三／第四指接近窗口边界 | 输出准确人数与唯一方向；组装中不先触发双指；无UP坐标依赖 |
| 150ms、各距离、角度、2倍比例、缩放及旋转边界内外 | 与本文比较规则一致；参数只有一个owner |
| 顺序／同时释放、变化列表重排、ID复用、早UP、释放帧所有点跳变 | 只认原组最后有效MOVE；最终最多一次提交；无降档、补点击或fling |
| 仅一指移动、对向、模糊对角线、沿途明显捏合／旋转再返回、五指、丢ID、非法坐标 | 不输出有效命令；未提交结果正确清理 |
| 冻结后CANCEL／新增指／模态／暂停／销毁／几何变化 | 无业务提交；恢复不接续旧会话 |
| 真实Panel按钮／空白／歌词／Pager／快捷／Dock与跨控件落指 | 无错误点击／音效／滚动／档位提交；普通单指行为保持 |

现场只标定统一参数与手感，记录实际事件、参数版本及预期结果，并保留为回归；不凭单条反馈改成另一套算法。只有用户明确改变手势产品合同，或出现无法在当前架构内修复的已证实技术问题，才另立变更决定。
