## 2. 卡顿的静态根因，不把症状当时间线问题

| 原路径 | 结构证据 | 本轮对应改动 |
|---|---|---|
| 歌词帧内离屏合成 | 旧 WallpaperLyrics 每帧建立 viewport 大小 `saveLayer`，再用 `DST_IN` 绘制上下边缘遮罩 | 用预建 bitmap／gradient／edge-alpha Shader 合成纹理；screen painter 只裁剪／变换／画预建墨迹，无 viewport `saveLayer` |
| 活动词重复选区与整段绘制 | 旧 `drawTimedText()` 帧内 `indexOf`、词跨行分段、列表／`Path`、`getSelectionPath`、`clipPath`，每个已唱片段再 `StaticLayout.draw()` | 字符簇、词映射、wrap、Bidi direction runs 与选区交集在 prepare 阶段编译；热 painter 不创建 Path／layout／bitmap／blur |
| 换句／主题／窗口变化重复栅格 | 旧可见行 `remember` 键包含 singing、focus、dark、visibleRows，每次重建 layout 和整行 bitmap；行高可跟长段落一起增长 | 全曲最大字号固定 geometry；按 visual line 切片、byte LRU；颜色／opacity 不参与纹理 key，当前与随后两行预热 |
| 快照重建整曲 UI 对象 | 旧 Mapper 每次 `map()` 都重新映射所有 line、主词和背景词；约100ms业务刷新也承担整曲对象成本 | 按不可变原 `lineList` **引用 identity** 缓存 UI rows／words；位置、游标、终态仍独立投影，新正文 identity 必须失效 |
| 背景 screen 合成层级 | 旧背景在屏幕上每帧绘制宏观底＋三层 LIGHTEN＋veil，整体淡化另用 `saveLayerAlpha` | worker 最长边192px预合成；motion最多10Hz发布；screen 稳态1张 bitmap、500ms转场最多2张 bitmap |
| 高刷新状态外溢 | 原词进度与滚动偏移在 composition 中直接读取，高刷新值可反复触发 composition／缓存重评 | 帧时钟主要在 draw／semantics 消费；结构窗口只在进入／离开边界时变更，停帧条件另作回归 |

这些事实解释了“已经预模糊、纹理很小”仍不能直接推导 screen 开销低：小源纹理会被铺满实际 viewport，多层混合、离屏层、重复 shaping／selection 与 UI 对象重建属于不同成本。根因包含 CPU／分配与屏幕合成，不只靠降低字体、降媒体采样频率或延迟跟随解决。

## 5. prepare 与 frame 的职责

1. **整曲 geometry：** `prepareLyricRow()` 使用full-context原生StaticLayout，一次编译完整主文／副文、换行、grapheme与源词映射。默认liga恢复，主任务已实读Manrope GSUB确认 `ffl/ff/fi/fl/tt/(c)/(>)/->/--/<-/ <3 ` 等替换，renderer按这些真实连字合并运动unit；另将`ffi`保守合并为motion单元以保护shaping，**GSUB未证实`ffi`，不能把此保守分组写成字体已存在的连字替换**；跨真实word边界的连字允许各源词fade，但片段不独立移动，避免撕裂字形。每个visualLine另编译自身paragraph direction／alignment的`pivotX`，prepared和cold缩放共用，RTL leading锚右边、trailing锚左边，LTR反向、center锚宽度中点，不以宿主LTR假定代替原段落对齐。
2. **Unicode／复杂文字：** ICU character BreakIterator不按UTF-16 code unit拆分；组合附加符、ZWJ emoji、肤色、旗帜、keycap、补充汉字等保持安全单元。Arabic／Indic／Thai等不安全joining脚本保留完整shaping，不独立拆动。Bidi按full paragraph建立后用`createLineBidi()`获取direction runs，源词与run／visualLine相交；歧义caret边界依赖prepare时的真实selection geometry，**空白selection cell也可能持有shaped ink，不能按`isBlank`删掉它**。彩色glyph按实际sharp raster RGBA判定，不用`cp>=0x1f000`，不能把“𠮷”误判emoji；彩色墨迹不做单色tint。字素／连字边界还须通过下节raster隔离检查才能独立rise，frame不新建Path或扫描像素。
3. **有界 worker raster：** 按visualLine预制sharp／soft纹理与安全上浮元数据，bitmap、rasterize及`extractAlpha/BlurMaskFilter`位于Default preparation分支；per-cache Mutex保证取消后的新旧任务不并行改同一cache，片间cancel checkpoint允许过期任务停止。worker使用独立TextPaint／layout副本，不与临时vector draw共改paint。sharp一次RGBA读取共同派生`colouredGlyphs`／`hasInk`／`clearMotionBoundary`；soft mask不重复扫描源像素。
4. **发布与冷路径：** 已可用slices在新窗口准备期间继续使用；cancel checkpoint和发布前ensureActive阻止旧结果回写。`visible=STARTED && focus && LocalIconVisible`进入prepare的LaunchedEffect key，false取消旧异步任务且不新准备，不清已准入正文；重新可见时有界预热。冷启动／大seek行片未到时，以同一已测量StaticLayout临时vector绘制防空屏，不在UI线程同步raster或blur。**此冷路径仍有原生layout.draw成本，且暂时无非当前模糊／精确feather-rise；不能称冷路径零绘制成本或冷帧与预热帧效果完全相同。**
5. **热 frame：** LyricInkPainter只采样真实位置／固定rise进度与prepare metadata，修改现有位移和alpha，画预建Shader墨迹；无bitmap/layout/Path/blur创建、无viewport saveLayer、无getPixels。BitmapShader与渐变／edge-alpha预先建立；Android API28 `Shader.setLocalMatrix()`会使native shader失效，**不能表述为“GPU uniform更新、零native分配”**。200次draw不新增raster的结构测试只证明栅格缓存命中，不证明native零分配或车机FPS。
6. **current与singing分离：** `lyricEmphasizedRows()`采用合法scroll current与真实singing的并集；未知位置／真实gap／duration端点阻止额外current。行首早于first-word时48sp强调立即生效，但源词揭示与rise必须仍等待真实word start。重叠声部仍保持各自真实轴。
7. **唯一派生停帧门禁：** `moving`的Snapshot derived boolean依据可见性、可信定时位置、正speed、有效word/gap与投影position<duration变化；只有`LaunchedEffect(moving)`取消／重启frame job，loop不再另设duration手动break。同一帧seekback可在composition看到false前恢复true，此时旧job应继续而非被手动break永久退出。投影到duration后停止、同曲seekback／新曲重启必须专测，不能只发业务端点快照或fake pause；最终检查状态见[验证记录](<../testing/歌词渲染与背景性能重构验证记录-20261003.md>)。

### 5.1 字形完整性收敛：空白cell、kerning连通边界与RTL

以下保留已实读的**静态根因／合同**；对应Arch API28／34各11变体随第五轮fresh通过，精确运行数量见验证记录，不把它们加到UI142之外。数字／符号的native shaping不是grapheme边界即可安全切开；本轮仍保持原正文、源word、参数和附轨，不改预期像素／容差来迁就实现。

### 5.2 SIMPLE常量与API28边界

SDK35的StaticLayout.Builder `setBreakStrategy` IntDef要求LineBreaker的SIMPLE符号；虽与旧Layout alias同为0，Lint仍拒绝旧符号。当前[geometry builder](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/LyricInkRenderer.kt#L164-L176>)与[worker builder](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/LyricInkRenderer.kt#L375-L380>)均引用Java compile-time `LineBreaker.BREAK_STRATEGY_SIMPLE` final int 0，常量编译时内联；未创建LineBreaker对象或调用API29方法／构造器，不以blanket Suppress或关闭Lint绕过。原SIMPLE策略、shaping及API28目标不变；源码符号修正本身不是通过证据；第五轮四Lint及正式同包闭包实际exit0见验证记录。

## 6. 固定上浮与源时间轴

源词 `[start,end]` 原区间只用于按visual width映射每个可移动视觉unit的 `startFraction` 起点；`lyricCharacterRiseProgress()`从该起点开始固定约1000ms，使用 `1-(1-t)^3` 的ease-out cubic，起点相对稳定基线下移2.5dp，先快后慢回到基线。源词短长不改变动画速度，窗口可以越过源词结束；如果滚动先发生，既有滚动和裁剪自然结束该字符的可见动画，不等待源词或滚动额外延长。函数不生成字符时间戳，不改变parser／cache／Store timeline。

横向揭示前沿仍在源词真实区间内从字形边界外开始、到边界外结束；它与固定上浮位移分离。fill按真实词内进度推进，不重排全曲geometry、不创建一套character Animator。暂停纯采样冻结，向后seek能在同一位置复现同一数学值；动画窗口结束后字符保持稳定基线，不回落重播、不留下逐字辉光。

## 7. 背景低分辨率预合成

[AmbientSceneBaker](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/MediaAmbientBackground.kt#L297-L343>)保留原128源field、三层LIGHTEN、veil及确定种子多周期motion，但将scene铺合移到Default worker，最长边192px，每100ms最多一次motion样本发布；10Hz是**宏观背景取样上限**，不是歌词跟随频率或500ms转场进度频率。screen [AmbientPainter](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/MediaAmbientBackground.kt#L346-L379>)稳态一bitmap、过渡两bitmap，不使用screen LIGHTEN／saveLayer。

**首次准备的Snapshot门禁：** 原`hasPreparedTarget` getter用plain `targetRequest == request && transition.target != null`判断；cold第一项false会短路，不读取任何Snapshot字段，外层derived可缓存false而不因首target发布重算。这是本轮实际状态依赖缺失，不靠增加UI等待时间或放宽测试掩盖。[AmbientRenderState](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/MediaAmbientBackground.kt#L194-L251>)改成显式Snapshot boolean，只由beginRequest设false、retarget按frame!=null发布、clear复位；updateTarget只在已准入target中更新纹理／phase，不重启淡化。[冷门禁精准测试](<../../ui-preview/content-ui/src/test/java/com/icar03/content/ui/AmbientTransitionTest.kt#L112-L130>)从empty false到首target true、新request false、新target true及clear false直接验证derived可观测性；对应本机专项已随第五轮通过，报告见本轮验证记录，仍非车机性能结果。

颜色混合与整体opacity分离：incoming=`opacity×fraction`，outgoing补偿后续source-over遮挡，使主题贡献仍为`1-opacity`，不把单独两张降alpha当等价group fade。快速中断仅在混合状态捕获一次同宽高比低分辨率快照，端点复用不可变纹理，不在每屏幕帧capture。已发布bitmap不主动recycle；只释放引用，未发布过期产物可回收。

本机`autoAdvance=false`夹具须先交付viewport layout事件，再观察prepare：wall-clock waitUntil不会替代frame clock交付。[AmbientPanelRenderTest](<../../ui-preview/content-runtime/src/test/java/com/icar03/content/runtime/AmbientPanelRenderTest.kt#L69-L104>)用test-only local Unconfined与`advanceTimeByFrame()`确定准备顺序，仍断言真实Canvas ready／全内容层颜色，原500ms曲线未放宽；这不是将生产Default worker改为UI线程，也不能单独证明生产线程／性能。

viewport resize只调整最新geometry，不重新开始500ms淡化；暂停／失焦冻结phase，冻结期间resize用published phase生成新aspect。宿主stop取消任务、拒收旧generation并释放准备／展示引用，恢复不补跑后台时间。背景稳定源算法／调色历史owner仍见[封面背景研究](Lyrimuse封面背景算法与Android适配.md)，其旧screen层级描述只适用于当时版本，本轮物理链由本记录覆盖。

## 8. 终态不猜测、正文不降级

[ContentPorts.LyricsSnapshot](../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentPorts.java#L382-L413)保留旧`EMPTY/LOADING/READY/UNAVAILABLE=0..3`，只新增`NO_MATCH=4`、`NETWORK_ERROR=5`、`INSTRUMENTAL=6`。Resolver／Engine／Mapper／LyricsPage共同保留原因，不往lyrics line或word轴塞占位文字。

- 纯音乐proof仅来自NetEase JSON真boolean `pureMusic=true`、LRCLIB真boolean `instrumental=true`，或**唯一明确纯音乐歌词标记**（可去合法metadata与时间tag）；空正文、曲名“纯音乐”、长gap、普通“Instrumental”文本、数字／字符串true均不猜。已存在另一真实主／副／词轨时不能仅因删掉那轨剩下marker而重新归类。
- 嵌入sole marker是明确终态事实，不是普通单行歌词。共享metadata的普通embedded正文≥2时间戳门槛会过滤`[99:00.00]纯音乐，请欣赏`；[Engine.embeddedResolved](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/lyrics/ContentLyricsEngine.kt#L456-L475>)仅当state.metadata.embeddedLyrics为空时，才从**当前raw embedded**窄恢复唯一明确marker，再走既有selector严格录音proof。普通单行正文仍不过共享门禁，不造时间戳／行／第二state-machine；[known／Unknown proof专项](<../../ui-preview/content-runtime/src/test/java/com/icar03/content/runtime/lyrics/ContentLyricsEngineTest.kt#L593-L608>)要求known录音无网络／无假轴／无cache写，Unknown与缺时长拒收。
- `LyricsResolutionSession.finish()`先选已准入真实正文，只有无正文时考虑同录音严格proof的纯乐；Engine重放当前录音／duration／lifecycle证据，迟到纯乐不得覆盖新歌或已有READY正文。纯乐无伪行／伪词轴，不进入body-quality持久cache；同录音内存中的已proof事实可跨短暂stop／resume保持，不声称重启有纯乐磁盘缓存。
- 完成无匹配与typed请求失败区分；已有缓存／provisional正文刷新失败保持READY，refresh budget不增加，失败不清有效歌词。
- 正式歌曲loading无正文继续blank，只保留背景，不新增加载／来源提示；no-song门禁压制旧网络／纯乐状态。无正文终态分别精确显示“暂无歌词”“网络错误”“纯音乐，请您欣赏”，每条文案文本自身中心精确对齐歌词viewport的水平／垂直几何中心；可选来源按钮只在文本下方12dp，有无来源按钮不能上移或改变文本中心。不能用group整体居中替代此契约。纯乐不显示歌词区来源按钮，底部媒体区既有来源按钮仍可使用；真实body优先于empty reason。
