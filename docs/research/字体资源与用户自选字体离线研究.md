# 字体资源与用户自选字体离线研究

> 本轮只做本机资源核查、字体文件元数据／字形对照和方案建议。车机离线，未发现／连接／安装设备，未修改正式业务源码；下文的设置项和新组件均为建议，尚未实现。
>
> 后续已完成[2026-10-06车机系统字体实查](<车机系统字体实查-20261006.md>)：默认sans-serif确实指向MiSans，系统还包含Noto简体黑体／宋体及其它字库。本文“未确认系统字体”保留为离线轮次的证据边界，当前设备结论以实查记录为准。

## 1. 结论与证据边界

1. 当前地图内容区已具备直接加载包内字体的条件。歌词正文固定使用 Manrope 的真实 `wght=800` 与 Noto Sans SC ExtraBold；普通 Compose 界面沿 Material 默认 Typography 和系统字体回退，没有用户字体 ID。
2. 正式高德源码里还有 Oswald、SDK_Font中英文字库、Alibaba Sans数字子集和图标字库。资源文件名不等于真实字族：名为 Roboto Regular／Bold 的文件内部名称均为 Alibaba Sans 102 Bold，英文样本缺字，不能按完整 Roboto 文本字体提供给用户。名为 AmapNumber 的文件内部名称为 SDK_Font Bold，实际包含约2.78万汉字及拉丁字母、数字，可作为高德原带中文字体候选。
3. 本地已保存的车机 DJI 应用资源中存在 MiSans、梦源黑体和 Montserrat；Launcher 中存在数字字体和 Impact。这些是原厂应用的私有字体资源，不能当作系统已注册字族，也不证明当前车机版本仍安装同一资源。
4. 本轮未找到目标车机的系统字体目录清单或系统字体配置快照，无法确认实际系统字族及 fallback 顺序。系统字体核查不影响先设计本应用内的字体选择。
5. 高德地图标签、原生 HMI 和本项目内容区文字由不同 owner 渲染。内容区的 Compose Typography 不会自动改变地图路名或原生导航文字；字体选择应明确作用范围。

适用正式输入为高德 `9.5.0.600013`、125% 全屏基线，SHA-256=`dfb763c9b9ab42d6096e6c988578937bfbaaa73436db22f99efe37503d54f3f5`，原始快照为 `ac6033c`。新增内容区字体属于后续正式施工资源，不能说成高德原带字体。

## 4. 建议的用户体验（未施工）

第一版优先在现有歌词设置里新增“歌词字体”，与已有字号和行间距相邻；如果用户希望内容区整体也可变，再单独增加“界面字体”，歌词默认保持当前已使用的组合。

- 第一版可直接提供三项：当前推荐（Manrope＋Noto Sans SC）、高德原带（SDK_Font）、系统默认。SDK_Font已经在输入APK内，不需要为这个候选增加一套中文字库；MiSans可作为下一套正式内置的比较候选，梦源黑体可作为扩展候选。
- 每个选项直接用候选字形显示同一段中文、英文、数字预览。字体名称和操作按钮保持稳定、可读的界面字形；数字子集／仅西文字体不得伪装成完整中文选择。
- 选择后应用并自动保存，提供恢复默认。内部处理中文、拉丁和Emoji的回退组合，普通用户只选择一套“字体”，不用配置各脚本。
- “导入字体”作为可选扩展，通过 Android Storage Access Framework 选择本地／U盘的TTF或OTF，复制到应用私有目录后验证并登记。失败保持上一个有效选择，不依赖原文件长期存在，不要求用户手改系统文件。
- 第一版无需字体商城、后台下载或每次启动扫描系统全部字体。只有运行时确实确认存在的系统字族才加入列表；`Typeface.create()`没有报错不能证明该字体存在，Android可能静默回退。

这套选择器可以离线使用。系统字体目录的完整盘点、驾驶视距可读性与真实车机切换效果仍需目标设备在线后核验。

## 5. 建议的唯一实现链（未施工）

`SettingsSheet → ContentEvent → ContentBinding → ContentStore／ContentPreferenceStore → ContentUiMapper → 字体解析 → Compose／歌词Canvas`

| 职责 | 已存在入口／建议落点 | 必要处理 |
|---|---|---|
| 用户偏好 | [SettingsSheet.LyricsSettings](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/SettingsSheet.kt#L314>)、[ContentModels](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentModels.kt#L120>) | 稳定字体ID和选择事件；新事件进入 `isSettingsInteraction()`，不借数组下标或显示名称持久化 |
| 唯一状态与保存 | [Binding.dispatch](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/ContentBinding.kt#L297>)、[Store.setLyricsFontScale](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentStore.java#L269>)、[PreferenceStore.load/save](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentPreferenceStore.java#L39>) | 字体ID沿现有Store保存与迁移，State.copy同步；未知／缺失只回退该项 |
| 分域投影 | [Mapper.sameShellFacts](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/ContentUiMapper.kt#L222>)与 `mapShell()` | 新偏好同时进入比较和映射，避免持久化后界面没有收到变化 |
| 字体解析 | 建议新增一个共享 `ContentTypography`／字体目录组件 | 将稳定ID解析成 `FontFamily` 与原生 `Typeface`；统一脚本回退、真实字重和导入文件身份；按ID／内容哈希／字重缓存，不在draw或每帧读文件 |
| 普通内容区界面 | [ContentTheme](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentTheme.kt#L113>)的 `MaterialTheme` | 统一注入Typography；顶栏与功能标签的真实字体测量使用同一style，不能只替换绘制字体而保留旧宽度 |
| 歌词排版与纹理 | [WallpaperLyrics](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/WallpaperLyrics.kt#L97>) → [LyricLayoutRequest](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/LyricLayoutDocument.kt#L10>) → `prepareLyricDocument()` → `LyricInkCache` | `remember(assets)`须加入字体身份；现有request已含face／cjk，可沿后台文档主链重排并原子发布。旧有效文档保持至新文档就绪，同录音沿旧可见锚迁移，不清播放进度或重新切歌 |
| 逐字运动安全 | [LyricInkRenderer.lyricMotionBoundaries](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/LyricInkRenderer.kt#L100>)与 `compileLyricInk()` | 现有连字名单专用于Manrope，导入其它字体时必须改为随字体验证的规则，或保守保留完整shaping／只做安全揭示。不得只改字体加载路径就宣称支持任意字体 |

车机为已知SDK28，方案不能依赖API29才有的 `Typeface.CustomFallbackBuilder` 或系统字体枚举接口；沿当前原生Typeface、跨度与平台fallback能力施工，并验证混排和缺字。

## 6. 本轮实际验证

- 使用glob盘点本机正式源码与已保存应用字体；使用read回读当前字体、设置、持久化、分域投影、后台文档和逐字渲染主链。
- Pillow／FreeType直接加载真实字体文件，Manrope设置真实变量轴800；[包内字体对照图](<../../apk-work/fonts-offline-research/font-resource-comparison.png>)与[中文字体对照图](<../../apk-work/fonts-offline-research/chinese-font-comparison.png>)已实际查看，后者中文／数字样本无缺字。
- 两图都是本机字形参考，没有模拟Android系统fallback，不代表同包车机截图、全部Unicode覆盖或运行性能。
- 本轮仅研究与文档，无业务源码改动；未生成地图APK，未执行Gradle、设备发现、安装或实体动作。后续功能实现应验证偏好重启恢复、坏字体回退、后台快速切换取消、旧文档保持、同歌锚点、混排／连字／Emoji、API28／34与多密度文字布局，再做同包车机视觉验证。
