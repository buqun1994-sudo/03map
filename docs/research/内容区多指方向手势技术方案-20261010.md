## 临时 APK 的抬指跳位

读取了实际[探针源码](<../../.tmp/touch-probe.n3afmMUN/TouchActivity.java>)和[末次日志](<../../.tmp/touch-probe.n3afmMUN/manual-test-log.txt>)。

| 静态事实 | 判断与边界 |
|---|---|
| `onTouchEvent()` 第 47–52 行每事件用当前 index 获取 pointer ID，再以 ID 查独立 Stroke；历史及当前坐标使用同一个当前 index | 正常事件流下没有固定 index 充当手指身份的常见错误；不能直接宣称这就是本次根因 |
| 第 63–65 行用 actionIndex 取得离开的 ID | 没有默认删除第 0 指；UP 事件仍包含离开指，先统计事件触点数再减去离开指的计数正确 |
| 第 47–53 行在区分 MOVE／UP／CANCEL 前都追加坐标，第 39 行活动路径直接 `lineTo()` | 如果终止事件或历史样本中某 ID 坐标突变，会直接画长线；现有证据不能证明该突变发生，也不能定位到驱动或硬件 |
| Stroke 抬起后仍保留；同一触摸序列内新按下可能复用 ID | `active=false` 时 `moveTo()` 避免旧末点连到新点，但沿用颜色、标签且唯一标签移动，可能产生身份换位观感。仅适用于抬起后重新落下一指，不解释没有新 DOWN 的纯抬指长线 |
| 第 91–95 行逐 Stroke 绘制，没有中心点计算 | 人数变化导致平均中心点跳变是正式识别器要预防的问题，不是这个探针已经证实的根因 |
| 日志只保留最后一次单指 DOWN／MOVE／CANCEL | 没有异常发生时的多指 UP，无法复原根因；MOVE 日志约 40ms 节流且未记录历史样本，不能替代全事件取证 |

Android 9 的 [MotionEvent 契约](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-9.0.0_r1/core/java/android/view/MotionEvent.java#L53-L75)明确：index 可在事件之间变化，ID 在该触点按下至抬起／取消期间保持稳定。ID 不是物理手指永久编号，生命周期结束后的新触点要分代处理。

下一次短时取证建议增强独立探针：保留每事件的 seq、downTime、eventTime、actionMasked、actionIndex、actionId、device/source、每个 index→ID→坐标及历史时间／坐标；路径身份用 `(ID, generation)`，已结束轨迹及标签保持独立。原始 UP／CANCEL 坐标照常记录，终止异常点以独立标记显示，避免诊断图自己画出误导性连接。

复现顺序：两指分开落下→平移→停止→只抬一指，交换抬指顺序；另测保留一指并重新落下一指，以区分合法 ID 复用；三／四指依次释放。若 App 同一活跃 ID 的原始坐标连续而画面跳，查绘制；若原始坐标已跳，再按设备名重新定位 `mb_mfd_ivi` 并同步采集 getevent，在 SYN_REPORT 帧边界重建 slot／tracking ID。Linux tracking ID 与 Android pointer ID 不按数值直接等同。

本轮未重新安装探针或采样。方向识别可以采用保守末态策略降低误触发，但不能把该策略称为探针根因修复；正常 UP 本身可以提供合法最终坐标。

## 高德自身多点链对照（2026-10-10补充）

用户指出地图已有至少双指手势，要求判断参考价值。本轮对照当前正式 Smali，**高德自身应优先作为同宿主参考，尤其是事件传递和现场末态行为；目前没有找到可直接提取的两／三／四指四方向识别源码。** 下列为静态确认，不新增地图手势实机验收。

主屏链为：`kc.v()`／`w()`给`kc.k` SurfaceView绑定`kc$j` → `kc$j.onTouch(View, MotionEvent)` → `h7.p(MotionEvent)` → `as.c(MotionEvent)`／`AutoEventProcessor.c(MotionEvent)` → Handler消息`0x10` → `AutoEventProcessor.g0(Message)` → `EventProcessorImpl.onTouchEventNative(J, int[], float[], float[], int, long, int)`。`MapApplication.n()`通过`tk.f()`将实际`AutoEventProcessor`登记到`h7.r(as)`，不是仅凭接口名推测。

[AutoEventProcessor](<../../source/amap-9.5.0.600013/smali/com/autonavi/eaglet/uisurface/AutoEventProcessor.smali>)第1995–2154行将每事件的全部pointer ID／X／Y复制到对应数组，保留完整`getAction()`，另外传递`getActionIndex()`；时间使用处理时的`SystemClock.elapsedRealtimeNanos()`，不是原始`MotionEvent.eventTime`。此方法没有两点截断，没有读取历史坐标，也没有Java／Smali层的中心点平滑或抬指末点过滤。第3540–3772行解包后转入[native入口](<../../source/amap-9.5.0.600013/smali/com/autonavi/eaglet/uisurface/EventProcessorImpl.smali>)，包括CANCEL专门日志及可以绕过普通Surface准入条件进入native的分支。具体引擎内部的缩放／旋转／倾斜、抬指交接或异常过滤算法未定位，本轮没有反汇编native库。

值得注意的是，`kc$j.onTouch()`起始还调用`kc.A(MotionEvent)`。后者调用[渠道管理器](<../../source/amap-9.5.0.600013/smali/se.smali>)的`multiFingerEnable(MotionEvent)`：返回1／2时构建`y10(3)`并映射operaType为1／0，进入协议派发。`y10`封装`RspFingersSlidingOperationNotifyModel`，协议KEY_TYPE为`0x2789`（10121）。这是一条三指操作通知钩子，**不是已经可用的通用识别器**：[默认渠道实现](<../../source/amap-9.5.0.600013/smali/di.smali>)第2680–2687行始终返回`-1`；实际运行渠道如动态替换需要另查，不能因方法名或通知模型就宣称本车已启用。`kc$j`调用`kc.A()`后未使用其返回值提前退出，仍将原始事件送入主屏引擎。

### Native可恢复性实查（2026-10-10再次补充）

用户进一步追问能否获取完整算法。本轮实际使用NDK27的`llvm-nm --dynamic --demangle`检查11个当前本地库，全部返回0；`llvm-objdump`成功读取`libGFrame.so`内两个函数的机器码。此前“未反汇编native”仅描述上一次补充阶段，不代表native不能分析。

静态确认：`libGFrame.so`保留`GNS_FRAME::CGUIPanGestureRecognizer`的`onViewEvent()`（0x57c784）、`cacheMultiEventPointWithout()`（0x57e014）、`notifyDragChange()`、`notifyDragEnd()`、`calMoveAntiShakeState()`和`getMoveAntiShakeDistance()`等定义符号；`CGUIGestureRecognizer`还有状态变更、速度及失败链函数。`libhsl.so`保留`MapViewBaseImpl::SetAxisOfTwoFingersPress()`／`SetAxisOfTwoFingersScaleRotate()`及`OnMotionEvent()`，`libGbl.so`保留`DisplayImpl::GetOperatorGesture()`／`AddGestureObserver()`。这些证明存在可追踪的native实现与地图操作接口，不证明其已可单独用于Compose或已恢复完整地图识别器。

实际反汇编的`cacheMultiEventPointWithout()`可见按传入位置参数分两段复制坐标及对应的整数数组，跳过该位置，并将坐标由浮点转整数；可见计数上限10的比较分支。`onViewEvent()`可见调用这个函数及多点`notifyDragChange(float*, int)`，因此不是只有函数名字而没有机器码。参数对应的事件枚举、完整对象布局与所有状态转移尚未恢复，不能据此把某一分支宣称为地图最终UP策略，也不能把内部上限10当作十指实机结论。

**当前结论：原始C++源码不可从APK保证还原；本需求相关算法具备继续逆向恢复条件，不能再将“位于native”当作无法参考的理由。但全链算法、常量语义、地图使用路径与行为回放均未完成。** 真正算法参考需沿输入转换→UI／地图识别器→触点增减／取消／防抖分支，恢复可解释伪代码并用事件序列验证；若某段只能定位入口则只报告该段，不能用平台常识或黑盒手感冒称高德算法。现阶段不直接调用高德私有native对象，也不宣称能独立抽取其二进制模块。

[符号与反汇编证据](<../../.tmp/amap-native-gesture.y3hxgbkx/>)包含`libGFrame.so.gesture-symbols.txt`、`cacheMultiEventPointWithout.asm.txt`及`panOnViewEvent.asm.txt`；[库身份](<../../.tmp/amap-native-gesture.y3hxgbkx/library-hashes.txt>)绑定本次磁盘输入。完整识别器逆向未完成，本轮没有编写内容识别器、修改native库或运行设备实验。

### 已恢复的平均位移与触点缓存

`notifyDragChange(float*, int)`（0x57e224）在有回调且传入点数等于内部缓存点数时，先把当前坐标逐点向零取整，再计算：

```text
N = 当前完整点数 = 缓存点数
sumCurrentX = Σ trunc(currentX[i])
sumPreviousX = Σ cachedX[i]
dx = trunc((sumCurrentX - sumPreviousX) / N)
dy = trunc((sumCurrentY - sumPreviousY) / N)
if dx != 0 or dy != 0:
    通知连续拖动变化(dx, dy)
```

同时计算当前整数坐标的平均中心用于通知上下文。**此函数不按ID查差值，而是比较同人数的坐标总和；同一组触点换index顺序不会改变总和。** 对向等量移动可相互抵消，所以它不能直接验证每指同向，也不是精确2／3／4指四方向的离散分类器。零平均位移不通知，点数不一致为内部断言／中止路径，不能让内容适配把不同人数的新旧中心直接送入此函数。

`cacheMultiEventPointWithout(event, skipIndex)`（0x57e014）从事件同一数组位置读取坐标和对应整数身份，保留至多10项，跳过指定位置并把余项连续写回缓存；`skipIndex=-1`表示不剔除。这是同事件index选取而非把固定index当永久手指。坐标向零取整；内部容量不代表本车已验证十指能力。

`onViewEvent()`的多点释放分支（0x57d294–0x57d2cc）在已识别状态下**先用释放事件仍包含的完整点集通知拖动变化，再排除离开的index更新缓存，最后减去内部人数**，供后续余指MOVE继续使用。因而可参考“人数变化时重建缓存，下一次计算使用同一批剩余点”，不能宣称高德这里用了“首次UP冻结、不读UP坐标”。本项目建议的首次UP冻结是自己的保守离散合同，不是复刻这段连续拖动处理。

### 已恢复的抖动门槛

`calMoveAntiShakeState()`（0x57d794）在防抖开启时逐点比较当前缓存位置与起始缓存位置；通过对象虚表+0x30获取门槛T，只要某点X或Y超出`[-T, +T]`，就设置开始处理的标志。防抖关闭时直接设置该标志。这是任一点／任一轴越界，不是所有手指一致越界，也不是圆形欧氏距离门槛。门槛的View／窗口消费者仍有上下游依赖，本轮不把某一个值当作内容区dp标定。

### 实际机器码核验及参考边界

## 早期候选识别契约（历史，施工以最终方案为准）

输入来自内容区同一父坐标系，按 PointerId 查当前变化，不能缓存 index。MotionEvent 适配每次用 `findPointerIndex(id)`，找不到即取消；Compose 按 `change.id` 查找，不以 `changes[0]` 代替原指。

1. **观察单指：** 第一指按下时观察并记录，不延迟现有单指点击。若单指已越过 slop、子控件已开始拖动或长按，后加手指不升级为多指命令。
2. **组装多指：** 第二指在短组装窗口内、第一指尚未开始单指动作时出现，父层取得多指候选所有权；继续允许第三／第四指依次落下。不能第二指刚落下就永久判为双指。每次合法加入都在同一时刻为整个候选组重设位置基准，前几指提前移动过多则拒绝。
3. **锁定群组：** 组装结束后固定 2、3 或 4 个 ID，只用该组的同向有效位移判断。不能使用整段峰值，也不能看到瞬间双指就提前触发。锁定后的新指／缺失 ID、超过四指或异常序列取消整次候选，不降档或升档。
4. **冻结末态：** 第一根组内手指抬起时保存不可变的指数组合及方向。本车抬指异常未定位期间，采用最后一组完整、有效 MOVE 作为分类终点，不依赖 UP 坐标；代价是舍弃最后一次 MOVE 到 UP 的合法尾部位移，快速短划需实测调节门槛。
5. **等待释放：** 余指移动／抬起均不重算方向，不产生另一组手势；持续消费，直到所有手指离开。同序列重新落下一指则取消已冻结结果，并继续等待全部释放。正常全部释放后通过当前资格检查，只派发一次结果。释放前出现 CANCEL／生命周期停止／窗口几何变化／模态遮挡则放弃未提交结果。
6. **重新待命：** 全部释放后才接受下一次完整手势；遇到异常新 DOWN 先取消旧候选。未识别／取消的已接管多指序列不回退成一次点击、歌词滚动或 Pager fling。

首次抬指冻结与全部正常抬起后提交分开，是为了保留 CANCEL 不执行业务的语义。第一版建议离散一次动作；未来若手势用于连续调节音量，应另定义预览／取消／提交合同，不能将十二类触发直接当作连续控制器。

方向以**固定群组逐指位移的平均值**计算：`D = Σ(position[id] - baseline[id]) / N`，同时核对每指主轴同向、最小有效移动与位移相近。不能只比较现存手指平均坐标与上一次平均坐标。例如两指 x=100／300 时中心为 200，左指抬起而右指不动后中心变为 300；这是假右移 100，单指完全没有移动。

仅平均值还不够：一指右移而其余不动不接受；捏合、明显旋转、对向移动及方向不清晰也拒绝。不能为了通过门槛将异常坐标强行夹到一个方向。

| 第一版候选参数 | 初始建议 | 证据边界 |
|---|---|---|
| 落指组装窗口 | 首指至最后一指约 150ms；可在约 120–180ms 内实测 | 允许落指时差，未标定；仅多指候选形成后暂缓分类，不延迟普通单指点击 |
| 群组主轴位移 | 约 48dp，同时核对每指至少约 24dp 的同向主轴移动 | 不用一个指带动平均值；使用内容区 LocalDensity，不使用地图125%密度 |
| 主轴方向优势 | 主轴绝对位移至少约为副轴的 1.5 倍 | 模糊对角线不猜方向；逐指一致性另查 |
| 速度 | 第一版不设必须快速甩动的下限 | 慢速有效平移也接受；靠距离与一致性排除点按／抖动 |

数值不承诺最优手感。组装结束与早期抬指的边界、逐指离散度和 MOVE 阶段异常跳变需在回放／实机样本中确定；不能为新增手指无限延长组装窗口。默认没有完整有效移动样本时不触发。

## 内容区接入与冲突

推荐接在 [ContentPanel](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentPanel.kt>) 根 `BoxWithConstraints`，它已经是空白点击观察器的共同祖先，覆盖 Pager、歌词、媒体、Dock 和控件；[Host](<../../source/amap-9.5.0.600013/content-compose/host/com/icar03/content/host/ContentComposeHost.kt>)负责生命周期与真实可见 viewport，不给地图 Surface 加透明全屏遮罩。

建议模块职责：纯核心保存身份、基准、状态和不可变结果；Compose Modifier 负责祖先 Initial pass 采样，取得多指候选后逐事件消费至释放；业务路由将 `(2|3|4, UP|DOWN|LEFT|RIGHT)` 映射到现有事件与 Store／Port。模块名称及实现尚未新增。

[Compose PointerEventPass 契约](https://github.com/androidx/androidx/blob/androidx-main/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/input/pointer/PointerEvent.kt#L1093-L1113)允许祖先在 Initial 先消费，Main 优先给子节点，Final 让子节点得知父层消费。**消费不是停止事件投递，自定义子手势仍要正确退出**，不能只加父 Modifier 就宣称冲突全解决。引用 AndroidX 主线仅核对机制，施工时还须核验本项目实际锁定依赖。

## 施工验证与开放项

先做独立识别核心和增强探针／回放，再在正式 Panel 仲裁与业务路由接线。先验证识别结果，具体功能未定义的手势输出诊断结果，不擅自分配车控操作。

核心回放覆盖十二类有效平移、ID／index 重排、落指／抬指顺序、UP 末点突跳、MOVE 阶段跳变、先抬后落 ID 复用、5指、捏合／旋转／对角线／单指带动、丢 ID、CANCEL、锁后新增指、释放阶段移动及单次提交。特别验证四指释放成 3→2→1 只产生原四指结果，末态 CANCEL 不提交。

实际 Compose 输入覆盖不同子控件落指、按钮／空白不点击、滑条／Dock 草稿取消、歌词不滚动、Pager 不翻页／fling、多指拒绝后余指无动作，以及普通单指点击／拖动保持。多指接管后的 Ripple／音效单独核对，不能用纯核心测试代替实际分发。
