## 3. AndroidX增减指算法已明确

每个事件仅选出“上一帧与当前帧都按下”的同一组触点S：

```text
S = changes where previousPressed && pressed
previousCenter = average(previousPosition of S)
currentCenter  = average(position of S)
pan = currentCenter - previousCenter
S为空时 pan = Zero
```

新指本帧尚无previousPressed，抬起指本帧已不pressed，均排除；**前后平均使用同一个S**。这是关键依据，不能改成“上一帧全部点中心”减“本帧剩余点中心”。

| 输入边界 | 官方算法结果 |
|---|---|
| 两指原在x=100／300均不动，左指抬起 | 前后都只算右指，pan=0，不产生假右移100 |
| 旧指不动、新指落在很远处 | 本帧只算旧指，新指加入本身不产生平移 |
| 抬起指的UP坐标异常跳变，余指位置正常 | 抬起指被排除，其终点不进入pan |
| 全部抬起，末点异常 | 交集为空，pan=0、zoom=1、rotation=0 |
| 只剩一指且继续移动 | 仍会产生该指的真实pan；不会自动维持原2／3／4指资格 |
| 剩余按下指本身收到异常坐标 | 仍可能产生位移；交集机制不能纠正驱动给仍按下ID的错误数据 |

`detectTransformGestures`使用`viewConfiguration.touchSlop`；累计pan长度、由半径换算的zoom／rotation移动中任一严格大于门槛即可启动。任一change已被消费则本次检测结束；启动后消费位置变化；`awaitEachGesture`等待全部抬起再接受新一轮。完整detector允许余指继续、允许旋转／缩放，不直接符合十二类离散命令，**建议复用公开计算函数与会话框架，不把完整detector回调直接连到业务**。

## 4. 开源方向与人数判定的真正含义

RNGH方向算法：先将向量归一化，计算它与目标方向单位向量的点积；点积严格大于`cos(锥总角/2)`才视为方向匹配。四个轴对应左／右／上／下；小向量先归零。Fling默认锥总角30°实际是轴两侧各15°，**不是各30°**。该数学判定可直接参考，但本项目角度窗口仍是需要明确的体验参数，不能把默认甩动角度当作车机已标定值。

Fling还要求：

```text
maxNumberOfPointersSimultaneously == numberOfPointersRequired
velocity方向匹配
velocity幅度 > 2000 px/s
800ms定时失败窗口内识别
满足即可activate，随后立即end
```

速度通过Android `VelocityTracker`的无ID`xVelocity/yVelocity`取得，不是对每根手指分别核验同向位移。人数变量是识别前观察到的同时触点峰值，不是锁定原始ID集合；`onHandle`先尝试识别，后更新峰值，因此首次达到所需人数的事件通常只更新峰值，后续事件才可能识别成功。上述“立即end”指识别条件满足后的同步状态变化，不是刚凑齐人数就必然触发。识别后再加入手指不会把已经结束的结果升级。因此不能原样解决“避免三／四指组装中途先触发双指”“慢滑也有效”“每指共同平移”“正常全抬再提交”。

[对角定义](<../../.tmp/mature-gestures.42b3_36o/rngh-v3.3.0-DiagonalDirections.kt>)明确将每个对角值定义为两个组成轴位的OR；掩码同时包含这两个轴位时，Fling对角检查才可能放行，单纯左右OR不因此形成对角。默认对角总锥为`90°-30°=60°`，即对角轴两侧各30°，与四轴的各15°不同。本项目若只允许四轴，应显式仅输出四轴类别并拒绝模糊对角线，不能简单把全部方向位OR起来当四分类器。

Pan有min/max人数与可选平均触点。它在人数变化时先累积旧translation再重设起点，维持连续位移；默认Android使用最近落指而非全指平均。这是连续拖动模型，同样不替本项目固定ID群组。

Mapbox的`MoveGestureDetector`默认required=1，`MultiFingerGesture`条件为`count >= required`。增减指时维护ID列表与基准，余指满足最小人数就续接；没有四轴输出。多指门槛只在人数>1时切换，触发为任一指X／Y超门槛。无参pressure取index0，不能称为每指合压。上述差异均来自[实际源码与API记录](<../../.tmp/multifinger-research.2oo7azbb/>)，不是只读README得出的比较。

## 5. 最少定制的施工方案与验证要求

基础层直接调用已有1.7.6依赖的`calculatePan`／`calculateZoom`／`calculateRotation`及pointer ID、事件消费、`awaitEachGesture`机制。内容规则层统一处理固定2／3／4个ID、组装期、逐指同向、方向锥、首次UP冻结最后完整有效MOVE、全部正常释放单次提交、取消／生命周期／几何变更；十二个功能映射放在现有业务出口，不进入基础数学。

根落点仍为[ContentPanel](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentPanel.kt#L144>)的`BoxWithConstraints`，不是全屏透明拦截层。父层需与Pager、歌词、按钮及滑条仲裁；不能直接把标准detector放到父节点便宣称争抢已解决。

[SplitPanelController](<../../source/amap-9.5.0.600013/smali/SplitPanelController.smali#L595-L599>)的listener实际挂在地图收放`gestureNode`，其第1522–1528行多指即cancel属于**另一触摸区域**；不能据此宣称整个内容区吞掉多指或为本需求必改手势条。内容区实际入口由[Host](<../../source/amap-9.5.0.600013/content-compose/host/com/icar03/content/host/ContentComposeHost.kt>)及Panel共同确定。

施工时先固定事件回放的预期输出，再接业务，避免依靠车上不断换算法：

| 核验范围 | 需要保持的结果 |
|---|---|
| 2／3／4指×4方向、快慢与合理落指时差 | 每个正常序列最多一个且只有正确类别；不因组装中间人数先触发另一类 |
| 坐标重排、ID复用、逐指抬起及抬指末点异常 | 无假方向、无降档续触发、无UP坐标改变冻结结果 |
| 捏合、旋转、对向、仅一指移动、模糊对角线 | 不伪装为共同平移命令 |
| CANCEL、丢事件、新指加入锁定组、暂停／销毁／几何变化 | 无业务提交，等待或正确取消下一次会话 |
| 真实Panel跨子控件落指、单指已拖动后加指 | 无控件／Pager／歌词副作用；普通单指体验及取消回滚符合既有合同 |

这张表是后续施工验证要求，**本轮尚未实现／通过完整识别器或同包车机测试**。组装窗口、距离和角度统一配置、一次标定后与回放结果绑定；不能为通过某一现场样本随意改底层计算或在多个控件分散补丁。用户反馈的抬指跳位仍缺完整原始事件；终止事件冻结能降低相关影响，不能据此宣称MOVE阶段异常或探针画线根因已排除。
