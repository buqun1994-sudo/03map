# 车机系统字体实查（2026-10-06）

## 1. 本轮结果

本轮通过项目车机发现入口重新核验 `S56_HQX / Android 9 / SDK 28`，只读获取当前系统字体配置、字体文件和相关APK字体资源。此前[离线研究](<字体资源与用户自选字体离线研究.md>)中的“未确认系统字族”是上一轮证据边界；本轮补上当前设备实际证据，不把历史DJI应用字体自动升级为系统字体。

**当前设备系统默认 `sans-serif` 常规字体为 MiSans Regular。** 系统同时有MiSans Semibold、Noto简体中文黑体／宋体、Roboto及多套西文和多语种字体。字体目录共236个条目（其中DroidSans／DroidSans-Bold是兼容软链接），ADB复制后累计87,947,552 bytes。它们不是236套适合用户选择的中文字族。

**发现一处配置与文件不一致：** 系统600字重引用 `MiSans-Demibold.ttf`，实际目录没有这个文件，存在的是 `MiSans-Semibold.ttf`。这只证明当前配置和磁盘不一致；没有运行Typeface探针或观察实际加粗字形，不据此断言系统加粗必定失败或使用哪种回退。本轮没有修复系统文件。

本机原始证据在[取证目录](<../../.tmp/vehicle-fonts-20261006-130445/>)；设备属性原始快照只保留本机，本文只记录型号／SDK，不复制设备私有标识或完整指纹。

来自车机 `/system/etc/fonts.xml` 的[本机配置副本](<../../.tmp/vehicle-fonts-20261006-130445/fonts.xml>)，配置SHA-256=`01fdb3cacf7db7f517b72a33b4a4ada5664a266a0614deee65df6dc7737c87a9`。与设备端再次执行 `sha256sum` 的结果相等。

|---|---|---|
| `sans-serif` | MiSans Regular400；MiSans Demibold600 | 默认字族，[配置24–28行](<../../.tmp/vehicle-fonts-20261006-130445/fonts.xml#L24>)；Regular存在且覆盖中文／西文，Demibold文件缺失 |
| `sans-serif-condensed` | Roboto Condensed 300／400／500／700与斜体 | [配置40行](<../../.tmp/vehicle-fonts-20261006-130445/fonts.xml#L40>)；字体自身不含汉字，中文走平台fallback，不能宣传整套中文变窄 |
| `serif` | Noto Serif 400／700与斜体 | [配置53行](<../../.tmp/vehicle-fonts-20261006-130445/fonts.xml#L53>)；西文衬线，简体中文通过Noto Serif CJK SC备用字面 |

配置另有Arial／Helvetica等名称指向 `sans-serif`，Times／Georgia等名称指向 `serif`；这些是别名，不是额外字体文件。`sans-serif-thin/light/medium/black`也只请求默认字族的权重，不证明有对应真实MiSans字重文件。

系统目录中的普通Roboto各字重确实存在，但当前配置未注册为默认字体，也没有名为 `Roboto` 或 `MiSans` 的独立family条目。不能仅凭文件存在就使用 `Typeface.create("Roboto", ...)` 或 `Typeface.create("MiSans", ...)` 宣称选中了它们；需要公开family映射或显式受控文件加载。

## 3. 中文字库与字节身份

全部系统文件均通过ADB读取到[本机系统字体目录](<../../.tmp/vehicle-fonts-20261006-130445/system-fonts/>)，没有修改设备。标准库SFNT／TTC解析得到[完整字体清单](<../../.tmp/vehicle-fonts-20261006-130445/font-inventory.json>)；字符数只计实际映射到非零glyph的Unicode码点，不能等同全部汉字覆盖或实际运行像素。

| 字体文件／字面 | bytes | 实际内部名字／OS/2字重 | 字符覆盖 | SHA-256 |
|---|---:|---|---|---|
| [MiSans Regular](<../../.tmp/vehicle-fonts-20261006-130445/system-fonts/MiSans-Regular.ttf>) | 8,073,152 | MiSans Regular／330 | 29,414码点，汉字27,781；中文／西文／数字；样本“𠮷”不在本字体cmap中 | `6aa32ded55e110a95be10080e0c322f2382681cd581c5cbb24f4fd4ce96fbb08` |
| [MiSans Semibold](<../../.tmp/vehicle-fonts-20261006-130445/system-fonts/MiSans-Semibold.ttf>) | 7,984,932 | MiSans Semibold／520 | 同上；是真实较粗字体，和DJI APK私有Demibold OTF不同 | `c7dc0cc24679c52af0a137d6a1edce7cf816af2a76ba9256d54b220cb0ea232c` |
| [Noto Sans CJK集合](<../../.tmp/vehicle-fonts-20261006-130445/system-fonts/NotoSansCJK-Regular.ttc>) index2 | 18,674,044（整个集合） | Noto Sans CJK SC Regular／400 | index2有44,615码点、汉字30,186；“𠮷”存在 | `aea63eb09eb66980e12511d9502bd9a3fc030ab8ae319afb9d43d2cc4bfbe494` |
| [Noto Serif CJK集合](<../../.tmp/vehicle-fonts-20261006-130445/system-fonts/NotoSerifCJK-Regular.ttc>) index2 | 24,757,472（整个集合） | Noto Serif CJK SC Regular／400 | index2有42,993码点、汉字28,541；“𠮷”存在 | `658fb3b16e40a404f46220575e7ae6c90c27bbc778813480beb48acd2cac1053` |

[配置514–529行](<../../.tmp/vehicle-fonts-20261006-130445/fonts.xml#L514>)明确：简体中文用TTC index2，繁体index3，日文index0，韩文index1；`serif`的对应中文回退用Noto Serif CJK。索引从0起算，必须显式选SC字面，不能把TTC默认index0的日文字形当作简体中文字体。

字体文件里的OS/2权重与系统配置的400／600权重不是同一层含义；MiSans按系统映射作为400加载，不根据OS/2的330强行改写系统权重。真实Semibold520可作为独立文件候选，但当前config没有引用它。

**缺失引用复核：** 对配置所有font文件名逐一检查，只发现 `MiSans-Demibold.ttf` 一项缺失；设备端 `ls -ln`再次明确返回“No such file or directory”。MiSans Regular／Semibold与配置的本机SHA均与同一轮设备端SHA相等，见[复核记录](<../../.tmp/vehicle-fonts-20261006-130445/misans-reference-verification.txt>)。

## 4. 字形对照与产品含义

[本轮中文对照图](<../../.tmp/vehicle-fonts-20261006-130445/vehicle-chinese-font-comparison.png>)使用本轮读取的系统文件，由Pillow／FreeType直接绘制，主样本全部45px。最后一项当前歌词Noto Sans SC ExtraBold来自正式地图源码，单列用于比较。图像已实际查看；它是本机参考，没有模拟Android回退，也不是车机界面截图。

本轮结果支持更精简的字体菜单建议：

1. **系统默认（MiSans）：** 用已注册的 `sans-serif`，常规字体无需增加包体，不另造一个视觉相同的“MiSans”重复选项。
2. **当前歌词：** 沿已有Manrope＋Noto Sans SC ExtraBold组合。
3. **高德原带：** 沿已确认的SDK_Font。
4. **中文黑体／宋体：** 可沿本车实际Noto CJK文件加载，API28支持 `Typeface.Builder(...).setTtcIndex(2)`；跨设备／固件须先验证路径和文件存在，失败回退当前有效字体。

如果要提供MiSans较粗选项，应使用已经确认存在的Semibold文件，或使用版本／许可明确的应用内字体。不要把缺失的Demibold配置当作可依赖粗体资源，也不要为了应用内字体功能修改系统配置。

这些仍是未实现建议。普通西文手写／窄体字族只改变其覆盖的字符，中文会沿平台回退，菜单应准确预览中文／西文／数字。车机读取的系统文件可以服务本车本地方案；当前结果不证明所有车机／系统版本具有相同资源。

## 5. 本轮检查范围

- 执行 `node scripts/find-vehicle-adb.mjs --serial-only`，第一次未发现后按真实ADB／mDNS状态恢复连接，再次发现并核验型号和SDK成功；后续全部显式带当次serial。
- 只读列出 `/system/fonts` 和系统字体配置位置；未发现本轮检查的product／vendor／odm等候选路径有其它字体目录或字体配置。
- 执行ADB pull获取配置与系统字体，配置1文件／字体236文件，均exit0；font metadata解析完成，未安装额外依赖。
- 对缺失的MiSans Demibold做设备端复核，`ls`exit1的原因明确为该文件不存在；其它检查成功，未通过重命名或写入掩盖问题。
- 本轮没有安装应用／探针、没有改字体／系统设置、没有推送文件或执行车辆控制；没有验证App实际Typeface渲染／粗体回退或导航文字视觉。
