# 高德业务代码地图

## 1. 作用

本目录的主要用途是把用户描述的业务需求翻译成可定位的代码主链：**要改什么 → 谁负责 → 从哪个文件/方法进入 → 上下游在哪里 → 用什么证据验证**。后续例如“改地址输入框”“改分屏启动”“改车标大小”，应先查 [主链索引](主链索引.md)，只打开命中的局部源码；索引尚未覆盖时才按业务词、资源 ID、调用签名逐层扩大搜索，并在同一轮把新入口补回索引。

当前正式源码是 `source/amap-9.5.0.600013/`，由 [正式输入 APK](../archive/amap-9.5.0.600013.md) 经 APKTool 3.0.3 解包派生，并纳入 Git 持续施工。原始输入快照在提交 `ac6033c` 中固定，当前文件数量和 Manifest 哈希会随正式施工变化，不再冒充原始输入。`assets/SignatureKiller/origin.apk` 是 0 字节占位文件；`apk-work/9.5.0.600013/decode/` 是被忽略的实验副本，Java、Smali、Manifest、资源和构建配置在提交前必须同步回正式源码。

## 2. 阅读顺序

1. [基线清单](基线清单.md)：核对输入 APK 身份、来源差异和快照边界。
2. [主链索引](主链索引.md)：用用户任务信号找到业务逻辑和可施工文件/方法。
3. [全量清单](全量清单.md)：只在索引未命中时了解目录分布，不能把混淆类名当业务语义。S191 第三方 APK 的静态差异、双 Surface 分栏链和可借鉴边界已并入 [主链索引](主链索引.md) 第 8 节。

## 3. 证据等级

| 标记 | 含义 |
|---|---|
| 静态确认 | 当前正式源码、Manifest、资源或 APK 静态工具可以直接复核 |
| 实机确认 | 指定 APK 在目标车机上有对应窗口、截图、Surface 或限定日志证据 |
| 实验参考 | 历史实验副本中的实现或现象，不在正式源码中，不能直接作为施工真值 |
| 待验证 | 需求、推断或 native 行为尚无足够证据，不得写成已完成 |

## 4. 更新方式

1. 每项至少写：任务信号、业务 owner、精确相对路径与方法签名、上游/下游、已确认行为、尚待验证的假设、适用 APK 身份和验证入口。
2. 拆分 UI 顶层、地图层、窗口层和启动层。相同视觉现象也可能由不同 owner 造成，不能只按类名或截图猜修改文件。
3. 对“改 UI 的某个部位”，先确认它是 Android View、`ui_surface` 由 native 绘制的控件，还是 `map_surface` 中的地图标注；仅有 `res/values/ids.xml` 中的资源名不等于已定位实际 owner。
4. 如果索引还没有目标控件的具体入口，显式写“未定位”，从现有父层/资源 ID 开始搜索，并将本次核实的局部文件与调用关系写回；不得臆造类名或全量罗列 7,269 个 Smali。
5. 视觉、相机和 native 倍率的生效结论必须在新构建包上运行验证；先核对设备安装 APK 哈希，不能把旧实验运行证据归因给新包。
