### 1.1 当前分屏手势链的回读证据

1. `fix1` 实机已通过启动和默认分屏，但释放手势进入 `animateTo(F)` 后触发 `NoSuchMethodError`；因此“地图瞬移到最右侧后闪退”不是地图 Surface 或 native 相机崩溃，而是吸附动画启动前的 Android API 方法签名不匹配。该结论为本轮车机运行日志确认。
2. `fix2` 的静态回读已确认两处 `ViewPropertyAnimator.setInterpolator()` 使用 `Landroid/animation/TimeInterpolator;`；`fix2` 尚无后续位置、跟手和点击语义的实机证据。
3. 03桌面热区的结构来源为 `03desktop/app/src/main/java/com/ninepointnine/desktop/overlay/DrawerGeometry.kt` 与 `DrawerWindowController.createTriggerView()`：触摸带宽 `60px`、高度 `810px`，白条 `6×150px`、左内距 `32px`，白条在触摸带内垂直居中。本项目只复用触摸带结构和内部定位，白条高度保持产品要求的 `256px`，不引入 03桌面代码或业务依赖。
4. 当前施工副本已去掉 `applyHandleOffset(F)` 的独立位移动画：地图面板是唯一横向位移 owner，触摸带和白条作为其子 View 同步移动；`onLayoutChange()` 在手势进行中不重置位移；`ACTION_UP` 传入非取消标志，点击路径回到提示文案。

### 1.2 当前唯一主链：状态、几何与生命周期

1. **视图层级：** `main_map_view.xml` 的 `panelHost` 直接承载 `mapLayer` 与 `gestureLayer`；地图层承载 `map_surface`、`ui_surface`、`cover`，手势层承载 `gestureNode`；`gestureNode` 下只有 `hintText` 和可见白条。
2. **几何真值：** `updateGeometry()` 从 `panelHost.getWidth()` 得到 `screenWidth`，按 `mapRatio` 计算 `mapWidth`，以 `expandedDividerX = screenWidth - mapWidth` 定义展开锚点；`defaultProgress` 只在首次布局把当前位置初始化为 `expandedDividerX + mapWidth × defaultProgress`。
3. **位移真值：** `applyDividerX(F)` 是唯一写入 `currentDividerX` 的几何出口，将值限制在 `[expandedDividerX, screenWidth]`，并只对 `panelHost` 写入 `translationX = currentDividerX - expandedDividerX`；布局、拖拽和吸附都回到该出口。
4. **触摸真值：** 只有 `gestureNode` 设置 `OnTouchListener`。`ACTION_DOWN` 取消旧的 `panelAnimator` 并让 `hintText` 渐隐；有效横向拖拽直接以 `downDividerX + (rawX - downX)` 更新 `currentDividerX`；错误方向、垂直手势和多指取消不生成第二套位移。
5. **吸附真值：** `finishGesture()` 用 `350ms` 速度预测位置；预测值小于 `expandedDividerX + mapWidth / 2` 吸附展开，否则吸附收起。`animateTo(F)` 启动前取消旧 `panelAnimator`，`onAnimationUpdate()` 仍只调用 `applyDividerX(F)`。
6. **提示真值：** `showHint()` 先取消并清理旧 `hintAnimator`，再在唯一 `hintText` 上同时播放渐变透明度和受边界约束的 `translationX`；动画结束统一隐藏并归零。点击只显示一次提示，不调用吸附；开始按下或拖拽时统一走渐隐出口。
7. **稳定状态不变量：** `0=展开`、`1=收起`、`2=按下`、`3=有效拖拽`、`4=吸附展开`、`5=吸附收起`、`6=阻断手势`；可见手势条不切换 `visibility`，其位置始终由 `gestureNode` 的几何和 `panelHost` 的唯一位移共同决定。

| 地图页面获得歌词容器 | `S191: res/layout/main_map_view.xml` 的 `music_panel_container`；`EmbeddedMusicPlayer.attachToActivity()V` | XML 在地图根布局增加 `tag=music_panel_container` 的 `FrameLayout`，初始宽度 `0dp`、可见性 `gone`。播放器在 Activity DecorView 按 tag 查找，设置层级并挂入动态面板；找不到时还有在 `android.R.id.content` 下创建容器的兜底 | 正式 `res/layout/main_map_view.xml` 只有 `map_surface`、`ui_surface`、`cover`，没有歌词容器；应从正式布局扩展时沿用当前 View/Surface 主链，不复制第三方 XML 或播放器类 |

### 8.3 分屏后按钮、播放状态和地图尺寸如何联动

1. `EmbeddedMusicPlayer.createUI()V` 动态创建播放器外框、`ViewFlipper`、简版页和歌词页；`createControlBar(Z)` 创建上一首、播放/暂停、下一首按钮，三个点击回调分别进入 `playPrev()V`、`togglePlayPause()V`、`playNext()V`，再通过 `MusicNotificationListener.getCurrentController()` → `MediaController.TransportControls` 发出媒体控制命令。`createThinSeekBar()` 另建进度条。设置、最小化按钮由 `lambda$createUI$4/3` 接到设置面板和折叠逻辑；播放器内部页切换不要误记成地图分屏方向切换。
2. 地图让位发生在 `applyLayoutSide()V` / `applyLayoutVertical()V`：播放器容器按 `panelWidthDp` 更新 `FrameLayout.LayoutParams` 的宽/高与左、右或底部 gravity；再经 `setViewMargins()` / `setViewMarginsTB()` 对 `map_surface` 和 `ui_surface` **同时**写入 `MarginLayoutParams` 并调用 `setLayoutParams()`。左右模式的占位量由面板宽度、黑边 `blackBorderDp` 与 `DockLayoutBridge.leftInset()/rightInset()` 共同组成；上下模式把 `panelWidthDp + blackBorderDp` 换算成底部 margin；隐藏模式隐藏面板并清除面板占位，再保留 Dock 左右 inset。角遮罩也同步更新，避免面板切换后边角露底。
3. 这解释了“面板出现后地图区域变窄”：Java View 的可用布局宽高随 margin 变化，而不是通过缩放地图位图或直接改相机参数。正式基线的下游仍是 `MapSurfaceViewEx.surfaceChanged()` → `MapSurfaceView.surfaceChanged()` / native Surface，以及 `rv$b.onLayoutChange()`、`e2.onWindowFocusChanged()` → `GAdaAndroid.nativeOnLayoutChange(III)V`。S191 的四个回调 Smali 未变化，不能证明 Surface buffer、native viewport 或三种视角焦点随布局正确更新；这些必须在正式目标包实测 `View frame`、Surface 回调尺寸、Layer/buffer 和画面。

### 8.6 对 03地图的利用优先级

1. **当前全屏动态分屏最值得吸收的是布局联动模型，不是播放器 UI：**内容层、地图面板、`map_surface`、`ui_surface`、黑边/遮罩必须在同一份几何计算里协调；比例变化与展开/收起必须同步两条 Surface，并给恢复全宽/隐藏状态明确归零规则。S191 提供可追的静态实现，但不提供有效 native 视口的运行证明。
2. **可复用的排障路径：**先看 Activity 内容层容器和具体 View 的 `LayoutParams`，再追 `surfaceChanged` 与 `nativeOnLayoutChange`，最后用同包运行证据核对 buffer、Layer 和截图。不能只看容器宽度变化就断言地图实际渲染尺寸或相机中心正确。
3. **后续可选能力的边界参考：**生命周期回调负责延迟挂载/恢复，播放器与 Dock 独立模块通过 host Activity 接入；需要歌词或快捷 Dock 时核对数据来源、生命周期及导航离开后的清理，任务授权沿用用户已明确目标，不复制 S191 第二 DEX。
4. **明确不沿用：**S191 的 `300dp` 面板默认值、`floatapp` 插件主链、不同密度注入、壁纸隐藏全屏内容和无法归因的 native 库/资源差异；它们与正式输入的密度、窗口和验收边界不等价。

### 8.7 证据等级与未来验证

1. **静态确认：**S191 SHA-256、包元数据/证书、DEX 数量、Manifest/布局、上列 Smali 调用和与正式快照的文件差异；路径仅对应本节开头的 S191 哈希。
2. **未验证：**S191 是否在目标车机实际显示分屏、按钮是否控制目标媒体会话、地图/Surface 是否随左右/上下/隐藏状态稳定重建、地图比例尺/车标/三种视角是否正确；没有 S191 运行证据，本文不作效果结论。
3. **正式施工必须以正式 `source/amap-9.5.0.600013/` 为唯一输入：**验证默认 `1/3 : 2/3`、至少一个其它比例、展开/收起和再次展开，记录两条 Surface 的 View frame、Surface 回调尺寸、SurfaceFlinger Layer/buffer、native layout 参数和截图；再重复冷/热启动及三种地图视角。只有这些证据齐全，才能把“margin 改了”升级为“地图尺寸和焦点正确”。
