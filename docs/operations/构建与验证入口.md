# 构建与验证入口

本文件是本机验证范围、输入证据和构建性能的操作入口；功能覆盖由[验证矩阵](<../testing/验证矩阵.md>)按改动信号选择，签名与安装仍走[APK工作流](<APK工作流.md>)。本轮实现、首次／缓存命中观察和实际验证见[工作流优化记录](<../testing/构建验证工作流优化记录.md>)。

## 1. 先规划，再验证

```sh
node scripts/validate-content.mjs --plan
node scripts/validate-content.mjs --scope docs
node scripts/validate-content.mjs --module content-model
node scripts/validate-content.mjs --module content-ui --tests 'com.icar03.content.ui.LyricInkArchitectureTest'
node scripts/validate-content.mjs --scope model --lint
node scripts/validate-content.mjs --scope all --lint
```

默认`auto`根据Git的已暂存、未暂存、未跟踪路径及当前Gradle模块／依赖图选择；新增模块自动参与，不依赖固定模块数量。正式实现或共享契约变化包含下游消费者；测试文件只选择所属模块。`--scope model`覆盖领域模型及全部消费者；`--module`是显式精确范围，适合失败类重跑，不自动扩消费者，报告会注明；`--tests`可重复，但只能选一个模块。Lint由`--lint`显式追加。

执行顺序为静态检查→所选测试的编译→测试与可选Lint。测试编译失败时立即停止，不先运行其它模块的测试。保留Gradle有效缓存和默认Kotlin增量，不进行clean或强制rerun。计划检查模块包含、Java白名单、正式源码路径和依赖闭包；`--plan`不执行Gradle、不读取私有工具配置或生成报告目录。

证据在忽略的`apk-work/validation.*`：计划、输入指纹、阶段日志、单调耗时／退出码与报告；任务分别记“本次执行／UP-TO-DATE或FROM-CACHE复用／未执行”。没有新XML不代表有效缓存证据失效。过滤测试不称全模块／全工程通过，源码或工具输入在验证期间改变时不接纳混合证据；纯文档检查不被无关源码施工阻断。

## 2. APK核验与源码回归分开

```sh
bash scripts/build-content-apk.sh
bash scripts/test-content-host.sh "$SIGNED_APK"
```

构建仍从正式源码编译、重链接、R8、对齐并按现有身份签名。`test-content-host.sh`保留名称兼容，但只检查指定签名包的身份、对齐、ZIP、原DEX、native及新增DEX闭包，不启动Gradle；包级报告绑定APK SHA-256，不冒充车机运行证据。相邻`original.dex`是同次APKTool回编产生的原primary校验输入，缺失时失败，不从其它候选借用。

构建目录新增`source-before.json`／`source-after.json`、`timings.jsonl`、`compose-command-timings.jsonl`与`build-report.json`。阶段使用单调时钟，签名阶段不记录私钥参数；Compose子阶段单独标记，不能与外层Compose整体耗时重复相加。结束前重新核对源码指纹，变化时停止发布候选；校验失败的中间包仍清理。

## 3. 固定输入缓存与批处理

`apk-work/9.5.0.600013/compose-cache`只保存从已核验正式输入生成的本机中间物：构建helper、AAR提取及Manifest信息、依赖AAPT2资源、ASM重定位JAR、原Smali ABI stub。缓存键包含输入SHA、helper源码、ASM／JDK或AAPT2工具指纹；命中时逐文件校验字节哈希和清单，缺失、额外文件或损坏会重新生成。依赖图／版本／SHA锁每次构建预检，下游再次核对冻结输入字节，避免仅按路径／mtime信任缓存。

Manifest解析、R生成和ASM重定位分别在一个JVM批次中执行；任何作业失败立即停止。R生成仍由当次合并资源符号决定；R8全图、原public IDs、原63库SHA、全部so Deflate、服务元数据、DEX闭包及最终签名检查继续执行。没有从旧候选APK借DEX。APKTool基线和正式资源仍回编，先用阶段报告量出剩余成本。

需要排查缓存时仅对当次构建禁用读取，不删除归档或他人产物：

```sh
CONTENT_BUILD_CACHE=0 bash scripts/build-content-apk.sh
```

## 4. 并行施工与有效证据

新构建／源码验证入口及独立Compose诊断入口共享`apk-work/.content-workflow-lock`；已有活跃owner时立即报告PID，不轮询等待。死亡owner通过原子恢复目录串行处理并重新核对owner，不能删除后来建立的活锁；恢复中断时停止并报告实际恢复目录，避免再次抢占。锁协调共享生成目录，不能阻止编辑器或旧命令直接写入，所以仍核对开始／结束指纹。

同一编译闭包的并行施工先约定接口及owner，独立任务使用隔离worktree或正式源码冻结快照；一个执行者负责共享构建。快照必须保留正式输入与脚本的逐SHA来源，不用隔离候选代验收正在变化的整合树。稳定整合点再执行适用全量；文档按唯一事实owner回填，失败流水保留在机器日志，不升级成以后每轮的全量门槛。
