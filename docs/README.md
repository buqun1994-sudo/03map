# 文档索引与职责

## 1. 当前口径

当前产品主线是高德 `9.5.0.600013` 的全屏动态分屏：启动即进入展开态，默认内容区约 `1/3`、地图区约 `2/3`；内容区主题只跟随高德自身主题状态。历史 `480×480` 悬浮地图只保留在[历史支线](<archive/480x480支线.md>)。

本目录只保存可追溯事实、稳定决策、源码锚点、验证证据和研究记录。聊天中的一次性判断不直接升级为长期真值。新增限制须有用户要求、已验证的技术原因或具体个人风险依据；来源模板和其它项目的规则不自动继承。个人风险只维护在[安全与密钥边界](<security/安全与密钥边界.md>)。

[正式源码](<../source/amap-9.5.0.600013/>)是 Git 跟踪的可维护入口；原始输入快照固定在 `ac6033c`，被忽略的[本机产物区](<../apk-work/>)只作为实验和产物区。提交前按[APK 工作流](<operations/APK工作流.md>)回写源码并从正式入口重建。

固定路由为：[正式源码](<../source/amap-9.5.0.600013/>)、[产品需求基线](<../docs/product/产品需求基线.md>)、[代码地图说明](<../docs/code-map/README.md>)、[主链索引](<../docs/code-map/主链索引.md>)、[项目Skill](<../.agents/skills/>)；下表链接均可从本索引打开。

## 5. 写入规则

1. **一事实一 owner：** 需求写产品基线，架构写内容区主链，源码入口写代码地图，设备证据写研究或验证，当前状态写进度。
2. **当前与历史分离：** 历史结论必须带日期和证据等级；不得用历史包、旧坐标或旧尺寸覆盖当前主线。
3. **证据分级：** 统一使用“静态确认／实机确认／实验参考／待验证”；推断不得写成完成事实。
4. **控制体量：** 长期总纲、产品基线、进度保持短；架构文档只保留owner和不变量；原始研究允许增长，但必须先维护摘要和结论表。
5. **改动联动：** 修改主线、源码入口或验证门槛时，同轮更新对应owner文档和本索引；不要在多个文档复制同一段事实。
