# 产品需求基线

> **职责：** 只定义用户可见的当前目标、行为和验收语义。系统边界见 [项目长期总纲](../architecture/项目长期总纲.md)，架构 owner 见 [内容区主链](../architecture/内容区主链.md)，偏好默认值见 [设置项清单](设置项清单.md)，验证证据见 [验证矩阵](../testing/验证矩阵.md)。

## 用户与目标

用户在 iCAR 03 车机壁纸状态下使用地图导航：左侧提供可扩展内容区，右侧保留高德真实地图、导航、定位和地图交互能力。当前目标是启动即进入全屏动态分屏；历史 `480×480` 悬浮地图已封存。

## 地图与手势

1. 正式输入为高德 `9.5.0.600013`、125% UI、默认全屏 APK。
2. 默认内容区约占屏幕宽度 `1/3`，地图区约占 `2/3`；地图面板保持自身宽度，收放只改变横向位置。
3. 启动首帧直接呈现展开态，不以透明页面、隐藏预览或延迟搬运掩盖过程。
4. `map_surface` 与 `ui_surface` 同步随地图面板几何变化；不以 UI 密度修改替代地图层问题。
5. 手势条只响应横向拖动；展开时位于分界处，收起时留在屏幕最右侧。松手后吸附到展开或收起稳定态，中途接管从当前位置继续。
6. 单击只显示一次轻量提示，不改变地图状态，不触发系统返回或主页动作。
7. 2D 车首、2D 北上、3D 车首均保持正确视觉焦点；不以未经验证的固定 native 偏移解决问题。

## 内容区

1. 主题只跟随高德自身解析出的浅 / 深色状态；不读取系统 `uiMode`，不维护第二套主题开关。背景和控件使用同一组高德主题令牌。
2. 首轮可见页面为 `shortcuts → lyrics`，单页横向滑动并吸附，默认主页为 `lyrics`；歌词由当前媒体会话的真实身份、可信播放时间线和03歌词解析／缓存核心驱动，直接显示在内容区中间留白，不再使用占位卡片；无正文时按下节真实终态显示居中文案与可选来源入口，不展示施工文案；`vehicle_info`、`projection` 首轮不展示。快捷页按第4项共用清单排布，已接通的车锁和主驾通风／加热／按摩仍为圆角方形**多状态按钮**，图标在上、文字在下，按原型四列间距排布；禁用方向盘占位和设置入口不伪造状态。下排纵向滑条用于**屏幕亮度和媒体音量**，与座椅命令完全分离。左侧内容板块使用车机系统原生密度计算控件尺寸，右侧高德 125% UI 密度不得放大左侧；SVG 中重复的座椅卡仅表示排版节奏，**不是必须补齐的空位**；不复制同一功能来填满网格，不添加未验证的假控制。页面可滑动，但页面切换圆点／页码指示器不在可见界面出现；稳定态相邻页／卡不能外露。
3. 控制区只有媒体和空调模块，默认 `media → climate`；媒体卡按 SVG 呈现为一块横向整体：底框 `600×120`，左侧封面为等高正方形、左侧圆角右侧直角；标题／歌手限制在中部文字区，不能挤压播放与下一首；右侧经一条细分隔线连接仅图标的媒体来源，展开后显示图标与完整名称。播放、暂停、下一首使用同车原厂实心图标；播放、下一首和来源不再各自套独立外框或排成第二行；播放／暂停原厂转场从原状态的0帧正向走到目标末帧，播完停留，不回闪首帧或切换另一套图形；高密度窄面板时优先保证“暂无媒体”等短状态可读。空调未接通时只在其对应卡内说明不可用；设置未接通时只在用户触发对应入口时说明，不在快捷页额外放“设置暂不可用”横条。
4. 快捷页与Dock共享同一入口清单和控制状态：车锁、方向盘加热、主驾通风、加热、按摩、设置。方向盘加热仅原厂图标禁用占位，不读取或写入未研究的车辆值；设置保留入口但当前未接通，触发时局部反馈。Dock不再有独立“快捷／菜单”入口，歌词与快捷页仍由横向滑动切换。Dock同一底座内车锁居左，其余五槽仅显示图标；车锁已锁为非选中、解锁为选中，选中背景铺完整车锁槽位；其余Dock槽选中仅显示与媒体按下相同尺寸／圆角的局部矩形。快捷功能与Dock共用从实际触点扩散的背景微动画，完整48dp以上热区不缩小；图标微动与扩散并存，不用直接变色或单纯缩放替代触点扩散。媒体按钮保留单层圆角矩形按下背景，固定RGB只动画透明度，避免先深后浅的闪变。快捷按钮只显示图标和较大名称，不显示第三行状态文字；实际／目标档位保留图标与无障碍说明。座椅沿原厂各档几何和档位透明度分层着色：关闭轮廓为主题基础色、关闭标记灰；开启时座椅轮廓也跟随功能色（通风蓝／按摩紫／加热橙），未激活档位继续灰色，快捷页与Dock呈现一致。车锁解锁为蓝色、锁定为主题基础色。五种媒体来源统一使用已核实的原厂简笔图标；爱趣听恢复原厂音符线图。
5. 歌词页 / 投屏页可进入页面沉浸式状态；快捷功能页不支持。地图重新展开时退出沉浸式状态。
6. 顶栏始终只有一行：所有状态时间在最左并带星期（遵循星期显示偏好），时间与星期之间有统一细间距，充电态星期与温度的内容间距额外增加4dp；时间／温度撤销20sp／窄幅18sp覆盖，恢复统一titleLarge（22sp）。电池外框始终为主题基础色，内部电量／充电符号绿色；充电图形继续使用已登记原厂图，不自绘替代。右侧固定剩余里程数值＋`km`＋电池图标。默认态温度在右侧状态区，右对齐且紧邻里程；插枪、预约、充电或待确认时状态右对齐并紧邻里程，温度移到时间右边。先测量文字自然宽度；放不下时优先让温度让位，再省略秒数、将“星期三”缩为“周三”，最后压缩充电详细文案，保留时间、星期、充电主状态和里程电池，完整状态保留无障碍说明；不得重叠或靠地图125%密度挤入。用户本次明确要求里程附`km`，覆盖此前仅原始数值的暂定显示，但不把显示决策写成新的仪表单位研究证据。状态字号与其他顶栏主文字匹配，不加可见“续航”前缀或电量百分比；无数据为`--`且不伪造读数。功率只用`kW`、剩余时间只用分钟，真实字段无效时不补值，`kWh`不能作为功率单位。连接确认插枪未充电显示“已插枪”；明确预约等待显示“预约充电中”；实际充电优先显示“剩余11分钟·72.0kW”这类真实分钟＋功率，有效字段缺一只显示另一项，两者均无效才显示“充电中”。原始电量精确100%且已插枪并明确停止充电显示“充电完成”；未知状态不猜完成，不能用四舍五入后的显示电量推断。实际多密度容量和省略项进入本机验证记录。
7. 浅色视觉以 `Group 77.svg`（来源菜单关闭）和 `Group 78.svg`（来源菜单展开）为完整画面基准，不是只提取颜色、圆角和局部控件。浅色背景底色为高德浅色#EFF0F7；普通按钮#E9E9E9、选中#E4E4E4、按下层#E2E2E2，恢复此前浅色配色；Dock、媒体卡和来源浮层保持白色。深色背景#0F0F0F，普通按钮#1A1A1A、选中#484848、按下层#5C5C5C，均为中性黑白灰。媒体卡保留整体提升层；深色来源浮层与Dock底座用非选中底色、选中项用更亮选中底色，两个纵向滑条的填充统一#484848；浅色滑条填充和底座保持白色、来源选中行恢复#E9E9E9。内容右侧有浅细分界线，始终跟随内容实际宽度，不按固定像素定位。主要靠填充差异和轻微向下柔和阴影建立层级；禁止给每张卡片、按钮、滑条、媒体内部区域及 Dock 槽位统一添加可见描边。只有原型明确出现的内部细分隔线保留。文字的字重、留白、顶栏锚点、媒体卡横向结构与整体轻盈感一并作为视觉验收项；占位卡数量和示例数据不作为功能验收项。
8. 只要当前媒体会话已确认是歌曲，内容区就保持封面氛围背景，覆盖顶栏、页面、控制区和Dock的下层，不依赖当前页面、歌词是否已获取或正在播放。切歌、缓冲、暂停和新封面暂缺期间保留最近有效的封面背景；新封面准备好后柔和过渡，暂停只冻结背景运动。出现、切歌替换和确认非歌曲后的消失共用500ms柔和淡化，快速中断从当前混合画面继续，不回到黑色或背景加载页。歌曲身份与歌词共用音频语义及元数据门禁，不由播放按钮、封面有无或包名单独推断；明确非歌曲退出，短暂同源元数据空窗允许1500ms确认宽限。尚未取得过真实封面时保留主题底色；进入后台停止动效和任务并释放引用。封面色场保留宏观色彩布局、柔化明暗差并叠加缓慢柔光，双主题只调整可读性遮罩，主题仍只跟随高德。
9. 页面和控制区翻页项的外层宽度等于各自内容面板的**实际可视宽度**，组件两侧的边距只放在翻页项内部。每次翻页后布局一致，稳定态右侧不截断当前项，也不露出相邻项；面板收放或宽度变化后仍按实际可视宽度对齐。
10. 车控与媒体按钮点击后立即切换目标图标并启动可用的触控／动画反馈，不等待车辆或媒体服务返回；车控反馈在同一待确认命令期间呈现，不叠发车控写入，真实成功仍由状态回流确认，失败、断连或超时恢复实际图标并提示。媒体命令不阻塞点击线程，未确认时显示目标图标，失败或超时回到媒体实际状态。
11. 页面内任何可见 UI 交互都要有动画：按钮触控／状态变化、纵向滑条拖动与吸附／回弹、翻页、菜单开合、顶栏布局转换及主题切换都须可见、可中断并正确停止；座椅通风／加热／按摩及五种媒体来源均播放已登记原厂路径动画，座椅从所选档位区间起点正向走到终点；每次只播放一次并停留同一动画末帧，不能在结束时闪首帧、循环或立即切另一套静态图形。静态资源的图标保留按压／状态微动。状态动画不得由时钟或重复快照重播；来源按下触发的动画在抬手后继续播完；暂停／失焦／离屏取消并回稳定图标，恢复不补播。所有可执行按钮复用车机原有点击音效，禁用、取消触摸、程序状态回流不发声，一次确认点击不双响。媒体来源恰为“蓝牙音乐、爱趣听、网易云音乐、USB音乐、本机音乐”，其中 U 盘与 USB 为同一来源；五项均有各自原厂图标，不使用 SVG 占位图标；SVG 菜单中重复的 USB / U 盘及示意图标不能覆盖这五项规则。

## 歌词与封面

1. 使用完整 Lyrimuse 源码作为能力参考，范围包括国内多源检索、版本匹配、正文质量升级、逐字/译文/源音译、缓存、真实播放跟随和原生封面回退；不能仅修复字号或三项表面问题。网络目录重点 QQ、网易云、酷狗、酷我、咪咕、汽水，保留 LRCLIB 兜底；用户明确不要求 Musixmatch、LyricFind、Deezer、AMLL 联网来源。
2. 歌词、封面只采纳能够与当前录音对应的真实来源，不能用搜索结果第一项、请求时长或伪造平台来通过匹配。蓝牙音乐不表示手机播放器品牌；保留来源倾向能力，当前不增加设置页。
3. 检索期间可先显示已验证的同步正文，但已有可用歌词后只允许真实能力升级（静态变同步、主要正文变完整逐字、有效译文／音译补齐）或可证明的截断正文补全；不同普通行歌词不能仅因末尾时间／跨源一致性分数更高而替换，包括首轮无缓存。升级不得丢已有有效附轨，同录音正文几何改变须从当前可见歌词锚续接。人工采纳始终优先。保留未来音乐平台偏好接口：同能力档优先对应来源，不把平台偏好降为细分分数的末级平局项，不无限循环追求更高分；仍不能放松同录音准入。源翻译和音译可独立显示，服务暂时失败不清除已经可用的主轨。
4. 当前句和逐字显示只跟随真实媒体位置；暂停冻结、seek 正确回退或前进、切歌拒绝迟到结果。同发布者可验证的倒序位置不得覆盖新锚点；真实新位置为0仍可回到开头。未知位置不作为首行游标，呈现保留既有滚动几何，恢复可信位置后从当前画面续滚；纯文本保持可浏览的静态正文，不假装同步。前台无歌曲时不得出现歌词加载／匹配文案。
5. 透明视窗歌词非当前40sp、current主文48sp并使用真实高字重，22sp译文、20sp源音译，左右48dp内缩；全曲按最大current字号固定占位，非当前只在每个视觉行的固定槽内缩小绘制，不因换句重排／抖动或让长段落首屏空白。合法跟随句成为current即放大、清晰，不能等first-word开唱才变大；current呈现与源singing分离，未知进度、真实等待行和歌曲端点不造当前唱词。非当前歌词更明显地柔化，近、远、过去层次清楚但仍可浏览。定时歌词支持平滑跟随、真实间奏、重叠声部及手动浏览后回跟；静态正文浏览保留到切歌。
6. 每个可安全独立移动的可见Unicode视觉单元按源词原区间轻微上浮、放大、回落；最高点辉光最强，最低点与源词首尾无残光，揭示边缘羽化。组合字符、emoji序列、真实连字与复杂joining文字保持原完整字形，彩色emoji保留颜色；不按UTF-16拆字，不为演出伪造逐字符时间戳、不延长短词、不提前句尾。复杂文字无法安全独立移动时保留完整shaping与真实源词渐显。暂停冻结、seek可复现，动效不改变歌词geometry或业务时间线。
7. 无正文终态精确显示“暂无歌词”“网络错误”“纯音乐，请您欣赏”，每条文案文本自身的中心精确对齐歌词视窗水平与垂直几何中心，不把文案＋来源按钮整体居中而上移文案；可选来源按钮位于文案下方12dp，来源入口有无不能移动文案。纯乐不显示歌词区来源按钮，底部媒体区来源入口保持。纯音乐必须有对应录音的明确来源boolean或唯一明确歌词标记及既有严格匹配证据；空正文、曲名、长gap不能猜，无假歌词行或词轴。已可用真实正文始终优先，刷新失败不得降为空态。正式歌曲正在检索且无正文时保持blank背景，不新增加载／来源提示；前台无歌曲只呈现普通暂无歌词，不泄漏旧网络／纯乐原因。
8. 歌词与封面均自动缓存，共享1GiB稳定存储上限；自动内容统一淘汰，人工歌词保留，满额不足时拒绝新写而不删人工记录。原生封面优先且自动持久化，缺图时先查同录音缓存再查询网络封面并有界重试；单图大小／解码边界不随总容量放宽。出现新有效封面前继续按已验收语义保留最近有效背景，运动是微弱、慢速、确定种子的多周期非线性流动，暂停与后台冻结而非重置相位。上游桌面私有缓存、需要授权的 Apple 接口、机器翻译及尚未迁移的管理界面明确记录适配差异，不以无效占位宣称具备。
9. 三个点属于歌词流内的前奏／间奏等待行：第一句前或已结束句与下一句之间，以真实时间边界全曲提前占位，参与同一排版／滚动，不能固定悬浮到歌词上；进入／退出等待只改变激活与跟随，不临时插入挤动正文。普通LRC只有行首间隔时不估唱完，不据长间隔猜间奏。
10. 自动缓存始终启用。进入后台只停止副作用／释放IO，不能清空同录音已可用正文；临时正文经准入并可展示即及时保存。回前台先验证当前录音，仍是同歌保持READY，换歌／换源按既有隔离重新获取。必要预览加载文案在歌词区域双轴居中；正式模式保持第7项blank规则，无歌曲不出现加载提示。

本轮低开销实现与参数证据见[逐字符歌词研究](../research/逐字符歌词低开销渲染与Apple风格适配-20261003.md)，第五轮fresh661项测试、四Lint与正式同包核验已通过；最终唯一合法发现未找到在线目标，未安装／smoke／测车机性能或视觉。本机证据与当前车机待验边界见[本轮验证记录](../testing/歌词渲染与背景性能重构验证记录-20261003.md)，不继承旧包的安装或性能结论。

## 车机能力

1. 车控是正式产品能力范围，不是仅供研究的附属功能；车锁、座椅、空调、充电和其它已验证车机能力按统一入口逐项接入。
2. 车控入口只通过统一状态、命令端口和车辆适配器工作；页面不直接依赖厂商属性编号、Binder 事务或设备权限。应用不附加P档或零速限制，驾驶条件是否允许由原车系统处理；系统拒绝、断连和超时仍回到唯一实际状态，不以已发命令判成功。
3. 每项车控能力必须完成读取 / 订阅、命令执行、成功状态回流、失败状态回流和可逆恢复验证；未完成闭环的入口显示不可用或施工预览。
