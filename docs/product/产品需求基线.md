# 产品需求基线

## 1. 用户与场景

用户在 iCAR 03 车机壁纸状态下使用地图导航，希望地图以全屏动态分屏形态显示：左侧保留可扩展的内容区，右侧承载高德地图。地图应复用高德真实地图界面，保留地图自身的导航、定位和交互能力。

## 2. 正式输入与目标

1. 输入：已保存的高德 `9.5.0.600013`、125% UI、默认全屏 APK。
2. 目标：从该输入 APK 修改出正式的全屏动态分屏版本。
3. 历史 `480×480` 悬浮地图保留为可继续研究的支线，不作为当前默认布局或验收尺寸。

## 3. 正式需求

### 3.1 启动形态

应用启动后默认直接呈现全屏分屏地图。不能先进入其它本体页面，再通过透明 Activity、alpha 为零、隐藏预览或启动后延迟搬运来制造“像是直接分屏”的效果。

### 3.2 分屏几何

1. 本轮沿用输入基线已经确认的 `125%` UI 密度，不修改 UI 密度链。
2. 内容层从启动时铺满全屏，地图作为右侧面板覆盖在内容层之上。
3. 默认内容区占屏幕宽度的 `1/3`，默认地图区占屏幕宽度的 `2/3`。
4. 内容区与地图区比例必须由单一几何参数计算，后续允许增加用户可调比例，不得把 `1/3`、`2/3` 分散写死在多个调用点。
5. 地图面板在收放动画中保持自身宽度不变，只改变横向位置；地图不能通过压缩宽度实现收起。
6. `map_surface` 与 `ui_surface` 必须使用同一份面板几何同步更新，不能只移动其中一条 Surface。

### 3.3 手势条与收放

1. 手势条只处理横向拖动，单击和长按不触发其它操作。
2. 手势条使用中性色，不随车机主题色变化；可见条沿用 `03桌面` 的视觉口径，长度暂定为物理 `256px`，触摸热区独立设置并比可见条更容易抓取。
3. 展开态手势条位于内容区与地图区交界处；收起态手势条保留在屏幕最右侧。
4. 地图展开和收起只有两个稳定状态；拖动中允许处于中间位置，松手后必须吸附到其中一个稳定状态。
5. 松手判定综合使用拖动距离和横向速度，以短时预测位置决定目标状态；不能只使用单一距离阈值或单一速度阈值。
6. 收放动画沿用约 `200ms` 的减速动画；动画中途再次触摸时，从当前位置继续拖动。
7. 手势条单击显示一次轻量操作提示，不改变地图状态，也不触发系统返回或主页动作。
8. 地图展开态提示文案为“向右拖动收起地图”，地图收起态提示文案为“向左拖动展开地图”。
9. 提示层贴近手势条显示，带柔和的中性色渐变底托；文字缓慢左右往返约 3 次后自然渐隐，不遮挡地图核心区域，也不产生持续闪烁或廉价弹跳感。

### 3.4 主题背景

1. 左侧内容区背景跟随系统亮暗主题变化，复用 `03歌词` 已验证的系统主题读取方式。
2. 车机主题色读取方式保留给未来内容区按钮、控件和选中态；当前空白内容区不强行使用主题色。
3. 主题切换后，内容区背景应在当前进程内正确刷新，不影响地图 Surface 和地图状态。

### 3.5 地图状态与视口

地图区域宽度变化不得通过硬编码相机偏移解决。地图应继续保持导航、定位和地图交互状态；比例变化、展开收起和再次打开都必须沿用地图自身的 Surface 与 native 布局回调。

以下视角都必须通过验收：

1. 2D 车首。
2. 2D 北上。
3. 3D 车首。

分屏布局可能改变地图可用视口。需要确认偏移来自 Surface View frame、Surface buffer、父容器裁剪原点、native layout 通知，还是地图引擎自己的视角锚点；在证据不足前不得直接添加横向或纵向 native 偏移。

## 4. 交互验收

1. 启动首帧直接进入全屏分屏，没有其它本体页面闪现。
2. 默认内容区为屏幕宽度的 `1/3`，地图区为屏幕宽度的 `2/3`。
3. 地图展开和收起只改变地图整体位置，不压缩地图面板，不丢失导航和定位状态。
4. 手势条只响应横向拖动，展开态和收起态均可操作，收起后手势条仍在最右侧。
5. 内容区背景正确跟随亮暗系统主题，手势条保持中性色。
6. 三种视角都以正确的当前位置和方向呈现，不出现由分屏裁剪造成的相机偏移。
7. 比例参数变化后，两条 Surface 同步更新，地图状态和相机中心保持稳定。

## 5. 当前非目标

1. 不重新实现地图渲染、路网、定位或车道级数据服务。
2. 不修改车辆控制、CAN、车厂私有接口或地图商业授权链。
3. 不把 ADB、电脑常驻连接、root 或无障碍操作作为正式产品依赖。
4. 不用地图 UI 密度调整替代地图层文字、车标或相机问题。
5. 当前不施工内容区业务控件、比例设置入口或主题色控件，只保留可扩展的比例和主题主链。
