# 内容区底层架构主链

> **职责：** 定义内容区的分层、状态流、唯一 owner、生命周期和适配边界。产品行为见 [产品需求基线](../product/产品需求基线.md)，用户偏好见 [设置项清单](../product/设置项清单.md)，源码锚点见 [主链索引](../code-map/主链索引.md)。
>
> **当前状态：** 首轮内容结构已在被忽略施工副本中形成 `ContentRegistry`、`ContentStore`、`ContentRuntime`、`ContentRenderer` 与 `ContentVehicleAdapter` / `ContentMediaAdapter` 的快照回流闭环；正式 APK 的车机权限、服务可达性和运行级状态回流仍待实机确认。历史 `480×480` 悬浮链和 S191 只作为参考，不属于本主链。

## 1. 运行形态与边界

`03地图` 是以高德地图为宿主的单 APK。内容区不嵌入外部 APK、Activity、WebView 或独立悬浮窗，而是在地图 Activity 的内容层中运行：

```text
一个 APK
└── 高德 Application / 地图 Activity
    ├── 高德地图链
    └── 03地图内容链
        ├── MediaAmbientBackgroundRenderer
        ├── 顶栏
        ├── 页面
        ├── 控制区
        ├── Dock
        └── 临时浮层
```

`MediaAmbientBackgroundRenderer` 是内容宿主内的全局背景层，必须位于顶栏、页面、控制区、Dock 和临时浮层的下方；它消费媒体快照及专辑封面派生的色彩 / 模糊状态，不属于歌词页，也不随页面切换创建或销毁。内容区只负责内容层；地图面板的宽度、位置、两条 Surface 和 native 布局仍由既有地图主链及 `SplitPanelController` 负责。页面不得直接修改 `map_surface`、`ui_surface` 或地图 Activity 的分屏几何。

允许借鉴 S191 的只有三点：同 APK 集成、Activity 生命周期挂载、动态 View 宿主。不得复制其播放器、插件主链、第二套宽度计算、`300dp` 默认值、密度策略或无法归因的 native / 资源差异。

## 2. 内容层级

```text
地图 Activity 根布局
├── ContentHost（全屏内容层）
│   ├── MediaAmbientBackgroundRenderer
│   ├── TopBarRenderer
│   ├── PagePagerRenderer
│   ├── ControlCarouselRenderer
│   ├── DockRenderer
│   └── TransientOverlayRenderer
└── MapPanel（既有地图层）
    ├── map_surface
    ├── ui_surface
    └── 手势条 / 提示层
```

正式布局锚点是 `res/layout/main_map_view.xml` 根 `FrameLayout`。内容层可以覆盖在地图层之上，但不能把两条地图 Surface 改造成业务容器。

## 3. 注册表与首轮内容

### 3.1 页面

页面以稳定 `pageId` 注册，物理数组顺序不作为身份：

```text
PageRegistry
├── shortcuts       可见
├── vehicle_info    已注册，首轮隐藏
├── lyrics          可见，首轮占位
└── projection      已注册，首轮隐藏
```

首轮派生顺序为 `shortcuts → lyrics`，默认主页为 `lyrics`。页面通过能力声明决定是否支持沉浸式状态；快捷功能页不支持，歌词页支持，投屏页预注册但未展示。

### 3.2 控制区

```text
ControlRegistry
├── media
└── climate
```

默认顺序为 `media → climate`。座椅通风、座椅加热和座椅按摩属于快捷功能，不注册为控制区模块。

### 3.3 Dock 与快捷功能

```text
ShortcutCatalog
├── lock             固定在左侧
├── shortcuts        右侧槽位默认项
├── seat_ventilation 右侧槽位默认项
├── seat_heating     右侧槽位默认项
├── seat_massage     右侧槽位默认项
└── settings         右侧槽位默认项
```

Dock 是“固定车锁 + 五个可替换槽位”。Dock 与快捷功能页共享同一 `ShortcutCatalog`、状态和命令端口；长按入口只发出 `BeginShortcutEdit` 意图，切换到快捷功能页编辑，不复制第二套清单。

### 3.4 顶栏

顶栏只订阅归一化 `TopBarState`，不自行轮询 Vehicle HAL、读取 MediaSession 或写偏好。当前预留时间、星期、车内温度、电量、充电状态、档位和天气；未完成正式应用层权限 / 订阅闭环时显示不可用或施工预览。

## 4. 呈现状态与地图几何

### 4.1 稳定状态

```text
ContentPresentationState
├── SPLIT
└── PAGE_IMMERSIVE

ImmersiveInteractionPhase
├── IDLE
├── DRAGGING
├── ELASTIC_REBOUND
└── SETTLING
```

`PAGE_IMMERSIVE` 只对当前页面生效。切换到不支持沉浸式的页面前，必须先回到 `SPLIT`；地图重新展开也等价于退出沉浸式状态。

### 4.2 唯一动画真值

```text
presentationProgress = 0
  分屏稳定态，地图完整可见

presentationProgress = 1
  当前页面沉浸式稳定态，地图完全推出

0 < presentationProgress < 1
  拖动或吸附过程，不是新的稳定页面状态
```

当前实现不另建第二套呈现协调器：`SplitPanelController` 的 `applyDividerX(F)` 是呈现进度、吸附动画和地图物理几何的唯一 owner；`ContentRuntime.onDividerChanged(...)` 只转发同一份进度给内容层，`ContentRenderer` 不反向改写地图尺寸。

不可沉浸页面允许受限弹性拖动，初始 `elasticLimit <= 0.12`，且必须小于沉浸式吸附阈值 `0.5`。受阻拖动不得改变页面、偏好、控制区或 Dock 状态。

### 4.3 渐进派生

Renderer 只接收 `DerivedUiState`、`presentationProgress` 和本页 `ImmersiveTransitionSpec`，派生位移、尺寸、透明度、间距和显隐；不得分别启动进入 / 退出动画。动画反向直接复用同一插值函数，不复制第二套退出逻辑。

## 5. 唯一数据流

```text
系统 / 车机 / 媒体 / 歌词 / 投屏
              ↓
        Port / Adapter
              ↓
      归一化 Snapshot
              ↓
       ContentStore / Reducer
              ↓
       DerivedUiState
              ↓
         Renderer / View
              ↓ 用户意图
      Command Port / Effect
              ↓
        Adapter 执行与回流
```

所有 UI 是状态投影，不持有业务真值。点击成功不能直接等同于业务成功，必须等待外部状态回流。

| 事实 / 行为 | 唯一 owner | 页面使用方式 |
|---|---|---|
| 呈现模式、进度、吸附 / 回弹 | `SplitPanelController.applyDividerX(F)` | 地图几何和内容宿主消费同一份进度，不创建第二份动画真值 |
| 地图面板、两条 Surface 几何 | `SplitPanelController` | 从进度派生，不由页面改写 |
| 主题 | 高德主题回调 → 内容主题状态 | 不读取系统 `uiMode` |
| 时间 | 系统时钟适配器 | 统一派生 `TopBarState` |
| 车辆状态 | `VehicleAdapter` → `VehicleStateStore` | 顶栏、车辆页和快捷入口订阅同一快照 |
| 媒体状态 | `MediaSessionAdapter` → `MediaStateStore` | 媒体卡片、歌词页和 `MediaAmbientBackgroundRenderer` 订阅同一快照 |
| 媒体氛围背景 | `MediaSnapshot` / 专辑封面 → `MediaAmbientBackgroundRenderer` | 播放中覆盖整个内容板块；停止或无封面时回退主题背景 |
| 歌词 | `LyricsEngine` | 只消费媒体身份和时间线 |
| 投屏 | `ProjectionEngine` | 通过命令 / 状态模型接入 |
| 排序和显示偏好 | `ContentPreferenceStore` | 只保存稳定 ID 和用户设置 |
| 页面 / 控制 / Dock 当前选择 | `ContentStateStore` | Renderer 只消费状态 |
| 临时浮层 | `InteractionStateStore` | 统一超时和显隐 |

运行时状态、持久化偏好和派生状态必须分离；派生值不能反向成为第二真值。

## 6. 生命周期与物理锚点

### 6.1 锚点

1. Application：`source/amap-9.5.0.600013/smali/com/autonavi/amapauto/app/MapApplicationProxy.smali` 的 `onCreate()V`。
2. 地图 Activity：`MainMapActivity` 相关 Manifest / 生命周期链；施工前必须以 Manifest 和调用证据确认唯一 owner，不能只按类名判断。
3. 根布局：`source/amap-9.5.0.600013/res/layout/main_map_view.xml` 的根 `FrameLayout`。
4. 地图几何：施工副本中的 `smali/SplitPanelController.smali`。
5. 首轮内容入口：施工副本 `content-src/com/autonavi/amapauto/content/` 下的 `ContentRegistry`、`ContentRuntime`、`ContentStore` 和 `ContentRenderer`。

### 6.2 生命周期合同

```text
Application.onCreate
  → 注册生命周期桥接，不创建 View
Activity.onResume
  → ContentRuntime.attach(activity)
  → 幂等挂载唯一 ContentHost，绑定 Store / Renderer
Activity.onPause
  → 暂停动画、刷新和触摸，保留 Store 状态
Activity.onDestroy
  → ContentRuntime.detach(activity)
  → 解除 Activity / View 引用和宿主订阅
```

必须满足：同一 Activity 只有一个 `ContentHost`；重建不重复注册；适配器不持有失效 Activity；页面重建不重复注册底层监听；内容区生命周期不重启地图。

## 7. 能力适配边界

### 7.1 媒体、歌词、投屏

- 媒体读取、来源切换和标准控制沿 [车机媒体能力研究](../research/车机媒体能力研究.md) 的已验证路径接入。
- 歌词只迁移业务逻辑、解析和时间轴，不在页面内读取通知、枚举 MediaSession、发网络请求或管理全局定时器。
- 投屏只迁移业务逻辑、状态模型和协议适配边界；页面不直接持有协议连接、不修改地图几何。

### 7.2 车辆与车控

车控状态至少能表达：

```text
AVAILABLE / UNAVAILABLE / STALE / PERMISSION_REQUIRED
EXECUTING / FAILED
```

研究文档是正式车控适配器的当前证据输入；`ContentVehicleAdapter` 已进入施工副本并通过统一快照回流到 `ContentStore`，但研究探针和静态接入都不等于正式地图 APK 已完成 UI 闭环。车锁、充电、温度、档位、座椅和除霜等能力必须分别完成正式应用层的读取 / 订阅 / 命令 / 成功回流 / 失败回流 / 可逆恢复验证；车机离线期间未验证的能力保持不可用、占位或置灰。

页面层不能出现厂商属性编号、Binder 事务、权限判断或直接写值；这些内容只进入 Adapter / Port 和研究文档。

## 8. 施工不变量

1. 一个事实只有一个 owner；任何新增能力只能扩展 Registry、Store、Port / Adapter 或 Renderer 的既有边界。
2. 页面、控制模块和快捷功能使用稳定 ID；顺序、选中态和编辑态不由 View 层级隐式决定。
3. 内容层不得拥有第二套地图分屏几何；`SplitPanelController` 是地图物理位置唯一 owner。
4. Activity 重建、地图收放和页面重排不丢失地图导航状态、用户偏好或媒体状态。
5. 动态 View 创建、更新和销毁受生命周期控制；不得重复监听或持有失效 Context。
6. 证据不足时显示不可用 / 预览，不把静态字段、旧实验包或单次调用成功写成产品完成。

## 9. 施工与验证入口

新增文件、命名空间、框架绑定和结构性接入必须先给出物理锚点并完成最小编译检查；具体文件头和源码施工规则以根 `AGENTS.md` 为准。

当前验证项目统一见 [验证矩阵](../testing/验证矩阵.md)，不在本文件复制命令和逐项 smoke。车机能力的原始证据统一写入 [车机媒体能力研究](../research/车机媒体能力研究.md)；当前状态统一写入 `docs/progress.md`。
