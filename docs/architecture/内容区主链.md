# 内容区底层架构主链

> 状态：`v0.3`，依据 2026-09-25 用户确认更新；本版固化页面单页模型、控制区、Dock、单一沉浸式全屏、手势进度动画和设置项持久化主链。车内温度字段仍等待车控研究补充。
>
> 本文是 `03地图` 内容区的架构主链，不是 S191 魔改 APK 的复制说明，也不是当前源码施工清单。S191 只提供“同 APK 内集成、Activity 生命周期挂载、动态 View 宿主”的结构参考。

## 1. 架构结论

### 1.1 最终产品形态

`03地图` 仍然是以高德地图为宿主的单 APK。未来的 `03歌词` 和 `03投屏` 不以外部 APK、外部 Activity、悬浮窗或 WebView 的方式嵌入，而是：

1. 抽象出各自与界面无关的业务逻辑、状态模型和端口。
2. 在 `03地图` 工程内重新实现适配层和界面层。
3. 将实现打进同一个高德 APK，在地图 Activity 的内容层中运行。
4. 通过地图 Activity 生命周期完成挂载、恢复、暂停和销毁。

因此，产品运行时的结构是：

```text
一个 APK
└── 高德地图 Application / 地图 Activity
    ├── 高德地图原有地图链
    └── 03地图内容链
        ├── 顶栏
        ├── 内容页面
        ├── 控制区
        └── Dock 栏
```

### 1.2 明确不采用的路线

1. 不把 `03歌词` 或 `03投屏` 的 APK 直接嵌入高德。
2. 不把页面实现成多个独立 Activity，再通过窗口切换伪装成内容区。
3. 借鉴 S191 的动态 View 组织方式，但本项目保留自己的 Dock 栏；Dock 是快捷车控入口，不是 S191 的外挂式扩展栏。
4. 不复制 S191 的播放器、歌词、设置页、`DockLayoutBridge` 或多套宽度计算逻辑。
5. 不允许内容页面直接修改 `map_surface`、`ui_surface` 的宽度、边距或横向位置。
6. 不允许内容区形成第二套地图分屏几何主链。
7. 不采用“三个页面同时占一屏”的经典车机三段式卡片行为；页面采用类似 Android 手机的单页切换模型。

### 1.3 借鉴 S191 的三件事

只借鉴以下结构，不继承其具体实现：

1. **同 APK 内集成：** 新功能代码与高德代码处于同一个 APK 和同一个应用运行时内。
2. **Activity 生命周期挂载：** Application 层只负责注册生命周期桥接；真正的 View 在地图 Activity 可用时挂载，在 Activity 销毁时释放。
3. **动态 View 宿主：** 内容宿主和页面卡片由运行时创建、排列和更新；页面切换、顺序调整、临时浮层不依赖重新启动 Activity。

动态 View 采用“固定宿主层 + 动态业务节点”的方式：宿主层级稳定，页面卡片、控制卡片和快捷按钮由注册表与工厂创建，避免把所有界面逻辑堆进一个超大的动态构建类。

## 2. 当前确认的界面分层

### 2.1 目标层级

当前正式分屏的地图几何仍由现有 `SplitPanelController` 唯一负责。内容区只作为地图之下的全屏内容层存在，不拥有地图面板几何。

```text
地图 Activity 根内容
├── ContentHost（全屏内容层）
│   ├── TopBarLayer                 顶栏
│   ├── PagePagerLayer              内容页面
│   ├── ControlCarouselLayer        控制区
│   ├── DockLayer                   Dock 栏
│   └── TransientOverlayLayer       临时控件浮层
└── MapPanel（地图层，既有主链）
    ├── map_surface
    ├── ui_surface
    └── 手势条与提示层
```

`ContentHost` 的目标宿主锚点是正式布局 `res/layout/main_map_view.xml` 的根 `FrameLayout`；`map_surface` 与 `ui_surface` 仍属于地图层，不能被内容页面改造成业务 View 容器。

### 2.2 四个内容区域

#### A. 顶栏

顶栏是只读状态展示层，不承载车控业务写操作。当前确定展示：

1. 时间；默认显示 `HH:mm`，用户可以设置显示日期、星期和秒数；启用秒数后显示 `HH:mm:ss`。
2. 车内温度；产品目标已确定，应用层字段是否可读等待车控研究补充，未验证前以不可用状态呈现，不伪造数值。
3. 动力电池电量。
4. 是否连接充电 / 充电状态。
5. 后续确认后可增加其它静态数据或状态数据，但必须沿同一状态主链进入。

顶栏不自己轮询 Vehicle HAL、不自己读取 MediaSession、不自己写偏好。它只订阅归一化后的 `TopBarState`。

#### B. 内容区

内容区是类似 Android 手机的单页横向滑动区域；视口一次展示一个主页面，页面切换按单页卡片吸附，不采用三个页面同时占一屏的车机三段式结构。当前页面集合和默认顺序确定为：

1. **快捷功能页 `shortcuts`：** 本软件设置，以及未来加入的手套箱、灯光、雨刮器等快捷功能。
2. **车辆信息页 `vehicle_info`：** 胎压、里程、电耗等车辆信息。
3. **歌词页 `lyrics`：** 集成重写后的 `03歌词` 逻辑。
4. **投屏页 `projection`：** 集成重写后的 `03投屏` 逻辑。

默认页面顺序为：

```text
shortcuts → vehicle_info → lyrics → projection
```

默认主页为 `lyrics`。主页是用户进入内容区时首先展示的页面；页面顺序和主页选择均为应用级持久化设置。

内容页面具备以下共性：

1. 页面通过稳定 `pageId` 注册，不用页面在代码中的物理顺序作为身份。
2. 页面显示顺序由统一偏好状态保存，可调整。
3. 页面通过吸附式滑动切换，切换单位是一个页面卡片，不使用自由漂移的无主滚动，也不以“三卡同屏”作为布局目标。
4. 页面只接收归一化状态和用户意图，不直接访问车控、媒体或投屏底层接口。
5. 页面通过稳定能力声明决定是否支持沉浸式全屏；当前歌词页和投屏页支持，车辆信息页和快捷功能页不支持。
6. 当前页支持沉浸式全屏时，地图手势条可以驱动进入沉浸式全屏；当前页不支持时，手势条进入受阻拖拽模式。

#### C. 控制区

控制区是内容层中的可滑动控制卡片带，当前只保留两个控制模块：

1. 媒体控制。
2. 空调设置控制。

默认顺序为：

```text
media → climate
```

控制模块可以滑动切换，顺序可以调整。座椅不再属于控制区，座椅通风、座椅加热等快捷入口统一进入 Dock。控制卡片只能通过统一的车控 / 媒体命令端口发出操作意图，不能直接向车机底层写值。

#### D. Dock 栏

Dock 栏是快捷车控和系统入口的快速呈现，不是另一套业务主链。当前默认项目为：

1. 车锁 `lock`。
2. 座椅通风 `seat_ventilation`。
3. 座椅加热 `seat_heating`。
4. 方向盘加热 `steering_wheel_heating`。
5. 设置 `settings`。

Dock 项目使用稳定 `dockItemId` 注册，排序和显示状态由统一偏好状态保存。座椅相关能力的业务真值仍来自统一车辆状态适配器，Dock 只负责展示和发出命令。

快捷功能页和 Dock 共享同一份快捷功能定义、稳定 ID、可用状态和命令端口；快捷功能页提供完整编辑入口，Dock 提供高频快捷入口：

```text
ShortcutCatalog（唯一功能定义）
├── 快捷功能页渲染
└── Dock 栏渲染
```

Dock 或快捷功能按钮支持长按编辑：

```text
Dock / 快捷功能按钮长按
    ↓
发出 BeginShortcutEdit 意图
    ↓
切换到快捷功能页
    ↓
进入编辑态
```

Dock 不得单独维护一套功能清单，也不得通过复制按钮回调实现与快捷功能页的联动。

## 3. 地图收起、沉浸式全屏和进度动画

### 3.1 已确认的行为

1. 默认状态仍是内容区 `1/3`、地图区 `2/3`。
2. 页面是否能进入沉浸式全屏由当前页面的能力声明决定；全屏不是全局无条件能力。
3. 当前页支持沉浸式全屏时，手势条从默认进度 `0` 向右拖动，地图推出，当前页面进入该页的沉浸式全屏。
4. 当前页不支持沉浸式全屏时，手势条呈暗色 / 灰色不活跃状态；仍允许一小段弹性拖拽，松手后自动回弹到 `0`，不得切换页面状态或推出地图。
5. 全屏状态只有一种：当前页面的 `PAGE_IMMERSIVE`；页面仍采用单页吸附切换，不采用“三个页面占一屏”的卡片结构。
6. 地图重新展开等价于退出当前页面的沉浸式全屏，所有页面动画沿同一进度值反向播放。
7. 歌词页和投屏页的沉浸式入口不是常驻按钮；页面顶部交互显示临时控件浮层，浮层自动隐藏。
8. 进入沉浸式全屏后，控制区和 Dock 栏跟随同一进度动画隐藏；当前页面主体扩展到全屏，顶栏扩展到全屏。

### 3.2 单一沉浸式状态与能力门控

页面呈现状态只保留两个稳定模式：

```text
ContentPresentationState
├── SPLIT
└── PAGE_IMMERSIVE

ImmersiveInteractionPhase
├── IDLE
├── DRAGGING
├── ELASTIC_REBOUND
└── SETTLING
```

其中：

1. 当前页面注册表必须提供 `supportsImmersive` 能力字段；该字段是真值，不由手势条外观推断。
2. 当前页面支持全屏时，手势条进入活跃态；不支持时进入灰色 / 暗色受阻态。
3. `PAGE_IMMERSIVE` 只对当前页生效，当前已确认支持歌词页和投屏页。
4. 页面切换到不支持全屏的页面时，不能保留 `PAGE_IMMERSIVE`；应先按反向进度退出，再完成页面切换。
5. 手势条是唯一触摸入口；触摸事件只产生统一的 `presentationProgress`，不直接分别驱动地图、歌词、控制区或 Dock。
6. `ContentPresentationCoordinator` 是呈现状态和 `presentationProgress` 的唯一 owner；`SplitPanelController` 只负责把该进度转换为地图面板和两条 Surface 的物理几何，不保存第二份呈现状态。

### 3.3 归一化手势进度

```text
presentationProgress = 0
    = 分屏稳定态，地图完整可见

presentationProgress = 1
    = 当前页沉浸式全屏稳定态，地图完全推出

0 < presentationProgress < 1
    = 手势 / 吸附过程，不是新的稳定页面状态
```

`presentationProgress` 是内容区、地图面板、控制区、Dock 和当前页面 Renderer 共同消费的唯一动画真值。手势条从默认进度 `0` 拖到最右侧进度 `1`；所有布局尺寸、间距、透明度和位移都由该值实时派生。

### 3.4 两阶段动画合同

以歌词页为例，动画分为两个连续阶段；阶段边界固定为 `0.5`，但每个页面可提供自己的属性规格：

| 进度区间 | 页面主体 | 控制区 / Dock | 沉浸式专属内容 |
|---|---|---|---|
| `0.0 → 0.5` | 歌词主体跟随手势位移，并按页面规格调整可见区域 | 透明度从 `1` 线性降到 `0`，完成隐藏 | 保持隐藏 |
| `0.5 → 1.0` | 歌词字号、行距、间距和布局尺寸从分屏规格插值到全屏规格 | 保持隐藏 | 大专辑封面、全屏媒体控制栏透明度从 `0` 升到 `1` |

页面不得各自启动独立的进入 / 退出动画。页面 Renderer 只接收 `presentationProgress` 和本页的 `ImmersiveTransitionSpec`，计算当前帧的：

```text
translation
scale
alpha
spacing
size
visibility
```

反向拖动直接复用同一组插值函数，`presentationProgress: 1 → 0` 时所有属性倒向播放；不得为退出过程复制一套相反动画。

### 3.5 可全屏页与不可全屏页

可全屏页的手势链：

```text
当前页 supportsImmersive=true
    ↓
手势条活跃
    ↓
拖动改变 presentationProgress
    ↓
地图几何 + 当前页 + 控制区 + Dock 同帧更新
    ↓
松手后吸附到 0 或 1
```

不可全屏页的手势链：

```text
当前页 supportsImmersive=false
    ↓
手势条显示灰色 / 暗色
    ↓
拖动只进入受限弹性进度 0 → elasticLimit
    ↓
松手后弹簧回弹到 presentationProgress=0
```

受阻拖拽不得改变 `ContentPresentationState`，不得隐藏控制区 / Dock，不得改变当前页面，不得写入用户偏好。`elasticLimit` 是体验参数，初始值建议不超过归一化进度 `0.12`；它必须始终小于沉浸式吸附判定阈值 `0.5`。

### 3.6 退出规则

1. 在 `PAGE_IMMERSIVE` 中把地图拖回，统一将 `presentationProgress` 从 `1` 向 `0` 驱动。
2. 地图面板、歌词 / 投屏内容、媒体控制栏、控制区和 Dock 同时反向动画。
3. 进度回到 `0` 后，状态回到 `SPLIT`；不额外创建“退出全屏”页面状态。
4. 如果沉浸式页面切换到不支持沉浸式的页面，必须先执行上述反向动画，再提交页面切换。

## 4. 真值驱动的唯一主链

### 4.1 总体数据流

```text
系统 / 车机 / 媒体 / 03歌词 / 03投屏
                ↓
          Adapter / Port
                ↓
       归一化领域状态 Snapshot
                ↓
       StateStore + Reducer
                ↓
      Derived UI State / Layout Model
                ↓
        ContentHost 各层 Renderer
                ↓
             用户意图
                ↓
       Command Port / Effect Runner
                ↓
        Adapter 执行外部操作
```

所有 UI 都是状态的投影，不是状态的持有者。所有写操作都先变成意图，再经统一命令端口执行；外部系统是否成功，必须通过状态回流确认，不能在点击后直接把 UI 当成成功结果。

### 4.2 真值 owner 表

| 数据或行为 | 唯一真值 owner | 内容区使用方式 | 禁止做法 |
|---|---|---|---|
| 沉浸式手势进度、当前页面呈现模式 | `ContentPresentationCoordinator` → `presentationProgress` | 地图、当前页、控制区、Dock 和浮层消费同一个 `0..1` 进度 | 各页面或各控件分别启动进入 / 退出动画 |
| 地图面板物理位置、两条 Surface 几何 | `SplitPanelController` | 从 `presentationProgress` 派生面板位置并同步 `map_surface` / `ui_surface` | 页面自己改 `map_surface` / `ui_surface` 的 `LayoutParams` |
| 顶栏时间 | 系统时钟适配器 | 派生为 `TopBarState` | 顶栏内各控件分别创建定时器 |
| 车内温度、电量、充电状态 | 车辆状态适配器 → `VehicleStateStore` | 顶栏和车辆信息页订阅同一快照；车内温度未验证时显示不可用 | 顶栏和车辆信息页分别读取底层属性或伪造温度 |
| 胎压、里程、电耗 | 车辆状态适配器 → `VehicleStateStore` | 车辆信息页订阅 | 页面自行轮询或缓存另一份值 |
| 媒体标题、歌手、封面、播放状态、进度 | `MediaSessionAdapter` → `MediaStateStore` | 媒体控制和歌词页订阅 | 播放器 View 自己维护播放真值 |
| 歌词内容与时间轴 | 重写后的 `LyricsEngine` | 歌词页订阅 `LyricsState` | 歌词 View 自己请求网络、解析和校时 |
| 投屏连接和播放状态 | 重写后的 `ProjectionEngine` | 投屏页订阅 `ProjectionState` | 投屏页直接持有协议连接 |
| 页面顺序、主页、控制顺序、Dock 顺序和显示状态 | `ContentPreferenceStore` | 注册表按稳定 ID 派生排列；保存到应用级偏好 | 各页面直接写自己的 `SharedPreferences` |
| 当前页面、当前控制卡片、编辑态、全屏能力 | `ContentStateStore` | Renderer 根据状态更新 | 多个 View 各自保存当前选中项 |
| 顶部临时浮层显示与超时 | `InteractionStateStore` | 临时层订阅 | 页面内散落多个 `Handler` 和超时标志 |

### 4.3 状态与偏好分离

1. **运行时状态：** 车辆快照、媒体快照、歌词时间线、投屏会话、`presentationProgress`、当前页面和临时浮层。
2. **持久化偏好：** 页面排序、主页、控制模块排序、Dock 项目排序 / 显示状态、顶栏显示项、歌词样式和用户明确选择的布局偏好。
3. **派生状态：** 顶栏模型、页面可见宽度、当前页全屏能力、控制区 / Dock 透明度、歌词尺寸与间距、沉浸式专属媒体栏透明度。

运行时状态不能被当作偏好写入；派生状态不能反向成为第二份真值；页面切换不能修改底层车辆或媒体状态。

## 5. Activity 生命周期与动态 View 主链

### 5.1 物理锚点

当前可确认的宿主锚点为：

1. Application 入口：`source/amap-9.5.0.600013/smali/com/autonavi/amapauto/app/MapApplicationProxy.smali` 的 `onCreate()V`。
2. 地图 Activity：`source/amap-9.5.0.600013/smali/com/autonavi/amapauto/MainMapActivity.smali` 与 `source/amap-9.5.0.600013/smali/com/autonavi/auto/MainMapActivity.smali`；正式施工前必须根据 Manifest 和实际生命周期调用确认唯一 owner，禁止只按类名猜测。
3. 根布局：`source/amap-9.5.0.600013/res/layout/main_map_view.xml` 的根 `FrameLayout`。
4. 地图几何 owner：施工副本 `apk-work/9.5.0.600013/decode/smali/SplitPanelController.smali`；它是当前分屏手势和面板几何的唯一主链，不被内容区替代。

### 5.2 生命周期职责

```text
Application.onCreate
    ↓
注册 ContentLifecycleBridge（只注册，不创建 View）
    ↓
地图 Activity.onResume
    ↓
ContentRuntime.attach(activity)
    ↓
ContentHost 挂载到地图根内容层
    ↓
订阅 Store，创建 / 绑定动态页面与控制节点
```

离开页面时：

```text
Activity.onPause
    ↓
暂停页面动画、进度刷新和触摸交互
保留 Store 中的运行时状态

Activity.onDestroy
    ↓
ContentRuntime.detach(activity)
解除 View / Activity 引用
取消当前宿主订阅
不清除用户排序和业务状态
```

生命周期实现必须满足：

1. 同一个 Activity 实例只能挂载一个 `ContentHost`。
2. Activity 重建或再次进入时可以幂等恢复，不重复添加页面、控制卡片或临时浮层。
3. View 引用属于 Activity 生命周期；媒体、车辆和投屏适配器不能持有已销毁 Activity。
4. 数据订阅与 View 订阅分离，不能因为页面重建而注册多份底层监听。
5. 内容区退出时不得销毁地图状态，不得触发地图重新启动。

### 5.3 动态 View 的组织方式

不采用“一个类动态创建全部 UI”的写法，目标结构为：

```text
ContentRuntime
└── ContentHost
    ├── TopBarRenderer
    ├── PagePagerRenderer
    │   └── PageRegistry + PageFactory
    ├── ControlCarouselRenderer
    │   └── ControlRegistry + ControlFactory
    ├── DockRenderer
    │   └── ShortcutCatalog
    └── TransientOverlayRenderer
```

另设 `ContentPresentationCoordinator` 负责能力门控、手势阶段、`presentationProgress` 和吸附 / 回弹；`SplitPanelController` 只负责把同一进度转换为地图面板和两条 Surface 的物理几何。所有 Renderer 只负责把 `DerivedUiState` 映射为 View 属性和节点结构；业务数据获取、命令执行、排序持久化和生命周期不写进 Renderer。

## 6. `03歌词` 与 `03投屏` 的内部重写边界

### 6.1 `03歌词`

`03歌词` 只迁移可复用的业务逻辑，不迁移原项目的 APK 入口和页面宿主。目标内部链为：

```text
MediaStateStore
    ↓ MediaIdentity + PlaybackTimeline
LyricsEngine
    ├── 歌词来源适配
    ├── 内容解析
    ├── 歌曲匹配
    └── 时间轴同步
    ↓
LyricsState
    ↓
LyricsPageRenderer / LyricsView
```

歌词页面不得自己读取通知、自己枚举 MediaSession、自己发网络请求或自己管理全局定时器。媒体真值来自统一媒体主链，歌词只消费媒体身份和播放时间线。

### 6.2 `03投屏`

`03投屏` 只迁移可复用的投屏业务逻辑、状态模型和协议适配边界，在 `03地图` 内重写为 `ProjectionEngine`。目标内部链为：

```text
ProjectionPage 用户意图
    ↓
ProjectionCommand
    ↓
ProjectionEngine / ProtocolAdapter
    ↓
ProjectionState
    ↓
ProjectionPageRenderer
```

投屏页必须覆盖 `03投屏` 已实现的全部业务能力，但不直接持有协议连接、不直接修改地图窗口、不直接控制全屏几何。需要进入沉浸式全屏时，只发出统一的布局意图，由内容呈现主链完成地图推出。

### 6.3 两个集成能力的共同约束

1. 两者都以内部业务模块存在，不以外部 APK 存在。
2. 两者的核心逻辑不依赖高德具体 View 层级。
3. 两者都必须能在无 Activity View 的情况下维护或暂停必要状态，并在 Activity 恢复时重新绑定 Renderer。
4. 两者都只能通过公开的项目端口进入媒体、地图布局和车机能力，不把第三方实现细节扩散到页面层。

## 7. 车控与媒体能力接入边界

### 7.1 当前纳入的能力集合

| 能力域 | 当前产品位置 | 状态模型 |
|---|---|---|
| 空调 | 控制区空调卡片 | 温度、风量、模式、开关及可用状态；具体字段按已验证车机能力接入 |
| 座椅 | Dock 栏、快捷功能页 | 座椅通风、座椅加热及后续已验证能力的状态；具体字段按车控适配器接入 |
| 媒体 | 控制区媒体卡片、歌词页 | 当前来源、标题、歌手、封面、播放状态、进度、可用控制 |
| 电量与充电 | 顶栏、车辆信息页 | 电量、连接状态、充电状态、可用的电压 / 电流 / 剩余时间 / 功率派生值 |
| 其它车控 | 快捷功能页和 Dock 栏 | 以稳定功能 ID 注册，未确认的功能不提前写入 UI 真值 |

### 7.2 车控状态的统一表达

所有车控数据必须带可用性边界，至少能够表达：

```text
AVAILABLE
UNAVAILABLE
STALE
PERMISSION_REQUIRED
EXECUTING
FAILED
```

车控按钮的视觉结果必须由状态回流确认。点击“开启空调”后不能只因为点击事件完成，就直接把开关画成开启；必须等待适配器返回成功状态或明确的失败 / 不可用状态。

### 7.3 现有研究事实的使用边界

1. 媒体读取、媒体切源和标准媒体控制沿 `docs/research/车机媒体能力研究.md` 的已验证路径进入，不在内容页内重新探测。
2. 电量、充电连接和充电状态使用研究文档中已确认的 Vehicle HAL 事实；普通第三方应用层权限仍由正式施工验证闭环，不把系统层快照直接等同于应用层必然可读。
3. 空调、座椅和其它车控的字段、命令与权限必须经过对应适配器验证后进入页面或 Dock；页面层只依赖统一接口，不直接依赖厂商属性编号。
4. 不连接 CAN、不调用未授权的车厂私有接口，不把 ADB、root 或无障碍作为正式运行依赖。

## 8. 统一注册与排序模型

### 8.1 页面注册表

内容页使用稳定 ID 和工厂注册：

```text
PageRegistry
├── shortcuts
├── vehicle_info
├── lyrics
└── projection
```

默认显示顺序是 `shortcuts → vehicle_info → lyrics → projection`，运行时显示顺序由 `ContentPreferenceStore.pageOrder` 派生；默认主页为 `lyrics`。页面对象本身不能通过数组下标代表身份，也不能在多个页面类里分别保存顺序。

### 8.2 控制模块注册表

```text
ControlRegistry
├── media
└── climate
```

控制区只注册媒体和空调。座椅通风、座椅加热等快捷车控进入 `ShortcutCatalog`，不再作为控制区模块注册。后续控制模块通过新增稳定 ID 注册，不通过在顶层布局中继续堆叠 `if / else`；排序由 `ContentPreferenceStore.controlOrder` 统一保存。

### 8.3 快捷功能目录

```text
ShortcutCatalog
├── lock
├── seat_ventilation
├── seat_heating
├── steering_wheel_heating
├── settings
├── glovebox       （后续确认后加入）
├── lights         （后续确认后加入）
└── wipers         （后续确认后加入）
```

默认 Dock 顺序为 `lock → seat_ventilation → seat_heating → steering_wheel_heating → settings`。快捷功能页和 Dock 栏都从 `ShortcutCatalog` 读取同一对象，只有展示密度、布局宽度和入口行为不同。

## 9. 绝对不变量

1. `ContentPresentationCoordinator` 是当前页面呈现模式、沉浸式能力门控、手势阶段和 `presentationProgress` 的唯一 owner；`SplitPanelController` 是地图展开、收起、拖动、比例和面板位置的唯一 owner。
2. `ContentHost` 是内容区的唯一宿主；页面、控制卡片和快捷按钮不得跨 Activity 自行挂载。
3. 每个业务事实只有一个真值来源；UI 只消费状态，不把显示值当作业务真值。
4. 页面、控制模块和快捷功能使用稳定 ID；顺序、选中态和编辑态不由 View 层级隐式决定。
5. 媒体、歌词、投屏和车控通过端口 / 适配器进入，不把外部协议、权限和厂商字段写进 Renderer。
6. 沉浸式全屏是统一布局状态，不是歌词页或投屏页各自实现的一套全屏逻辑。
7. 临时控件浮层是交互状态，不是常驻页面按钮，也不是新的页面。
8. 地图收放、Activity 重建和页面重排不能丢失地图导航状态、用户排序或媒体状态。
9. 动态 View 的创建、更新和销毁必须受生命周期控制，不能重复注册监听或持有失效 Activity。
10. 新增车控、页面或投屏能力只能扩展注册表和适配器边界，不能扩展第二套主链。

## 10. 施工前物理边界

本文目前只确定架构角色和主链，不提前虚构新包名、中文命名空间、文件头或具体 Smali 文件。正式施工前必须补齐：

1. `MapApplicationProxy.onCreate()` 到内容生命周期桥接的唯一接入语句。
2. `MainMapActivity` 的真实生命周期 owner 和根布局设置入口。
3. `main_map_view.xml` 根 `FrameLayout` 中 `ContentHost` 与既有 `panelHost` / `map_surface` / `ui_surface` 的实际层级。
4. `ContentRuntime`、`ContentStateStore`、各 Adapter、Registry 和 Renderer 的正式包路径、文件头来源和项目包含关系。
5. 每完成一个新增文件或结构性接入，都先做命名空间、类型归属、项目包含关系和最小编译检查。

未完成以上物理锚定前，不得直接把 S191 的 `smali_classes2` 目录、类名或动态 UI 大方法复制进正式源码。

## 11. 最小验证闭环

后续施工必须至少覆盖以下验证：

1. **生命周期：** 冷启动、Activity 恢复、暂停、销毁、再次进入；确认 `ContentHost` 只存在一份，监听不重复注册。
2. **默认布局：** 内容区 `1/3`、地图区 `2/3`，两条地图 Surface 和内容层保持既有几何主链。
3. **地图收放：** 地图收起后内容区扩展，地图重新展开后内容页面、地图状态和导航状态保持。
4. **页面滑动：** 页面按卡片吸附，顺序调整后重启仍保持；不得出现自由漂移或重复页面。
5. **控制区：** 媒体、空调卡片切换和排序生效；成功、失败、不可用状态均有对应 UI，座椅不再作为控制区模块。
6. **Dock：** 快捷功能页和 Dock 栏使用同一清单；长按 Dock 快捷按钮进入快捷功能页编辑态。
7. **顶栏：** 时间、温度、电量和充电状态从统一状态更新，不产生多个定时器或多个数据源。
8. **歌词：** 媒体切换、播放 / 暂停、进度变化后，歌词内容与时间轴正确恢复。
9. **投屏：** 连接、断开、失败和恢复状态可观测；投屏页不直接破坏地图布局。
10. **沉浸式：** 歌词 / 投屏页面顶部触发临时控件浮层，按钮自动隐藏；进入沉浸式后地图推出，地图重新展开后沉浸式自动退出。
11. **地图视角：** 2D 车首、2D 北上、3D 车首在内容层变化后仍通过既有地图视口链验收。

所有标记为必须通过的验证项，任意一项失败都代表内容区主链未达标。

## 12. 施工前待验证证据

以下项目不是产品语义待定，而是进入施工前必须补齐的外部能力证据。证据不足时，界面只能展示不可用 / 未验证状态，不能伪造成功：

1. **车内温度：** 确认字段来源、应用层权限、更新频率和断链时的不可用表现；不得用车外温度替代。
2. **空调、座椅与其它车控：** 按研究文档逐项验证读取、命令、成功回流、失败回流和权限边界；当前先按全量范围设计，验证不可用后再删减。
3. **03投屏：** 形成已实现能力清单，逐项映射到 `ProjectionCommand`、`ProjectionState` 和页面入口，确认全部能力都能在本项目内重写适配。
4. **沉浸式视觉参数：** 在真实内容区尺寸上确定歌词字号、行距、封面、媒体栏、Dock / 控制区透明度和插值规格；不得改变统一 `presentationProgress` 主链。
