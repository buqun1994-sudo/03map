# 内容区底层架构主链

> **职责：** 定义内容区的分层、状态流、唯一 owner、生命周期和适配边界。产品行为见 [产品需求基线](../product/产品需求基线.md)，用户偏好见 [设置项清单](../product/设置项清单.md)，源码锚点见 [主链索引](../code-map/主链索引.md)。
>
> **当前状态：** 首轮内容结构和双主题页面已迁入正式 Compose 源码；`ContentRegistry`、`ContentStore`、`ContentRuntime`、`ContentComposeHost`、`ContentBinding` 与车辆／媒体适配器构成当前唯一主链。`ContentRenderer` 仅保留为历史实现记录，不是当前歌词、媒体封面或氛围背景 owner。Java/Kotlin、资源、签名包及本机宿主可验证；正式 APK 的车机首帧、权限、服务可达性、真实主题和状态回流仍待实机确认。历史 `480×480` 悬浮链和 S191 只作为参考。

## 1. 运行形态与边界

`03地图` 是以高德地图为宿主的单 APK。内容区不嵌入外部 APK、Activity、WebView 或独立悬浮窗，而是在地图 Activity 的内容层中运行：

```text
一个 APK
└── 高德 Application / 地图 Activity
    ├── 高德地图链
    └── 03地图内容链
        ├── MediaAmbientBackgroundRenderer
        ├── 顶栏
        ├── 页面
        ├── 控制区
        ├── Dock
        └── 临时浮层
```

`MediaAmbientBackgroundRenderer` 是架构上的全局背景职责，物理实现为 `ContentBinding` 的唯一 `ambientArtwork` 加 `MediaAmbientBackground`；它位于顶栏、页面、控制区和 Dock 之下。它只消费真实媒体快照中的封面；`ContentBinding` 在后台按媒体身份与位图 generation 去重生成小型柔化色场，UI在Android 9兼容的Canvas网格上缓慢流动，暂停／无封面立即隐藏，销毁时取消任务和释放自有缓存，页面切换不重算。内容区只负责内容层；地图面板的宽度、位置、两条 Surface 和 native 布局仍由既有地图主链及 `SplitPanelController` 负责。页面不得直接修改 `map_surface`、`ui_surface` 或地图 Activity 的分屏几何。

允许借鉴 S191 的只有三点：同 APK 集成、Activity 生命周期挂载、动态 View 宿主。不得复制其播放器、插件主链、第二套宽度计算、`300dp` 默认值、密度策略或无法归因的 native / 资源差异。

## 2. 内容层级

```text
地图 Activity 根布局
├── ContentHost（全屏内容层）
│   ├── MediaAmbientBackgroundRenderer
│   ├── TopBarRenderer
│   ├── PagePagerRenderer
│   ├── ControlCarouselRenderer
│   ├── DockRenderer
│   └── TransientOverlayRenderer
└── MapPanel（既有地图层）
    ├── map_surface
    ├── ui_surface

```

正式布局锚点是 `res/layout/main_map_view.xml` 根 `FrameLayout`。内容层可以覆盖在地图层之上，但不能把两条地图 Surface 改造成业务容器。

## 3. 注册表与首轮内容

### 3.1 页面

页面以稳定 `pageId` 注册，物理数组顺序不作为身份：

```text
PageRegistry
├── shortcuts       可见
├── vehicle_info    已注册，首轮隐藏
├── lyrics          可见，直接投影透明壁纸歌词视窗；03歌词解析／缓存核心经ContentLyricsEngine接入，仍由ContentStore唯一拥有状态
└── projection      已注册，首轮隐藏
```

首轮派生顺序为 `shortcuts → lyrics`，默认主页为 `lyrics`。页面通过能力声明决定是否支持沉浸式状态；快捷功能页不支持，歌词页支持，投屏页预注册但未展示。

### 3.2 控制区

```text
ControlRegistry
├── media
└── climate
```

默认顺序为 `media → climate`。座椅通风、座椅加热和座椅按摩属于快捷功能，不注册为控制区模块。

### 3.3 Dock 与快捷功能

```text
ShortcutCatalog
├── lock             固定在左侧
├── shortcuts        右侧槽位默认项
├── seat_ventilation 右侧槽位默认项
├── seat_heating     右侧槽位默认项
├── seat_massage     右侧槽位默认项
└── settings         右侧槽位默认项
```

Dock 是“固定车锁 + 五个可替换槽位”。Dock 与快捷功能页共享同一 `ShortcutCatalog`、状态和命令端口；当前版本明确禁用 Dock／快捷项长按弹出列表，后续编辑模式必须复用同一清单和热区，不得重新引入临时替换菜单。

### 3.4 顶栏

顶栏当前由 `content-compose/ui/com/icar03/content/ui/ContentPanel.kt` 的 `PrototypeTopBar()`／`TopBarText()` 呈现，数据来自 `ContentUiMapper.map()` 投影的 `ContentUiState`；`ContentRenderer` 的旧 `buildTopBar()`／`renderTopBar()` 只保留历史记录。主题由 `ContentTheme` 持有，时间、温度、里程、充电和媒体状态均来自 `ContentStore` 派生状态；UI 不轮询 Vehicle HAL、读取 MediaSession 或计算车辆功率。普通文字与原厂来源资源继续使用正式 APK 已登记资源；页面、状态、按压和弹层动画由 Compose 生命周期控制，暂停／销毁取消回调和动画。

## 4. 呈现状态与地图几何

### 4.1 稳定状态

```text
ContentPresentationState
├── SPLIT
└── PAGE_IMMERSIVE

ImmersiveInteractionPhase
├── IDLE
├── DRAGGING
├── ELASTIC_REBOUND
└── SETTLING
```

`PAGE_IMMERSIVE` 只对当前页面生效。切换到不支持沉浸式的页面前，必须先回到 `SPLIT`；地图重新展开也等价于退出沉浸式状态。

### 4.2 唯一动画真值

```text
presentationProgress = 0
  分屏稳定态，地图完整可见

presentationProgress = 1
  当前页面沉浸式稳定态，地图完全推出

0 < presentationProgress < 1
  拖动或吸附过程，不是新的稳定页面状态
```

当前实现不另建第二套呈现协调器：`SplitPanelController` 的 `applyDividerX(F)` 是呈现进度、吸附动画和地图物理几何的唯一 owner；`ContentRuntime.onDividerChanged(...)` 只转发同一份进度给内容层，`ContentRenderer` 不反向改写地图尺寸。

内容区内部的两页／两控制卡只由各自 `ContentPager` 在裁剪 viewport 内切换，步长等于实际 viewport 宽，稳定态邻项外露 `0px`；`220ms` 吸附不改地图进度，也不需要可见页码圆点。快捷页四项为圆角方形多状态按钮，图标在上、文字在下；设置作为与 Dock 共享的快捷项保留，未就绪时只在点击反馈中提示，不铺设额外横条；按摩／通风／加热仍通过车控 Store 和 VehiclePort，连续点击以 pending 档位为下一次计算基准，命令发送不等待回读，回读仅用于确认、失败和日志；按摩开关使用 `0x241=2/1`，开启时确认开关、模式和初始强度有效后再写 `0x243=1/2/3`，真实车机强度闭环仍单独标待验证。亮度与媒体音量纵向滑条经独立系统端口读取和在权限允许时写入，不触发车控命令。滑条文案位于图标下方，百分比填充从底部连续计算到顶部，不让文字占用可拖动轨道。`ContentRuntime.contentContext(Context)` 只为左侧 View 创建系统密度配置，原 Activity 的高德 125% 密度与地图 Surface 不改；主题不持久化、不读取系统 `uiMode`：`readInitialAmapTheme()` 直接读取高德 `GAdaAndroid.nativeIsNightMode()`，`onAmapThemeChanged(I)` 直接接收高德日夜回调并更新 `ContentStore`，attach／resume 只重新读取该高德真值。设置入口只留 Dock 图标及触发后的不可用反馈，不把横向设置提示卡放进快捷页。空调未接通时只在对应控制卡内说明。媒体卡由原有两排改为封面／曲目信息／播放与下一首／来源在同一横向底座；媒体来源常态无背景，打开的选择浮窗按 `边距×2 + 热区×4 + 间距×3` 计算高度、`边距×2 + 热区` 计算宽度，每项为固定 `88×88px` 正方形热区、间隔 `12px`、边距 `6px`，图标与文字在热区内居中；Dock 保留固定锁与五槽，当前版本禁用长按替换菜单，名称保留在可访问描述中，宽度不足时自身横向滚动，不减少热区。媒体播放、下一首、来源、快捷卡和 Dock 共用 `bindPressEffect()` 与 `PRESS_CORNER_PX=24` 的高圆角矩形按压令牌，按下才显示背景，不使用圆形按压面；36px 图标的媒体／来源／Dock 按压背景固定为 72px 容器，不缩小触摸热区。`ContentRenderer` 的外观角色应区分浅灰／白色填充、选中底、柔和阴影与局部分隔线，不复用全局 `1dp` 描边；这属于呈现层，不改变 `ContentPager`、Store、端口和地图几何的 owner。

深色主题的呈现令牌固定为背景 `#0F0F0F`、普通表面 `#1A1A1A`、提升层 `#232323`、选中层 `#2D2D2D`、按下层 `#414141`；颜色只由 `ContentTheme` 持有，Renderer 不得散写深色常量。

不可沉浸页面允许受限弹性拖动，初始 `elasticLimit <= 0.12`，且必须小于沉浸式吸附阈值 `0.5`。受阻拖动不得改变页面、偏好、控制区或 Dock 状态。

### 4.3 渐进派生

Renderer 只接收 `DerivedUiState`、`presentationProgress` 和本页 `ImmersiveTransitionSpec`，派生位移、尺寸、透明度、间距和显隐；不得分别启动进入 / 退出动画。动画反向直接复用同一插值函数，不复制第二套退出逻辑。

## 5. 唯一数据流

```text
系统 / 车机 / 媒体 / 歌词 / 投屏
              ↓
        Port / Adapter
              ↓
      归一化 Snapshot
              ↓
       ContentStore / Reducer
              ↓
       DerivedUiState
              ↓
         Renderer / View
              ↓ 用户意图
      Command Port / Effect
              ↓
        Adapter 执行与回流
```

所有 UI 是状态投影，不持有业务真值。点击成功不能直接等同于业务成功，必须等待外部状态回流。

| 事实 / 行为 | 唯一 owner | 页面使用方式 |
|---|---|---|
| 呈现模式、进度、吸附 / 回弹 | `SplitPanelController.applyDividerX(F)` | 地图几何和内容宿主消费同一份进度，不创建第二份动画真值 |
| 地图面板、两条 Surface 几何 | `SplitPanelController` | 从进度派生，不由页面改写 |
| 主题 | 高德主题回调 → 内容主题状态 | 不读取系统 `uiMode` |
| 时间 | 系统时钟适配器 | 统一派生 `TopBarState` |
| 车辆状态 | `VehicleAdapter` → `VehicleStateStore` | 顶栏、车辆页和快捷入口订阅同一快照 |
| 媒体状态 | `MediaSessionAdapter` → `MediaStateStore` | 媒体卡片、歌词页和 `MediaAmbientBackgroundRenderer` 订阅同一快照 |
| 媒体氛围背景 | `MediaSnapshot` / 专辑封面 → `MediaAmbientBackgroundRenderer` | 播放中覆盖整个内容板块；停止或无封面时回退主题背景 |
| 歌词 | `LyricsEngine` | 只消费媒体身份和时间线 |
| 投屏 | `ProjectionEngine` | 通过命令 / 状态模型接入 |
| 排序和显示偏好 | `ContentPreferenceStore` | 只保存稳定 ID 和用户设置 |
| 页面 / 控制 / Dock 当前选择 | `ContentStateStore` | Renderer 只消费状态 |
| 临时浮层 | `InteractionStateStore` | 统一超时和显隐 |

运行时状态、持久化偏好和派生状态必须分离；派生值不能反向成为第二真值。

## 6. 生命周期与物理锚点

### 6.1 锚点

1. Application：`source/amap-9.5.0.600013/smali/com/autonavi/amapauto/app/MapApplicationProxy.smali` 的 `onCreate()V`。
2. 地图 Activity：`MainMapActivity` 相关 Manifest / 生命周期链；施工前必须以 Manifest 和调用证据确认唯一 owner，不能只按类名判断。
3. 根布局：`source/amap-9.5.0.600013/res/layout/main_map_view.xml` 的根 `FrameLayout`。
4. 地图几何：正式源码 `source/amap-9.5.0.600013/smali/SplitPanelController.smali`。
5. 首轮内容入口：正式源码 `source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/` 下的 `ContentRegistry`、`ContentRuntime`、`ContentStore`，以及 `content-compose/{host,runtime,ui}` 下的 `ContentComposeHost`、`ContentBinding`、`ContentPanel`。

### 6.2 生命周期合同

```text
kc.v() 内容根 View 就绪
  → ContentRuntime.attach(rootView)
  → 幂等挂载唯一 ContentComposeHost，绑定 Store / ContentBinding
Activity.onPause
  → kc.onPause → ContentRuntime.onHostPaused → ContentBinding.stop
  → 暂停歌词解析、氛围生成、页面动画和封面任务，保留 Store 状态
Activity.onResume
  → kc.onResume → ContentRuntime.onHostResumed → ContentBinding.start
  → 当前状态对齐并恢复可见层，不重播已完成的历史转场
Activity.onDestroy
  → ContentRuntime.detach(activity)
  → ContentComposeHost.destroy → 解除 Activity / View 引用和宿主订阅
```

必须满足：同一 Activity 只有一个 `ContentHost`；重建不重复注册；适配器不持有失效 Activity；页面重建不重复注册底层监听；内容区生命周期不重启地图。

图标的物理 owner 是 `ContentIconView`：原厂同包资源封装在 `res/drawable/content_oem_*` 与 `assets/content-oem/`；资源来源、版本、APK 内原路径和原始／包内 SHA-256 在 `assets/content-oem/asset-manifest.json`。静态 Vector 是稳定帧；通过兼容试验的七份 Lottie 在按钮点击产生的目标图标变化时即可单次播放，不再等待服务返回，仍基于 `isShown`、窗口焦点、当前页卡和 Activity 生命周期停播。通风／加热的 AE 效果和预合成部分未获播放器完整支持，按摩颜色变体无可证档位映射，三者仅使用原厂日／夜四态静态 Vector，不能宣称这三类动态图标已复用或说成 native 可调用文件。跨包直接挂载的 A 类资源目前为零项；原厂完整控件是 C 类视觉参考。

字体与动效的物理 owner 由当前 Compose 内容层承担：系统 `LocalDensity` 只影响内容子树，原厂资源仍由正式 `res/drawable`／`assets/content-oem` 提供；不存在网页字体、WebView 或外部图标库运行依赖。页面吸附、歌词换句和媒体氛围网格使用重量缓动并在 `pause()`／`destroy()` 取消；真实媒体封面氛围背景由唯一 `ContentBinding.ambientArtwork` 与 `MediaAmbientBackground` 承载。

## 7. 能力适配边界

### 7.1 媒体、歌词、投屏

- 媒体读取、来源切换和标准控制沿 [车机媒体能力研究](../research/车机媒体能力研究.md) 的已验证路径接入。
- 歌词解析、候选准入、缓存和时间轴由 `ContentLyricsEngine` 在 `ContentStore` 的唯一 `LyricsPort` 边界内完成；页面不读取通知、不枚举 MediaSession、不发网络请求、不管理全局定时器。Engine 发布不可变整曲行，`ContentStore` 按可信时间线调度当前句。
- 投屏只迁移业务逻辑、状态模型和协议适配边界；页面不直接持有协议连接、不修改地图几何。

### 7.2 车辆与车控

车控状态至少能表达：

```text
AVAILABLE / UNAVAILABLE / STALE / PERMISSION_REQUIRED
EXECUTING / FAILED
```

研究文档是正式车控适配器的证据输入；本轮 `ContentVehicleAdapter` 已在正式源码中按探针验证的原厂 Binder 契约重写，绑定 / 描述符核对、后台轮询和单目标命令仍经 `ContentPorts.VehiclePort`、`ContentStore` 统一回流，页面不直连服务。Store 对写命令保持待确认态，只由后续真实快照确认成功；待确认目标只供图标预反馈，失败、断连和超时恢复实际图标并提示，不把预反馈当成功。充电对 `0/0/0` 标未插枪；连接 `1` 显示已插枪，只有 BMS `3` 标充电中、`6` 加预约 `1` 标预约等待；连接 `2` 仅在 BMS `3` 时按已记录的充电样本显示充电中，其余未知。未确认的插枪状态不猜充电功率、剩余时间。仅在三项原始字段变化时记录最小充电原始值，供目标车机只读诊断。按摩按用户选择支持关闭与三 / 二 / 一档：关闭只写开关，开启时确认 `0x241=2`、模式 `0x245` 在 `1–5` 且强度 `0x243` 在 `1–3` 后，再写用户选择的 `0x243=1/2/3`；读取开关、模式和强度，但不会因关闭后的模式记忆差异自动回写模式或强度。强度值与原车界面、厂商源码和映射相符，但第三方探针尚未独立写过强度；因此本地 Binder 顺序探针只证明发送顺序，不证明真实车机 UI 闭环。研究探针和本地静态 / 构建证据都不等于正式地图 APK 已完成车机 UI 闭环；车锁、充电、温度、座椅等能力仍需逐项补正式应用层读取、状态变化、命令、结果回流及可逆恢复运行证据。档位与除霜不是本轮对用户暴露的控制能力。应用不再在`queueCommand()`读取档位／车速并自加P／零速拒绝，原车系统仍是驾驶条件限制owner；Binder身份、连接、权限失败、单目标待确认、回读和6秒超时边界保持。

页面层不能出现厂商属性编号、Binder 事务、权限判断或直接写值；这些内容只进入 Adapter / Port 和研究文档。

## 8. 施工不变量

1. 一个事实只有一个 owner；任何新增能力只能扩展 Registry、Store、Port / Adapter、ContentBinding 或 Compose UI 的既有边界。
2. 页面、控制模块和快捷功能使用稳定 ID；顺序、选中态和编辑态不由 View 层级隐式决定。
3. 内容层不得拥有第二套地图分屏几何；`SplitPanelController` 是地图物理位置唯一 owner。
4. Activity 重建、地图收放和页面重排不丢失地图导航状态、用户偏好或媒体状态。
5. 动态 View 创建、更新和销毁受生命周期控制；不得重复监听或持有失效 Context。
6. 证据不足时显示不可用 / 预览，不把静态字段、旧实验包或单次调用成功写成产品完成。

## 9. 施工与验证入口

## 10. Compose 第二层消费边界

`ui-preview/content-runtime/` 是新呈现层与已有正式业务层之间的接入库，不建立新的 Store 或 Adapter。`ContentUiMapper.map()` 将 `ContentState`、真实系统快照和 Port 能力投影为纯 `ContentUiState`；`ContentBinding.dispatch()` 把稳定用户意图送回已有 Store／SystemPort；`BoundContentPanel()` 只负责宿主生命周期订阅，并把真实封面与自有氛围背景交给内容UI slot呈现。

第一层默认示例字段不进入真实模式：真实投影关闭预览开关，按各字段有效性显示未知；车辆目标只来自 Store 待确认，媒体播放目标只来自 Store，来源没有第二套模拟成功状态。真实模式四控制与 Dock 共用控制状态，系统滑条拖动草稿在提交／取消后撤销，媒体播放、下一首和来源服务分别门禁。歌词页与快捷页经 Compose Pager 切换；歌词页只消费 `ContentUiMapper` 投影的整曲歌词和当前句索引，网络解析、缓存、时间线和封面回退留在 `ContentLyricsEngine`／`ContentStore`。

Store 生命周期由调用方拥有，默认 Shared 解绑不销毁；Owned 只用于移交唯一生命周期，不能在同一 Store 上动态切换 ownership，Binding 不得活得比 Store 更久。停止时解除监听、取消时钟／系统回读和自有媒体处理；过期后台回调不得污染新的生命周期。高德主题、地图收放和几何仍由既有宿主提供，本轮不把 Compose 注入高德 APK。

最小 Java 编译闭包通过 Gradle 白名单直接引用正式八类源码；默认 Store 构造仍创建相同真实适配器，注入构造用于已有宿主提供端口和本机测试。来源可用性由既有媒体服务可达性声明，不与 MediaSession 可用性混用；系统可写能力包括权限门禁，不以可读宣称可写。库 Manifest 与运行／测试边界见 [模块入口](../../ui-preview/content-runtime/README.md)，第二层证据见 [第二层验证记录](../testing/Compose第二层能力接入验证记录.md)。

## Compose 实车反馈与来源回读

当前可见行为以产品基线为准，旧Renderer的顶栏居中、无km、Dock菜单和统一座椅滤色只作历史记录。正式UI的`ShortcutId`共用六项清单，只有既有`ControlId`进入车控，方向盘加热不新增事件、属性、读写或真实状态。原厂通风开启Vector为单色，既有六份`_color_day/night`派生保留。当前`OemIcon.kt`的`oemLayerColors()`在呈现层按已登记Vector路径顺序只改指定fill：座椅开启轮廓跟随功能色，电池外框基础色／内部绿色；原路径、变换、裁剪、档位透明度、描边与资源哈希全部保留，原资源不重写。车锁只对解锁投影蓝色和选中背景，失败回弹仍由Store决定。Dock与快捷页共享Material3触点Ripple；同一`MutableInteractionSource`也驱动`OemIcon`微动。仅车锁整槽选中，其余Dock选中局部矩形与媒体按下区域同构；媒体背景固定RGB只动画alpha，无第二层Ripple。按钮音效集中在已接受事件边界经`playClickSound()`调用高德`playSystemClick()`，失败回退系统View音效，一次点击不双响，程序快照与页面settled不发声。原厂Lottie6.6.7和Okio1.17.6按既有版本／SHA纳入Compose锁，不复用旧Renderer／IconView、不引入AppCompat。图标消费集中于同目录`OemIcon.kt`，`ShortcutOemIcon()`仅从同一`ControlState.displayed/known`投影座椅主题、档位区间与路径调色，供网格和Dock共享；媒体来源共用`animationFor()`。局部呈现键、按压计数和播放进度不进入Store，也不确认命令。`OemFrame`只保留实际已绘制的资源／调色／composition配方，新资源异步解析期间继续展示上一帧，解析就绪后以进度0原子切入，失败回目标Vector；不提前画目标静态再倒回动画首帧。每次从对应起点正向播放一次，结束保留同一Drawable末帧；下一次明确触发才seek起点，时钟、同值快照和松手不重播。生命周期暂停／失焦／离屏取消并消费当前键，恢复稳定Vector而不补播，异步监听dispose移除；没有原厂动效的资源仅做既有微动。爱趣听恢复原厂简笔Vector；浅色配色恢复、深色填充契约由产品基线定义，右边界仍对齐viewport。原始JSON与哈希保留，媒体圆底隐藏和符号画布归一仅为登记的消费者呈现适配。

来源命令与来源实际状态分开：`ContentStore`拥有唯一待确认来源，`ContentUiMapper`投影`targetSource`；命令发送成功不更新actual，失败／超时恢复actual并反馈。`ContentMediaAdapter`保留既有显式切源Intent，新增原厂`PlayControlCheryAction`的只读Binder状态订阅／读取，通知只触发重新读取；内部来源值不复用外部`audio_source`命令值。已证实映射与未知值分别处理，未确认的爱趣听内部枚举不猜。

标准MediaSession仅凭`com.tencent.wecarflow`包名不能区分爱趣听／网易云。已可靠回读的来源优先于包名，切换后与实际来源不匹配的旧会话不能贡献播放能力、元数据或封面。Binder读取在独立工作线程，发布回主线程，stop解除订阅／绑定并取消任务，epoch隔离过期回调，不依赖ADB／root／跨包私有View。正式与接入库已有限queries声明该包，不扩大权限。SDK静态契约及本机替身测试不冒充本车普通UID绑定成功；新包来源变化、断连与真实播放能力须现场核实。

## 11. Compose 第三层宿主

正式Kotlin已迁入 `source/amap-9.5.0.600013/content-compose/{ui,runtime,host}/`，`:content-ui`／`:content-runtime`／`:map-host`直接编译这些入口；预览Controller仍只属于独立`:app`。`ContentRuntime`保留原静态签名与唯一Store，挂载 `ContentComposeHost` 后不再创建旧Java Renderer。旧Renderer源码仅历史参考，不打进第三层内容DEX。

`kc.v()`→`ContentRuntime.attach()`→内容子树独立owner→`BoundBindingPanel`；主题初值UNKNOWN=-1，未解析前仅保存弱引用root，不创建默认浅色Store／宿主；高德native明确夜间或mode1/2回调决定初始主题。native false包含未就绪，unknown经原有`nativeRequestDayNightMode(-1)`请求，`AndroidProtocolExe.sendAutoStatus(II)`状态1补ready请求；回调取得结果后原位attach，pending后台暂停等待owner恢复、detach清待挂载root。pause使Lifecycle降至CREATED，解除Binding、撤销来源菜单、停止内容时钟；resume保留已解析的高德主题，不由生命周期查询覆盖可靠回调；detach销毁Composition／ViewModelStore，再由Runtime销毁唯一Store及Adapter。绑定上下文可包装，Activity owner通过ContextWrapper解包；重入幂等，其他Activity不能解绑本owner。

`ContentComposeHost`以系统Resources的density与fontScale提供LocalDensity，不改变Activity／地图资源配置；ComposeView在挂载前显式使用绑定局部Lifecycle的Recomposer，不从无现代owner的地图窗口根查找，原地图owner不受污染。`SplitPanelController`仍唯一提供分界，宿主仅调整content_host的宽度和裁剪，不接触两条Surface。临时来源层返回键由 `kc.onKeyDown/onKeyUp` 委托 `ContentRuntime.onBackKeyDown/onBackKeyUp`，只锁存本owner已消费的菜单返回序列，重复DOWN与UP不穿透地图，暂停清锁；无菜单时保持原按键与地图返回路径。

生产依赖按版本／SHA锁定，新增现代AndroidX及旧support引用隔离，graphics-path JNI类名独立保留；库资源重链接到最终地图资源表且原public IDs不变，多DEX闭包和包身份检查纳入原强制签名主链。UI按系统密度做真实模式紧凑布局，固定字体与48dp热区，不虚构原型占位卡或扩大能力范围。构建与本机探针见 [宿主入口](../../ui-preview/map-host/README.md)，车机真实服务、地图首帧、手势与双Surface仍需同包实测。

充电字段在既有`ContentVehicleAdapter.readSnapshot()`中归一：电压0x344用INT32事务7，电流0x345用FLOAT事务13，正有限量且充电才计算kW；原始SOC100、已连接和明确BMS idle0归COMPLETE5，`ContentStore.normalizeChargeState()`只增该有效枚举，UI不以显示电量推导。剩余时间沿已记录充电样本暂按分钟、2047特殊值为未知；仅快照经Store→Mapper→UI投影，UI不读取或计算车辆功率。研究单位与未确认完成状态边界仍须同包现场核对，见[类型补充](../research/充电功率读取类型与完成态补充.md)。
