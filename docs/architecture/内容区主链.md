# 内容区底层架构主链

> **职责：** 定义内容区的分层、状态流、唯一 owner、生命周期和适配边界。产品行为见 [产品需求基线](../product/产品需求基线.md)，用户偏好见 [设置项清单](../product/设置项清单.md)，源码锚点见 [主链索引](../code-map/主链索引.md)。
>
> **当前状态（2026-10-04）：** 正式 UI 唯一入口是 [content-compose](<../../source/amap-9.5.0.600013/content-compose/>)；`ContentRegistry`、`ContentStore`、`ContentRuntime`、`ContentComposeHost`、`ContentBinding` 与车辆／媒体适配器构成当前唯一主链。旧 [ContentRenderer](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentRenderer.java>)／[ContentIconView](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentIconView.java>)只保留历史实现，不是当前快捷、Dock、图标、歌词、媒体封面或氛围背景 owner。用户已安装上一车控签名候选并确认颜色与主驾／方向盘可点击；当前扩展副驾独立真值入口、同源AUTO／方向盘路径动效与按摩wave着色，已验收颜色和Ripple保持为回归基准。本机测试、当前签名身份与新包现场边界统一见[修正记录](<../testing/自动加热动效与副驾入口修正验证记录-20261004.md>)，用户反馈不外推副驾或新动效的硬件闭环。历史 `480×480` 悬浮链和 S191 只作为参考。

## 1. 运行形态与边界

`03地图` 是以高德地图为宿主的单 APK。内容区不嵌入外部 APK、Activity、WebView 或独立悬浮窗，而是在地图 Activity 的内容层中运行：

```text
一个 APK
└── 高德 Application / 地图 Activity
    ├── 高德地图链
    └── 03地图内容链
        ├── MediaAmbientBackgroundRenderer
        ├── 顶栏
        ├── 页面
        ├── 控制区
        ├── Dock
        └── 临时浮层
```

`MediaAmbientBackgroundRenderer` 是架构上的全局背景职责，物理实现为 `ContentBinding` 的唯一 `ambientArtwork` 加常驻的 `MediaAmbientBackground`，位于顶栏、页面、控制区和Dock之下。歌曲身份由 `ContentMediaAdapter` 读取会话音频语义及元数据并发布 `MediaSongIdentity`，经唯一Store投影为 `MediaState.isSong`；歌词和背景共用该门禁，播放状态只驱动时间线／柔光运动。Binding在后台按recordingKey、位图引用与generation生成128×128色场及羽化柔光，切歌空窗／暂停／新图失败保留最近有效背景，异步结果按请求代数与宿主生命周期验收。[MediaAmbientBackground](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/MediaAmbientBackground.kt>)的`AmbientSceneBaker.prepare()`在Default worker将128源field的overscan宏观底、三层LIGHTEN与veil合成最长边192px场景，确定种子多周期motion最多10Hz发布；screen `AmbientPainter.drawTransition()`稳态只画1bitmap、500ms淡化期间至多2bitmap，没有screen LIGHTEN或saveLayer。motion取样和500ms进度分离，颜色／整体opacity正确解耦；混合状态中断只capture一次同宽高比低res，端点复用不可变纹理。viewportresize不重开fade，暂停／失焦冻结published phase，stop取消worker并由generation拒收过期结果。已发布位图不主动recycle，离开引用后由Android安全释放；只回收从未发布的过期结果。宿主stop取消任务／帧驱动并释放缓存引用，页面切换不重算。内容区只负责内容层；地图面板的宽度、位置、两条Surface和native布局仍由既有地图主链及 `SplitPanelController` 负责。页面不得直接修改 `map_surface`、`ui_surface` 或地图Activity的分屏几何。

本轮歌词仍只有 `ContentMediaAdapter → ContentPorts.MediaSnapshot → ContentStore → ContentUiMapper/ContentBinding → WallpaperLyrics` 一条状态链。Adapter 只接收实际 MediaSession/AVRCP 位置与来源证据，Store 拥有可信时间线和纯 `ContentLyricsCursor` 的活动句、滚动锚、多声部及间奏派生；UI 只在已经证实的锚点上绘制词内进度，不读取服务或创建媒体事件。定时/纯文本在 LyricsSnapshot 明确区分。未知位置的活动句与滚动锚均为-1，不用首行冒充业务真值；UI只保留上一有效目标的呈现几何，新的可信seek由同一偏移动画从当前帧接管，动画沿途按当前可视偏移取行，不按终点提前替换视窗。MediaSession同generation的有效单调发布时间只作为位置排序证据，倒序位置拒绝，缺省时间兼容；publisher变更清排序证据，不清已有位置。歌词加载显示与媒体共享isSong门禁，无歌曲不显示加载文案。

`ContentLyricsEngine`持有最新请求、生命周期与歌词/封面缓存副作用；`LyricsProviderRegistry`集中注册八个Provider（Apple当前无登录入口，未连接时不发网），`SharedProviderCatalog`让歌词和封面共享同一目录IO且各自独立取消/截止。Provider基础正文与可选逐字增强分离，首个同步正文及后续实质升级立即投影；`LyricsContentRanker.isMaterialUpgrade()`仍是已显示正文和自动缓存的唯一替换门槛。录音proof、人工优先、Store唯一时间线保持。请求调度、完整来源边界、封面竞速及未来设置接线只在[歌词封面统一解析](歌词封面统一解析.md)维护；本轮不改颜色或设置UI。

歌词／封面自动缓存始终启用，`LyricsCache`同库事务及`ContentCacheBudget`统一拥有自动歌词、网络／原生封面的1GiB预算和淘汰顺序；SQLite物理页上限与可复用空闲页也受控，人工歌词不是淘汰对象，配额不足整笔回滚。2MiB单响应／条目、512px解码边界保持，旧PNG只迁移到同库而不并存第二缓存。后台可取消网络解析、关闭IO句柄，但不能把同录音已准入正文清为LOADING；临时正文及时持久化，恢复时先重新验证当前录音再投递已有READY快照，换歌／换源则按既有隔离清理。[WallpaperLyrics](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/WallpaperLyrics.kt>)全曲按48sp最大current字号固定geometry，非current主文在每visualLine固定槽内以40sp绘制，同录音正文升级按当前可见行身份迁移呈现原点，不变更Store播放游标。`ContentLyricsCursor.waitRows()`复用同一resolve门槛投影静态前奏／词尾／行尾间奏区间，Mapper只按不可变正文／曲长缓存布局事实，不维护第二游标；UI把`LyricWaitRow`固定占位纳入全曲tops、可视行和拖动几何，当前Store gap精确匹配才点亮对应等待行，不在固定坐标浮画，进出不改全曲排版。普通LRC的长行首间隔不能推断唱完，更不能按8秒上限伪造等待；必要加载文案在歌词区域居中。

### 1.1 歌词低开销呈现与终态 owner（2026-10-04）

- [ContentUiMapper](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/ContentUiMapper.kt>)按不可变原lineList引用identity缓存全曲UI rows／words，业务位置／游标／状态仍真实投影；新body identity才失效，不创建第二时间线。
- [WallpaperLyrics](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/WallpaperLyrics.kt>)拥有呈现文档请求／跟随动画／实际偏移binary-search窗口及帧门禁；current强调是合法scroll current与真实singing并集，不等first-word开唱，gap／unknown／duration守门，singing与Store游标不被UI改写。[LyricLayoutDocument](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/LyricLayoutDocument.kt>)按不可变正文、width、metrics和字体在独立Default worker编译全曲shaping，逐row检查cancel，整个文档原子发布。worker完成只发布candidate；composition仅在candidate.request仍匹配时成对准入文档与source，最后准入pair保存为非Snapshot呈现引用，时间锚不额外写状态。新文档未准入时保留最后完整pair并冻结，不能把A游标套未准入B的geometry；连续B完成／C升级合并重组也须保留A pair。同录音真正准入后迁移旧可见锚。纹理另由Default worker的per-cache Mutex与片间cancel checkpoint准备有界slices；visible=false取消文档／纹理prepare，过期结果不可发布。
- `LyricFrameSchedule`只从强调行的当前可见visualLine、真实reveal／安全glyph onset+1000ms及真实可见gap区间派生采样需求；RUN使用frame clock，词间休眠到按真实playbackSpeed换算的下一边界，anchor／seek／正文／可见窗口变化通过conflated请求唤醒。UI不resolve第二游标、不造媒体事件。frame job只有Snapshot derived moving负责终端取消／重启，不在loop另设duration break，防同帧seekback恢复true却失去job；自然到duration停帧、无source更新的下一边界自唤醒与同歌seekback必须通过专项。
- [LyricInkRenderer](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/LyricInkRenderer.kt>)拥有full-context StaticLayout geometry、grapheme／liga／Bidi／源word选区映射、visualLine纹理与逐字上浮元数据；unsafe joining保守不独立移动、跨word连字只源词fade，颜色grapheme cuts与运动安全分离，joining＋emoji混排不让彩色cell取消相邻文字theme tint。actual raster RGBA保色；geometry预编译`fullRevealEndMs`，cold仅完整合法coverage才整体完成，已知词结束不等同全正文完成。worker预编译物理相邻cell，热painter按相同颜色／Shader／alpha／rise合批，未映射正文不能因已知词全部结束被提前唱亮；每slice一次save，批次之间只增量translate。每ink独立edge Shader只在自身实际geometry改变时setLocalMatrix，完成／未开始状态复用整批，不逐字符save／restore；真实fill前沿仍按源词采样。12MiB byte LRU只计sharp／soft纹理条目，不是总进程峰值；热painter无bitmap/layout/Path/blur／viewport saveLayer，但API28动态Shader仍有native更新成本，不声称零nativealloc。冷首屏geometry异步准入后、纹理未到的slice仍用原StaticLayout防空窗，暂缺blur／精确rise并有layout.draw成本。
- `lyricCharacterOnset()`只读取源word的startFraction确定起点；`lyricCharacterRiseAt()`把源位置纯采样为0..1，每安全视觉单元固定1000ms ease-out cubic，从正常基线开始向上2.5dp，完成保持1，不在起点下跳或终点归零。源word时长只影响开始时刻，不改变动画速度，短词允许上浮尾部跨过源词结束；滚动／离屏按既有窗口裁剪，暂停冻结、seek复现。该动效不改变parser、cache、真实word或Store timeline；不生成scale／逐字halo，复杂字形仍按clearMotionBoundary禁止独立移动。
- [ContentPorts.LyricsSnapshot](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentPorts.java#L382-L413>)保留0..3并新增NO_MATCH4／NETWORK_ERROR5／INSTRUMENTAL6；[LyricsContent](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/lyrics/LyricsContent.kt>)拥有明确provider boolean／唯一marker证据，[LyricsResolutionSession](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/lyrics/LyricsResolutionSession.kt>)与[ContentLyricsEngine](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/lyrics/ContentLyricsEngine.kt>)重放严格录音proof，realbody优先，失败refresh保持READY且不耗budget。pure无伪行／词轴，不进入body持久cache；同歌内存proof事实可保，切歌／源／lifecycle迟到拒收。
- [LyricsPage](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentPanel.kt#L542-L595>)只消费终态投影，正式songloading blank、no-song拒旧reason、body优先。单次Compose Layout将三句精确文案text自身中心放到viewport双轴几何中心，optional source只在下方12dp，不移动文案；pure不放歌词区source，媒体区来源入口保持。业务failure不按空body／曲名／gap猜pure。

上游与早期成本依据见[历史研究](<../research/逐字符歌词低开销渲染与Apple风格适配-20261003.md>)；当前源码与专项入口见[主链索引](<../code-map/主链索引.md>)；本轮tests／Lint／签名包身份及设备连接边界只以[当前验证记录](<../testing/歌词微动态与帧调度重构验证记录-20261004.md>)为准。静态绘制计数、worker线程与SDK28／34 native像素通过不能换算为8155性能或用户现场视觉验收。

### 1.2 媒体事实、稳定锚点与分域订阅（2026-10-04，本机与签名完成）

用户反馈整合包周期卡顿后，同包线程／Binder审计确认媒体回报重复pull、未变化来源重仲裁和外层锁贯穿UI投影。本轮Adapter协议在锁内更新事实／复制快照，退出所有外层锁后FIFO通知；真实callback参数缓存、初次缺失事实后台补读、来源单在飞合流、能力缓存由生命周期／连接／包事件更新。录音metadata与播放clock必须配对，命令由命令后真实来源读回确认；失败一次定时恢复，健康来源不增轮询。Store保留唯一可信Timeline与Cursor，暴露稳定不可变anchor并按下一真实语义边界单次唤醒，不再16–100ms把插值位置重新锚定为全状态。

Binding／Mapper在投影前分别拥有shell、lyrics、clock、artwork域；实际Compose在顶栏／歌词叶节点订阅，媒体时间变化不重新格式化日期或投影车控。独立时钟按显示分钟／秒与当地日期调度，系统读写在serial worker，迟到结果按生命周期／顺序和反馈版本准入。正文／文档成对准入、Unicode安全、批次与一秒上浮终点继续保持。实现不变量和同包诊断边界见[本轮职责方案](<../plans/周期卡顿的媒体事实与呈现调度重构.md>)，实际稳定源码回归、签名候选及用户自行上车测试边界统一见[本轮验证记录](<../testing/周期卡顿职责重构验证记录-20261004.md>)。本机与包级证据完成，按用户要求本轮不连接／安装，新包现场性能待验证。

## 3. 注册表与首轮内容

### 3.1 页面

页面以稳定 `pageId` 注册，物理数组顺序不作为身份：

```text
PageRegistry
├── shortcuts       可见
├── vehicle_info    已注册，首轮隐藏
├── lyrics          可见，直接投影透明壁纸歌词视窗；03歌词解析／缓存核心经ContentLyricsEngine接入，仍由ContentStore唯一拥有状态
└── projection      已注册，首轮隐藏
```

首轮派生顺序为 `shortcuts → lyrics`，默认主页为 `lyrics`。页面通过能力声明决定是否支持沉浸式状态；快捷功能页不支持，歌词页支持，投屏页预注册但未展示。

### 3.2 控制区

```text
ControlRegistry
├── media
└── climate
```

默认顺序为 `media → climate`。座椅通风、座椅加热和座椅按摩属于快捷功能，不注册为控制区模块。

### 3.3 Dock 与快捷功能

当前 Compose 的固定入口清单由 [ContentModels](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentModels.kt>) 的 `ShortcutId.entries` 唯一枚举，[ContentPanel](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentPanel.kt>) 的 `PrototypeGrid()` 与 `PrototypeDock()`消费相同顺序：

```text
ShortcutId.entries（固定七项） → ContentEvent
├── Lock             → ControlId.Lock             → toggleLock
├── SteeringHeat     → ControlId.SteeringHeat     → steering_heating
├── Ventilation      → ControlId.Ventilation      → seat_ventilation
├── Heating          → ControlId.Heating          → seat_heating
├── PassengerHeating → ControlId.PassengerHeating → passenger_seat_heating
├── Massage          → ControlId.Massage          → seat_massage
└── Settings         → SettingsTapped（不是 ControlId）
```

这是**六个车控 ControlId + 一个设置入口**；主副驾加热各自有稳定ID和实际状态。方向盘已接入与座椅相同的 Store／VehiclePort 命令链，不再是禁用占位；是否可以写仍由实际能力声明与字段有效性决定，不以新增图标或读到值宣称车辆闭环。Dock 车锁居左、其余六槽仅图标，无独立“快捷／菜单”槽；设置仍只反馈尚未接入，页面切换经横向 Pager。

当前 Compose 不消费可编辑 Dock 偏好，不支持长按替换菜单。[ContentRegistry](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentRegistry.java>)／[ContentPreferenceStore](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentPreferenceStore.java>)保留的旧“独立固定锁 + 五槽”持久化契约只为历史 Renderer 兼容，不是当前七项清单的排序／持久化 owner；不宣称两清单已统一持久化。未来编辑模式需另定义迁移与热区，不重新引入临时替换菜单。

### 3.4 顶栏

顶栏当前由 `content-compose/ui/com/icar03/content/ui/ContentPanel.kt` 的 `PrototypeTopBar()`／`TopBarText()` 呈现，数据来自 `ContentUiMapper.map()` 投影的 `ContentUiState`；`ContentRenderer` 的旧 `buildTopBar()`／`renderTopBar()` 只保留历史记录。主题由 `ContentTheme` 持有，时间、温度、里程、充电和媒体状态均来自 `ContentStore` 派生状态；UI 不轮询 Vehicle HAL、读取 MediaSession 或计算车辆功率。普通文字与原厂来源资源继续使用正式 APK 已登记资源；页面、状态、按压和弹层动画由 Compose 生命周期控制，暂停／销毁取消回调和动画。

## 4. 呈现状态与地图几何

### 4.1 稳定状态

```text
ContentPresentationState
├── SPLIT
└── PAGE_IMMERSIVE

ImmersiveInteractionPhase
├── IDLE
├── DRAGGING
├── ELASTIC_REBOUND
└── SETTLING
```

`PAGE_IMMERSIVE` 只对当前页面生效。切换到不支持沉浸式的页面前，必须先回到 `SPLIT`；地图重新展开也等价于退出沉浸式状态。

### 4.2 唯一动画真值

```text

presentationProgress = 1
  当前页面沉浸式稳定态，地图完全推出

0 < presentationProgress < 1
```

当前 [ContentPanel](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentPanel.kt>) 的两个 `HorizontalPager` 只在各自实际 viewport 内切页／卡，稳定态邻项外露 `0px`，不创建第二套地图几何。快捷／Dock 共用第3.3节固定清单；车控经 Binding → Store → VehiclePort，单一待确认期间不叠发车控命令。`ControlState.displayed = target ?: actual` 立即投影目标图标与选中 base，actual 只由外部快照回读；失败、断连、拒绝及超时清目标并恢复实际状态，不把目标当车辆成功。

## 5. 唯一数据流

```text
系统 / 车机 / 媒体 / 歌词 / 投屏
              ↓
        Port / Adapter
              ↓
      归一化 Snapshot
              ↓
       ContentStore / Reducer
              ↓
       ContentState（唯一 Store）
              ↓
       ContentUiMapper / ContentBinding
              ↓
       ContentUiState → ContentPanel / OemIcon
              ↓ 用户意图
      Command Port / Effect
              ↓
        Adapter 执行与回流
```

所有 UI 是状态投影，不持有业务真值。点击成功不能直接等同于业务成功，必须等待外部状态回流。

| 事实 / 行为 | 唯一 owner | 页面使用方式 |
|---|---|---|
| 呈现模式、进度、吸附 / 回弹 | `SplitPanelController.applyDividerX(F)` | 地图几何和内容宿主消费同一份进度，不创建第二份动画真值 |
| 地图面板、两条 Surface 几何 | `SplitPanelController` | 从进度派生，不由页面改写 |
| 主题 | 高德主题回调 → 内容主题状态 | 不读取系统 `uiMode` |
| 时间 | 系统时钟适配器 | 统一派生 `TopBarState` |
| 车辆状态 | `ContentVehicleAdapter` → `ContentPorts.VehicleSnapshot` → `ContentStore` | 顶栏、快捷与 Dock 经同一 Mapper 投影；known 不等于 writeAvailable |
| 媒体状态 | `ContentMediaAdapter` → `ContentPorts.MediaSnapshot` → `ContentStore` | 媒体卡片、歌词页和 `MediaAmbientBackgroundRenderer` 订阅同一快照 |
| 媒体氛围背景 | 唯一MediaSnapshot／Store → Binding的ambientArtwork → MediaAmbientBackground／AmbientSceneBaker | 确认歌曲后覆盖内容板块，暂停／切歌／新封面暂缺保留最近有效场；非歌曲才500ms退出，首次从未有真实封面保留主题底；screen物理链见第1节 |
| 歌词 | ContentLyricsEngine／唯一Store／ContentUiMapper → WallpaperLyrics＋LyricInkRenderer | 只消费严格录音／可信源轴，UI不造时间线；当前呈现、worker与终态职责见第1.1节 |
| 投屏 | `ProjectionEngine` | 通过命令 / 状态模型接入 |
| 排序和显示偏好 | `ContentPreferenceStore` | 只保存稳定 ID 和用户设置 |
| 页面 / 控制 / Dock 当前选择 | 唯一 `ContentStore`；当前 Compose 七项 Dock 固定 | Compose 只消费投影，旧 Dock 偏好仅保历史兼容 |
| 临时浮层 | `ContentBinding` 的 sourcesOpen／局部 feedback | 只承载呈现状态，停止清理，不成为业务成功真值 |

运行时状态、持久化偏好和派生状态必须分离；派生值不能反向成为第二真值。

## 6. 生命周期与物理锚点

### 6.1 锚点

1. Application：`source/amap-9.5.0.600013/smali/com/autonavi/amapauto/app/MapApplicationProxy.smali` 的 `onCreate()V`。
2. 地图 Activity：`MainMapActivity` 相关 Manifest / 生命周期链；施工前必须以 Manifest 和调用证据确认唯一 owner，不能只按类名判断。
3. 根布局：`source/amap-9.5.0.600013/res/layout/main_map_view.xml` 的根 `FrameLayout`。
4. 地图几何：正式源码 `source/amap-9.5.0.600013/smali/SplitPanelController.smali`。
5. 首轮内容入口：正式源码 `source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/` 下的 `ContentRegistry`、`ContentRuntime`、`ContentStore`，以及 `content-compose/{host,runtime,ui}` 下的 `ContentComposeHost`、`ContentBinding`、`ContentPanel`。

### 6.2 生命周期合同

```text
kc.v() 内容根 View 就绪
  → ContentRuntime.attach(rootView)
  → 幂等挂载唯一 ContentComposeHost，绑定 Store / ContentBinding
Activity.onPause
  → kc.onPause → ContentRuntime.onHostPaused → ContentBinding.stop
  → 暂停歌词解析、氛围生成、页面动画和封面任务，保留 Store 状态
Activity.onResume
  → kc.onResume → ContentRuntime.onHostResumed → ContentBinding.start
  → 当前状态对齐并恢复可见层，不重播已完成的历史转场
Activity.onDestroy
  → ContentRuntime.detach(activity)
  → ContentComposeHost.destroy → 解除 Activity / View 引用和宿主订阅
```

必须满足：同一 Activity 只有一个 `ContentHost`；重建不重复注册；适配器不持有失效 Activity；页面重建不重复注册底层监听；内容区生命周期不重启地图。

当前图标的播放与绘制 owner 是 [OemIcon](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/OemIcon.kt>)；网格与Dock经同一`ShortcutOemIcon()`消费同一`ControlState.displayed/known`。控制图标recipe的唯一owner是[VehicleControlIcons](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/VehicleControlIcons.kt>)的`vehicleControlIconRecipe()`，集中决定原厂家族、左右座椅、mode、主题、Vector fallback、Lottie帧段和路径调色；OemIcon的播放signature只含asset／frames／mediaGlyph，颜色、描边和Vectorfallback换配方不会重启同一时间轴。车锁只用displayed业务目标触发，不读取LocalIconAction先重播旧锁状态；正常pending／ACK／自身确认和重复快照不变displayed，不会打断或重播。业务actual／target与图标进度分层，recipe不决定车控成功。来源、版本、原APK entry与source／decoded／deployed SHA的唯一owner是[OEM清单](<../../source/amap-9.5.0.600013/assets/content-oem/asset-manifest.json>)。手动与AUTO采用同一Launcher skin家族，主副驾使用左／右专用资源，方向盘也使用真实原厂Lottie；不再因AUTO或SteeringHeat提前返回静态旁路，也不把Vector名称中的数字猜成动画帧。

原厂`DockAcButton`与真实皮肤资源表确定seat-auto的中性A段91..120、wheel-auto的中性A段61..90；本轮AUTO只表达自动选择，不把固定图标段推定成实时硬件热级。手动及关闭保持各自原厂段，主题替换recipe不触发业务播放；原字节与hash保持，runtime只适配已登记fill／stroke路径颜色，档位alpha、geometry、trim和transform不改。按摩的body fill与wave strokes各有独立颜色回调，开启全部wave固定功能紫、关闭按主题基础色；不得依赖末帧紫色来放任中间白线，也不以全图tint消除原厂档位层次。精确owner、皮肤文件名与帧段见[动画研究](<../research/座椅与媒体来源原厂动画补充.md>)，本轮测试与新包边界见[修正记录](<../testing/自动加热动效与副驾入口修正验证记录-20261004.md>)。

> **历史 Java 图标合同：**以下保留旧消费者、兼容试验和当时限制，不覆盖当前 Compose 已登记的分档路径动画。
>
> 图标的物理 owner 是 `ContentIconView`：原厂同包资源封装在 `res/drawable/content_oem_*` 与 `assets/content-oem/`；资源来源、版本、APK 内原路径和原始／包内 SHA-256 在 `assets/content-oem/asset-manifest.json`。静态 Vector 是稳定帧；通过兼容试验的七份 Lottie 在按钮点击产生的目标图标变化时即可单次播放，不再等待服务返回，仍基于 `isShown`、窗口焦点、当前页卡和 Activity 生命周期停播。通风／加热的 AE 效果和预合成部分未获播放器完整支持，按摩颜色变体无可证档位映射，三者仅使用原厂日／夜四态静态 Vector，不能宣称这三类动态图标已复用或说成 native 可调用文件。跨包直接挂载的 A 类资源目前为零项；原厂完整控件是 C 类视觉参考。

字体与动效的物理 owner 由当前 Compose 内容层承担：系统 `LocalDensity` 只影响内容子树，原厂资源仍由正式 `res/drawable`／`assets/content-oem` 提供；不存在网页字体、WebView 或外部图标库运行依赖。页面吸附、歌词换句和媒体氛围网格使用重量缓动并在 `pause()`／`destroy()` 取消；真实媒体封面氛围背景由唯一 `ContentBinding.ambientArtwork` 与 `MediaAmbientBackground` 承载。

## 7. 能力适配边界

### 7.1 媒体、歌词、投屏

- 媒体读取、来源切换和标准控制沿 [车机媒体能力研究](../research/车机媒体能力研究.md) 的已验证路径接入。
- 歌词解析、候选准入、缓存和时间轴由 `ContentLyricsEngine` 在 `ContentStore` 的唯一 `LyricsPort` 边界内完成；页面不读取通知、不枚举 MediaSession、不发网络请求、不管理全局定时器。Engine 发布不可变整曲行，`ContentStore` 按可信时间线调度当前句。
- 投屏只迁移业务逻辑、状态模型和协议适配边界；页面不直接持有协议连接、不修改地图几何。

### 7.2 车辆与车控

车控状态至少能表达：

```text
AVAILABLE / UNAVAILABLE / STALE / PERMISSION_REQUIRED
EXECUTING / FAILED
```

研究文档是正式车控协议的证据输入；`ContentVehicleProtocol`集中原厂读写编码，`ContentVehicleAdapter`复用既有Binder封包并串行执行当前按钮的单一目标；通风与加热的相互处理归原车系统，不在应用增加互斥、预先关闭另一控制或补偿写入。绑定 / 描述符核对、后台轮询和命令仍经 `ContentPorts.VehiclePort`、`ContentStore` 统一回流，页面不直连服务。Store 对写命令保持待确认态，只由后续真实快照确认成功；待确认目标供图标及选中 base 预反馈，失败、断连和超时恢复 actual 投影并提示，不把预反馈当成功；`known` 只表示读状态有效，不能推导 `writeAvailable`、Binder写权限或自动命令可用。充电对 `0/0/0` 标未插枪；连接 `1` 显示已插枪，只有 BMS `3` 标充电中、`6` 加预约 `1` 标预约等待；连接 `2` 仅在 BMS `3` 时按已记录的充电样本显示充电中，其余未知。未确认的插枪状态不猜充电功率、剩余时间。仅在三项原始字段变化时记录最小充电原始值，供目标车机只读诊断。按摩按用户选择支持关闭与三 / 二 / 一档：关闭只写开关，开启时确认 `0x241=2`、模式 `0x245` 在 `1–5` 且强度 `0x243` 在 `1–3` 后，再写用户选择的 `0x243=1/2/3`；读取开关、模式和强度，但不会因关闭后的模式记忆差异自动回写模式或强度。强度值与原车界面、厂商源码和映射相符，但第三方探针尚未独立写过强度；因此本地 Binder 顺序探针只证明发送顺序，不证明真实车机 UI 闭环。研究探针和本地静态 / 构建证据都不等于正式地图 APK 已完成车机 UI 闭环；车锁、充电、温度、座椅等能力仍需逐项补正式应用层读取、状态变化、命令、结果回流及可逆恢复运行证据。档位与除霜不是本轮对用户暴露的控制能力。应用不再在`queueCommand()`读取档位／车速并自加P／零速拒绝，原车系统仍是驾驶条件限制owner；Binder身份、连接、权限失败、单目标待确认、回读和6秒超时边界保持。

页面层不能出现厂商属性编号、Binder 事务、权限判断或直接写值；这些内容只进入 Adapter / Port 和研究文档。

### 7.2.1 共享控制定义、协议与实际模式

纯[VehicleControl](<../../source/amap-9.5.0.600013/content-compose/model/com/icar03/content/model/VehicleControl.kt>)是六控制的稳定ID、合法模式、循环、自动模式和关闭↔开启边界的唯一owner。`:content-model`不依赖Android服务、Compose、厂商编号或模拟器；UI的`ControlId`只是类型别名，Store、Preview和Ripple均消费同一份定义。Settings不属于车辆控制。

| 控制 | 业务循环 | 读写语义边界 |
|---|---|---|
| 方向盘 | 关闭0 → 2档2 → 1档1 → 自动3 → 关闭0 | 主档位与自动active联合回读；主字段命令承担手动／自动切换，active只读；AUTO可伴随实际热级变化 |
| 主驾加热 | 关闭0 → 3档3 → 2档2 → 1档1 → 自动4 → 关闭0 | 复合0x212与auto0x282分开；自动请求复合8，auto只读；AUTO不等于无实际加热 |
| 副驾加热 | 关闭0 → 3档3 → 2档2 → 1档1 → 自动4 → 关闭0 | 独立复合0x213与auto0x34a、area0；与主驾共用归一规则但actual／known／active分别保存，auto只读 |
| 主驾通风／按摩 | 关闭0 → 3档3 → 2档2 → 1档1 → 关闭0 | 保持已核对映射及按摩开关／模式／强度合同；末档关闭边界由共享定义派生 |

[ContentVehicleProtocol](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentVehicleProtocol.java>)集中厂商字段、读取归一与不可变命令映射；[ContentVehicleAdapter](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentVehicleAdapter.java>)负责绑定、串行执行、回读和失败回流。一个正式`requestSeatLevel()`覆盖全部已实现目标，删除research特许入口；读取编码和写入编码不可互代，active状态回报不作为发送目标。具体OEM消费证据与现场边界见[车机研究](<../research/车机媒体能力研究.md>)本轮补充。

[ContentStore](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentStore.java>)在同一锁中解析循环目标、校验能力并锁存唯一pending；actual只采纳有效`VehicleSnapshot`，6秒超时、请求代数、拒绝／断连和回弹保持。[ContentState.controlLevel()](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentState.java>)为Store和Mapper提供同一实际模式投影；Store的`snapshotLocked()`在相同状态锁内派生并发布不可变`writableSeatControls`集合与连接／车锁能力，Binding不混用旧actual与新能力。

[VehiclePort](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentPorts.java>)能力区分连接、控制支持、合法目标和实时字段有效性。未知模式不造默认档位，按摩开关已知开启但强度未知时只保留关闭意图。验证等级记录在证据文档，不硬编码成方向盘／自动档永久禁用。[ContentBinding.dispatch()](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/ContentBinding.kt>)直接路由稳定ID，Mapper只投影同一快照的actual／target／能力。排队或Binder返回均不能确认成功，仅后续实际模式匹配目标才清pending成功。

回归必须经过默认正式Port及真实Adapter＋Binder替身，覆盖加热1→auto→off、方向盘完整循环、单pending、拒绝、未知、断连、超时和迟到隔离；不能只测另行放开的candidate替身。替身必须将命令码转换成独立回读字段，不能简单回显。正式地图同包现场读写、回流与可逆恢复仍需独立证据，不继承旧研究或旧包验收。

## 8. 施工不变量

1. 一个事实只有一个 owner；新能力按职责扩展现有 Registry、Store、Port / Adapter、ContentBinding 或 Compose UI，必要时新增模块并记录输入、输出和生命周期。
2. 页面、控制模块和快捷功能使用稳定 ID；顺序、选中态和编辑态不由 View 层级隐式决定。
3. 内容层不得拥有第二套地图分屏几何；`SplitPanelController` 是地图物理位置唯一 owner。
4. Activity 重建、地图收放和页面重排不丢失地图导航状态、用户偏好或媒体状态。
5. 动态 View 创建、更新和销毁受生命周期控制；不得重复监听或持有失效 Context。
6. 入口是否可用由连接、自身有效实际模式、已实现目标和pending决定；现场未验收如实记录待验证，不把静态字段、旧实验包或单次调用成功写成产品完成，也不把验证等级硬编码成永久禁用。

[ui-preview/content-runtime](<../../ui-preview/content-runtime/>) 是接入库的构建／测试模块，当前可维护实现来自正式 [content-compose/runtime](<../../source/amap-9.5.0.600013/content-compose/runtime/>)；不建立新的 Store 或 Adapter。`ContentUiMapper.map()` 将 `ContentState`、真实系统快照和 Port 能力投影为纯 `ContentUiState`；`ContentBinding.dispatch()` 把稳定用户意图送回已有 Store／SystemPort；`BoundContentPanel()` 只负责宿主生命周期订阅，并把真实封面与自有氛围背景交给内容UI slot呈现。

### 10.1 快捷／Dock 边界 Ripple 的呈现 owner（2026-10-03）

- 资格由 [ContentPanel](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/ContentPanel.kt>) 的 `shortcutRippleEnabled()`拥有：车锁有效且可操作时每次按压都有Ripple；四类多态仅下一次意图跨0↔on边界时允许。具体为方向盘actual0／auto3、加热actual0／auto4、通风和按摩actual0／末档1；2→1、3→2及加热1→auto4等on→on档级切换不播Ripple、不改变选中背景。unknown、不可写或pending不接收新车控按压。
- [BoundaryPressFeedback](<../../source/amap-9.5.0.600013/content-compose/ui/com/icar03/content/ui/BoundaryPressFeedback.kt>) 的 `rememberBoundaryPressFeedback()`／`start()`在DOWN锁定本次资格、坐标、原base与ripple颜色；后续pending／actual回读引起重组不撤销已接受pulse。collector仅按InteractionSource及可见生命周期重启，不按最新eligible拆除；UP或CANCEL释放对应press，扩散覆盖后整体uniform fade，不堆第二层矩形按下底。
- Dock的`RoundedPressButton(rectangular=false)`保留原外层hit-area和至少48dp热区，inner为原48／72dp圆角press-area；`touchCoordinates`与`area()`记录同root坐标，触点按outer→inner转换并夹在inner bounds，circle由inner圆角clip裁剪。网格与Dock复用同一feedback owner，图标微动使用同一interaction source，不以缩小外层命中区解决泄漏。
- 车锁扩散后uniform fade回**同一个base**，锁／解锁没有常驻选中填充，也不再有“仅锁整槽选中”规则。多态base仅由`ControlState.displayed > 0`和当前主题决定；目标在UP后立即投影，已锁存Ripple完整播放再露出目标base，on→on回读不造成背景闪动或重播。
- pause、窗口失焦、离屏、Composition dispose取消pulse且不补播，重复快照／时钟不触发Ripple。媒体的`rectangular=true`原固定RGB／alpha按下效果和纵向滑条保持原链，来源菜单自身Material Ripple不被本轮替换。

以上是当前源码可核对的呈现合同；DOWN快速UP、CANCEL、延迟回读、断连、边缘触点、双主题像素及生命周期仍须逐项填入[本轮记录](<../testing/车控与Ripple改造验证记录-20261003.md>)，源码存在不是测试通过。

按钮音效集中在已接受事件边界经`playClickSound()`调用高德`playSystemClick()`，失败回退系统View音效，一次点击不双响，程序快照与页面settled不发声。原厂Lottie6.6.7和Okio1.17.6按既有版本／SHA纳入Compose锁，不复用旧Renderer／IconView、不引入AppCompat。图标消费集中于同目录`OemIcon.kt`，`ShortcutOemIcon()`仅从同一`ControlState.displayed/known`投影座椅主题、档位区间与路径调色，供网格和Dock共享；媒体来源共用`animationFor()`。局部呈现键、按压计数和播放进度不进入Store，也不确认命令。`OemFrame`只保留实际已绘制的资源／调色／composition配方，新资源异步解析期间继续展示上一帧，解析就绪后以进度0原子切入，失败回目标Vector；不提前画目标静态再倒回动画首帧。每次从对应起点正向播放一次，结束保留同一Drawable末帧；下一次明确触发才seek起点，时钟、同值快照和松手不重播。生命周期暂停／失焦／离屏取消并消费当前键，恢复稳定Vector而不补播，异步监听dispose移除；没有原厂动效的资源仅做既有微动。爱趣听恢复原厂简笔Vector；浅色配色恢复、深色填充契约由产品基线定义，右边界仍对齐viewport。原始JSON与哈希保留，媒体圆底隐藏和符号画布归一仅为登记的消费者呈现适配。

来源命令与来源实际状态分开：`ContentStore`拥有唯一待确认来源，`ContentUiMapper`投影`targetSource`；命令发送成功不更新actual，失败／超时恢复actual并反馈。`ContentMediaAdapter`保留既有显式切源Intent，新增原厂`PlayControlCheryAction`的只读Binder状态订阅／读取，通知只触发重新读取；内部来源值不复用外部`audio_source`命令值。已证实映射与未知值分别处理，未确认的爱趣听内部枚举不猜。

标准MediaSession仅凭`com.tencent.wecarflow`包名不能区分爱趣听／网易云。已可靠回读的来源优先于包名，切换后与实际来源不匹配的旧会话不能贡献播放能力、元数据或封面。Binder读取在独立工作线程，发布回主线程，stop解除订阅／绑定并取消任务，epoch隔离过期回调，不依赖ADB／root／跨包私有View。正式与接入库已有限queries声明该包，不扩大权限。SDK静态契约及本机替身测试不冒充本车普通UID绑定成功；新包来源变化、断连与真实播放能力须现场核实。

## 11. Compose 第三层宿主

正式Kotlin已迁入 `source/amap-9.5.0.600013/content-compose/{ui,runtime,host}/`，`:content-ui`／`:content-runtime`／`:map-host`直接编译这些入口；预览Controller仍只属于独立`:app`。`ContentRuntime`保留原静态签名与唯一Store，挂载 `ContentComposeHost` 后不再创建旧Java Renderer。旧Renderer源码仅历史参考，不打进第三层内容DEX。

`kc.v()`→`ContentRuntime.attach()`→内容子树独立owner→`BoundBindingPanel`；主题初值UNKNOWN=-1，未解析前仅保存弱引用root，不创建默认浅色Store／宿主；高德native明确夜间或mode1/2回调决定初始主题。native false包含未就绪，unknown经原有`nativeRequestDayNightMode(-1)`请求，`AndroidProtocolExe.sendAutoStatus(II)`状态1补ready请求；回调取得结果后原位attach，pending后台暂停等待owner恢复、detach清待挂载root。pause使Lifecycle降至CREATED，解除Binding、撤销来源菜单、停止内容时钟；resume保留已解析的高德主题，不由生命周期查询覆盖可靠回调；detach销毁Composition／ViewModelStore，再由Runtime销毁唯一Store及Adapter。绑定上下文可包装，Activity owner通过ContextWrapper解包；重入幂等，其他Activity不能解绑本owner。

`ContentComposeHost`以系统Resources的density与fontScale提供LocalDensity，不改变Activity／地图资源配置；ComposeView在挂载前显式使用绑定局部Lifecycle的Recomposer，不从无现代owner的地图窗口根查找，原地图owner不受污染。`SplitPanelController`仍唯一提供分界，宿主仅调整content_host的宽度和裁剪，不接触两条Surface。临时来源层返回键由 `kc.onKeyDown/onKeyUp` 委托 `ContentRuntime.onBackKeyDown/onBackKeyUp`，只锁存本owner已消费的菜单返回序列，重复DOWN与UP不穿透地图，暂停清锁；无菜单时保持原按键与地图返回路径。

生产依赖按版本／SHA锁定，新增现代AndroidX及旧support引用隔离，graphics-path JNI类名独立保留；库资源重链接到最终地图资源表且原public IDs不变，多DEX闭包和包身份检查纳入原强制签名主链。UI按系统密度做真实模式紧凑布局，固定字体与48dp热区，不虚构原型占位卡或扩大能力范围。构建与本机探针见 [宿主入口](../../ui-preview/map-host/README.md)，车机真实服务、地图首帧、手势与双Surface仍需同包实测。

充电字段在既有`ContentVehicleAdapter.readSnapshot()`中归一：电压0x344用INT32事务7，电流0x345用FLOAT事务13，正有限量且充电才计算kW；原始SOC100、已连接和明确BMS idle0归COMPLETE5，`ContentStore.normalizeChargeState()`只增该有效枚举，UI不以显示电量推导。剩余时间沿已记录充电样本暂按分钟、2047特殊值为未知；仅快照经Store→Mapper→UI投影，UI不读取或计算车辆功率。研究单位与未确认完成状态边界仍须同包现场核对，见[类型补充](../research/充电功率读取类型与完成态补充.md)。
