# 验证规则

1. 按本轮改动选择相关检查，复用同一稳定输入已有有效证据；纯文档改动不要求 APK 构建或车机安装。先用 `node scripts/validate-content.mjs --plan`查看范围，测试编译／失败类先最小验证，收敛后再扩到相关消费者；稳定整合时才执行适用全量。缓存复用与本次执行分别报告，不为fresh XML强制rerun；历史专项不累加为每轮门槛。具体入口见[构建与验证入口](../../operations/构建与验证入口.md)和[验证矩阵](../../testing/验证矩阵.md)。
2. 安装前核对包名、版本、入口、签名和 ABI，默认保留数据覆盖安装；新增数据损失或设备中断按 [个人风险口径](../../security/安全与密钥边界.md) 判断，已有目标不重复授权。
3. “应用已安装”不等于“分屏地图可用”；运行结论应有目标进程、实际画面、相关窗口 / Surface 及错误日志证据。
4. 设备离线、系统授权未完成或 APK 身份冲突时记录实际原因，继续可执行的本机工作，不自动清数据或切换未知签名。
5. 有正式视觉原型时，按当前 [产品基线](../../product/产品需求基线.md) 在相同画布比较关键状态、整体结构、字重、留白、色阶、阴影和触摸热区；功能通过不能代替视觉结论，示意数据和重复占位不作为功能数量要求。
6. 交互检查覆盖即时反馈、实际 / 目标分离、状态回读、失败 / 超时、取消、连续操作和生命周期；实际入口以 [代码地图](../../code-map/主链索引.md) 为准，不让历史 Renderer、旧配色或固定动画参数覆盖当前 Compose 行为。
7. 只把无法自动完成的现场或主观判断交给用户，并写清触发动作、预期画面和需要的证据。
8. 交互渲染验证区分物理输入、组件接受 Press 和动画终态：滚动父容器可能延迟 Foundation Press，边界反馈必须在 Initial pass 的真实 DOWN 锁存资格、base、颜色和当前手势凭据，后续 pending／actual 重组不能改写已接受 Ripple；终态像素采样先确认扩散进度到终点。来源菜单或弹层仍遮挡目标时，先关闭并完成退出动画再进行物理按压；不能将未收到Press时的基础色作为按压终态。固定画布的新测试宿主复用相同全屏与系统栏设置；本机Compose测试冻结时钟时，用有上限的帧推进等待目标语义与LaunchedEffect采用完成，再捕获资源和像素，`waitForIdle()`不等于推进动画／重组帧。圆角裁剪使用真正处于轮廓外的点，不把仍在圆弧内的点当成角外。生命周期回归包含不经过中间重组／帧的暂停再恢复，验证停止事件直接取消任务，不能只测正常逐帧路径。依据和实例见[车控与 Ripple 验证记录](../../testing/车控与Ripple改造验证记录-20261003.md)。
9. 状态／循环契约变化时同步校正预览替身与测试的原始 actual、known 和 target 断言；新增测试保留相邻原方法声明，再以真实编译与完整报告确认，不把括号计数、存在测试文件或只跑新用例当作全量通过。适用本机验证，不替代实车读写和可逆恢复证据。
10. 修改微动态的时间窗、起点或终点时，验证触发前／触发当刻／结束前／结束当刻的原生轨迹连续性、方向、暂停与seek复现；仅断言“像素变了”不能证明动效正确。热路径性能回归分别检查布局／栅格创建、实际绘制批次、Canvas状态栈、Shader矩阵失效和帧唤醒需求，不把“bitmap计数不增”扩张为零分配或车机流畅；端点与词间无需变化时停止高刷，真实边界、seek和恢复须能唤醒。依据与SDK28／34 oracle见[微动态重构验证](../../testing/歌词微动态与帧调度重构验证记录-20261004.md)，静态成本不能换算成8155帧率或总进程峰值内存。
11. 扩展多态控制时，完整循环必须经过正式默认Port及真实Adapter＋Binder替身；替身分开命令码与回报字段，不能特许放行正式链禁用的目标或简单回显命令。主题／资源修正必须在同一Composition内切换日→夜→日并检查实际像素、资源与动画消费；固定主题截图或Tint语义不足以证明缓存失效正确。同色独立角色用不同测试调色板验证实际消费，避免共享字段串改；现场成功仍需同包回读及恢复证据。触发与根因见[本轮车控重构记录](../../testing/车控真值架构与主题重构验证记录-20261003.md)。
12. 修改共享路径播放器、动态资源分支或命名布局时，先复核真实资源owner与帧段，再验证固定原厂帧的实际Canvas像素，排除按压缩放造成的假运动；one-shot须覆盖真实DOWN／UP、正常已知状态立即pending、ACK／自身确认、短暂未知调色、重复快照和最终尾帧。播放时间轴与调色recipe分开，资源或主题更换与业务触发分别检查；仅末帧或progress增加不能证明中间路径未被取消。颜色缺陷在实际问题关键帧验证功能色并与原始alpha对照；字体按当前密度／字体指标测量完整文字，不只按标称行高或语义文本长度推断裁切。依据见[原厂动效与副驾修正](../../testing/自动加热动效与副驾入口修正验证记录-20261004.md)，适用本机回归；无现场状态轨迹时不把可复现代码缺陷宣称为唯一车机故障原因。
13. 修改可伸缩阴影时，分别检查冷生成的最大位图尺寸／模糊工作量、几何与颜色变化的缓存miss以及暖绘制批次／中心重复填充；最终缓存小或固定尺寸200次命中不能证明冷进入轻。用分数密度与不同宽高／填充的输入验证样式缓存，不为追逐逐尺寸软件像素而把完整面板烘焙带回UI线程。车机持续卡顿归因仍需同包、同设置页的冷进入／暖滚动及UI／RenderThread采样，静态计数不换算帧率。
14. 新增Activity应用Dialog时，独立验证构造Context保留真实Activity WindowManager／父Window归属、默认应用token注入和首predraw物理几何。配置Context只负责资源；ViewRootImpl窗口binder不能替代应用token。Robolectric的WindowManager替身不执行真实WMS AppWindowToken校验，窗口测试通过仍须将同包冷开／复开／返回与IME列为实机项。触发事实与已安装旧包根因见[现场交接](../../testing/设置卡顿与Apple登录崩溃交接-20261008.md)，本机检查不宣称真实账号成功。
