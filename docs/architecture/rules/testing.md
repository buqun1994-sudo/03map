# 验证规则

1. 按本轮改动选择相关检查，复用同一候选包已有有效证据；纯文档改动不要求 APK 构建或车机安装。具体入口见 [验证矩阵](../../testing/验证矩阵.md)。
2. 安装前核对包名、版本、入口、签名和 ABI，默认保留数据覆盖安装；新增数据损失或设备中断按 [个人风险口径](../../security/安全与密钥边界.md) 判断，已有目标不重复授权。
3. “应用已安装”不等于“分屏地图可用”；运行结论应有目标进程、实际画面、相关窗口 / Surface 及错误日志证据。
4. 设备离线、系统授权未完成或 APK 身份冲突时记录实际原因，继续可执行的本机工作，不自动清数据或切换未知签名。
5. 有正式视觉原型时，按当前 [产品基线](../../product/产品需求基线.md) 在相同画布比较关键状态、整体结构、字重、留白、色阶、阴影和触摸热区；功能通过不能代替视觉结论，示意数据和重复占位不作为功能数量要求。
6. 交互检查覆盖即时反馈、实际 / 目标分离、状态回读、失败 / 超时、取消、连续操作和生命周期；实际入口以 [代码地图](../../code-map/主链索引.md) 为准，不让历史 Renderer、旧配色或固定动画参数覆盖当前 Compose 行为。
7. 只把无法自动完成的现场或主观判断交给用户，并写清触发动作、预期画面和需要的证据。
8. 交互渲染验证区分物理输入、组件接受 Press 和动画终态：滚动父容器可能延迟 Foundation Press，边界反馈必须在 Initial pass 的真实 DOWN 锁存资格、base、颜色和当前手势凭据，后续 pending／actual 重组不能改写已接受 Ripple；终态像素采样先确认扩散进度到终点。圆角裁剪使用真正处于轮廓外的点，不把仍在圆弧内的点当成角外。生命周期回归包含不经过中间重组／帧的暂停再恢复，验证停止事件直接取消任务，不能只测正常逐帧路径。依据和实例见[车控与 Ripple 验证记录](../../testing/车控与Ripple改造验证记录-20261003.md)。
9. 状态／循环契约变化时同步校正预览替身与测试的原始 actual、known 和 target 断言；新增测试保留相邻原方法声明，再以真实编译与完整报告确认，不把括号计数、存在测试文件或只跑新用例当作全量通过。适用本机验证，不替代实车读写和可逆恢复证据。
