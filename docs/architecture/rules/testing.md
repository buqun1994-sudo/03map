# 验证规则

1. 静态检查必须先于安装：包名、版本、入口、权限、签名和 ABI 均可追溯。
2. 默认验证闭环为静态检查、最小构建，以及在安全门禁内的保留数据覆盖安装、启动和最小日志检查；用户当次要求优先。
3. “应用已安装”不等于“分屏地图可用”；必须同时看到目标进程、地图界面或 SurfaceView、分屏 / Surface 证据和无致命异常。
4. 设备离线、系统授权未完成或 APK 身份冲突时记录为客观阻断，不用清数据或改成未知签名掩盖。
5. 每轮只把最后无法自动完成的一小段交给用户，并写明触发动作、预期画面和返回证据。
6. 同类内容区视觉偏差再次出现时，设计稿不能仅提炼色值和控件尺寸：施工前还要记录无框／阴影／填充、文字重量、结构层级、缺席的冗余控件及不属于功能数量的占位内容；施工后必须在相同画布上输出关闭／展开等关键状态的同屏对照和差异清单。功能测试与签名包级通过不得代替视觉合格；设备离线不阻止本机视觉门槛执行。仅对有正式视觉原型的任务适用，不把示意数据或重复占位卡当成需要实现的功能。
7. 内容区可复用交互规则：所有可点控件都通过 `ContentRenderer.bindPressEffect()` 复用同一按压令牌；36px 图标的媒体／来源／Dock 按下视觉容器固定为 `72×72px`，`PRESS_CORNER_PX=24`，是平滑高圆角矩形而不是圆形，容器负责按下态、父按钮负责热区；快捷卡沿用同一按压状态规则但保留卡片自身填充。媒体播放、下一首、来源、快捷卡和 Dock 必须在 `ACTION_DOWN` 显示按下背景、在 `ACTION_UP/CANCEL` 恢复常态，来源按钮常态不得有固定背景。卡片、滑条、媒体来源按钮和 Dock 底座统一复用同一方向性轻阴影绘制，不在公共圆角函数中追加普遍描边；为滑条等容器增加阴影时，必须核查从自身到父容器的裁剪链，并对底部越界像素做宿主帧断言，不能仅凭背景 Drawable 类型宣称阴影可见。媒体来源菜单按统一竖向热区布局，图标与文字是一组，固定 `88×88px` 正方形热区内居中，项目间隔 `12px`、边距 `6px`，弹层高度必须满足 `边距×2 + 热区×4 + 间距×3`、宽度满足 `边距×2 + 热区`。车控按钮必须先更新 pending 目标态并发送命令，再异步等待快照确认，连续点击以 pending 目标态为下一次输入；按摩开启顺序固定为确认 `0x241=2`、模式 `0x245` 在 `1–5`、强度 `0x243` 在 `1–3`，再写目标强度 `0x243=1/2/3`，关闭只写 `0x241=1`；不得用回读延迟点击反馈，也不得用长按弹出未定义的编辑列表。主题以高德自身为唯一真值：`ContentRuntime.readInitialAmapTheme()` 直接调用 `GAdaAndroid.nativeIsNightMode()`，`GAdaAndroid.onDayNightChange(I)` 直接转发 `ContentRuntime.onAmapThemeChanged(I)`；不保存主题偏好、不读取系统 `uiMode`，Activity attach／resume 只重新读取高德值。
8. 深色视觉令牌固定为背景 `#0F0F0F`、普通表面 `#1A1A1A`、提升层 `#232323`、选中层 `#2D2D2D`、按下层 `#414141`；宿主截图必须同时断言背景精确值和由暗到亮的层级顺序，禁止在 Renderer 或控件中散写第二套深色常量。
