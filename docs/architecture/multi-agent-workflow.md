# 多 Agent 协作

独立审查、文档梳理、研究、验证或互不重叠的施工可委派并行，主 Agent 负责采纳、整合和最终交付。

## 分工

任务单说明目标、相关文件、已有改动、关键依赖和预期结果。按实际任务选择只读或施工角色，不要求每个角色只具备固定动作。

- 独立文件和无共享可变状态的检查可以并行。
- 同一文件的写入、同一设备的操作、共享构建输出等存在顺序依赖时，指定单一执行者或串行协调，避免相互覆盖。
- 包名、签名、权限、密钥等主题本身不禁止并行审查；实际修改按依赖和用户目标安排，敏感信息仅传递必要内容。

各 Agent 提供实际发现、改动、验证和未解决项。主 Agent 在整合时处理文件冲突和证据不一致，并完成与本轮改动相关的检查。

个人风险和已有授权统一见 [安全与密钥边界](../security/安全与密钥边界.md)，不因多 Agent 分工增加确认门槛。
