# 多 Agent 编排协议

## 1. 使用范围

本协议只约束需要并行只读审查、文档梳理或互不重叠验证的任务。它不替代主 Agent 的架构判断、用户授权或最终收尾；当前地图基线重建任务默认由单 Agent 顺序完成。

## 2. 可以并行的场景

1. 只读审查：一个 Agent 检查 APK / 代码地图，主 Agent 决定是否采纳。
2. 文档梳理：按互不重叠的目录分区读取和汇总。
3. 验证：只读验证 Agent 运行已有检查并整理失败原因，不扩大修改范围。
4. 独立施工：文件范围、物理锚点和验证命令完全独立时才允许并行。

## 3. 禁止并行的场景

1. 同一关键文件或同一 Smali 类型的大规模编辑。
2. 包名、签名、权限、密钥、设备数据、发布和提交决策。
3. 安装、卸载、清数据、重启车机、悬浮广播或其它设备写操作。
4. 代码地图主索引、基线清单或根约束的最终合并。

## 4. 角色和任务单

主 Agent 负责实现、整合和最终交付；审查 Agent 只读 review；验证 Agent 只运行既有检查；文档 Agent 只改明示的文档范围。

每个任务单必须写清：目标、允许修改范围、禁止修改范围、必读文档、验证命令和输出格式。输出至少包含改动、验证、风险和未处理项。

## 5. 合并顺序

先审查，再施工，再验证，最后由单一收尾流程整合。发现同文件冲突、源码与代码地图不一致或验证失败时，停止并回到主 Agent 定位根因，不把失败状态直接交给用户。
