# 项目长期总纲

## 1. 文档定位

本文是 `03地图` 进入正式施工后的系统级真值。它定义输入 APK、当前产品目标、业务主链、代码地图职责、工具边界和验收不变量；不把未验证的实验实现写成完成事实。

## 2. 项目身份与重建边界

1. 项目面向 iCAR 03 车机壁纸状态下的全屏动态分屏地图导航。
2. 当前工作不是重新开发地图引擎，也不是继续维护实验报告，而是从已确认的高德 9.5 输入 APK 建立可持续施工的正式工程入口。
3. 不新增 Android 壳应用，不重新实现地图渲染、路网、定位或车道级数据服务；优先复用高德自身地图能力。
4. 历史 `480×480` 悬浮地图保留为可继续研究的支线；新对话不得把它当作当前默认布局、验收尺寸或施工入口。
5. 内容区底层架构以 [内容区主链](内容区主链.md) 为专项真值：同 APK 内集成，Activity 生命周期挂载，动态 View 宿主，页面 / 控制区 / Dock 由统一状态主链驱动。

## 3. 正式输入基线

1. 当前所有 APK 修改都从 `apk-archive/9.5.0.600013/` 中保存的高德 `9.5.0.600013`、125% UI、默认全屏 APK 开始。
2. 正式源码入口是 `source/amap-9.5.0.600013/`；正式施工副本是从该快照复制到被忽略的 `apk-work/9.5.0.600013/decode/`。
3. 用户提供的上游 APK 与当前输入基线包名、版本、SDK、权限和 Smali 数量一致；当前基线的真实代码改动集中在：
   - `AndroidManifest.xml`：`resizeableActivity` 从上游的 `true` 改为 `false`。
   - `smali/rv.smali`：`C()I` 增加无效值回退，并将密度按 `5/4` 计算。
   - `smali/kc.smali`：`v()V` 改为消费 `rv.C()I`，把自定义密度注入 `DisplayMetrics`。
   - `res/drawable*`：一批 UI、导航、Widget 和转向图标资源不同；`res/values/attrs.xml` 只有枚举顺序差异，语义集合一致。
4. 上述差异是输入基线身份的一部分；后续施工不能误把用户提供的上游 APK 当成当前基线，也不能从历史魔改包反推正式源码。

## 4. 当前正式产品目标

1. 地图承载形态为全屏动态分屏；默认内容区占 `1/3`，地图区占 `2/3`。
2. 内容层铺满全屏，地图作为固定宽度的右侧面板覆盖在内容层之上；地图收放只改变面板横向位置，不压缩面板宽度。
3. 启动时直接进入展开态，不允许先显示其它本体页面，再通过透明、alpha 为零、预览隐藏或延迟搬运来掩盖启动过程。
4. 本轮沿用输入基线的 `125%` UI 密度，不修改 UI 密度链。
5. 内容区背景跟随系统亮暗主题；车机主题色只为未来内容控件保留，不改变当前中性色手势条。
6. 手势条只处理横向拖动，视觉长度为物理 `256px`；展开态位于分界处，收起态位于屏幕最右侧。
7. 内容/地图比例由单一动态参数计算，后续允许用户调整；比例变化必须同步两条 Surface 和 native 布局链。
8. 2D 车首、2D 北上、3D 车首三种视角都必须保持正确的视觉焦点；裁剪或布局变化不能引入相机偏移。

## 5. 业务主链

1. **输入基线与显示密度**：`rv.C()I` → `of.a(Context)I` → `kc.v()V` → `DisplayMetrics`；这是 UI 顶层密度链，不是地图引擎相机或车标缩放链。
2. **启动与 Surface 接管**：Manifest 的 `UsbFillActivity` / `MainMapActivity` → `LifecycleCallbacks` → `AMapViewManage`；当前源码会在 Activity 生命周期中取得地图和 UI 两条 Surface，正式目标要求把悬浮显示时机前置到启动主链。
3. **全屏分屏与手势**：全屏 Activity 根布局的内容层、地图面板几何和独立手势热区共同决定展开/收起；历史 `ApplicationInitialization` / `ControlReceiver` / `FloatWindowsManage` 悬浮广播链只作为 `480×480` 支线保留。
4. **地图与 UI Surface**：`main_map_view.xml` 定义 `map_surface`、`ui_surface`、`cover`；分屏几何必须同步两条 Surface，`MapSurfaceView.surfaceChanged()` 把实际 Surface 尺寸交给 native，`MapSurfaceViewEx` 负责 callback 复用。
5. **视口与相机**：分屏面板宽度、Surface buffer、父容器裁剪和 `e2.onWindowFocusChanged()`、`rv$b.onLayoutChange()` 的 `nativeOnLayoutChange(III)` 共同决定 native 看到的逻辑尺寸；在三种视角上必须先对齐这条链，再判断是否存在引擎内部相机参数问题。
6. **地图层车标与文字**：静态入口包括 `MapSurfaceView`、`GAdaAndroid.nativeOnLayoutChange(III)`、`assets/res/HmiRes/MultipleScreen.json` 和 `assets/res/HmiRes/CarLogo_Style/`；倍率最终是否由 native 配置生效，必须以运行证据确认。
7. **内容区主链**：`MapApplicationProxy.onCreate()` → 内容生命周期桥接 → `ContentRuntime.attach(MainMapActivity)` → `ContentHost` → `StateStore / Reducer` → `ContentPresentationCoordinator.presentationProgress` → 派生 UI 状态 → 顶栏、页面、控制区、Dock Renderer；内容区只能订阅 `SplitPanelController` 的地图几何，不能成为第二个地图几何 owner。详细边界见 [内容区主链](内容区主链.md)。

## 6. 代码地图不变量

1. 代码地图的目的，是让后续需求可以从业务描述直接找到逻辑主链和精确源码文件，不需要在 7,000 多个 Smali 文件中重新盲搜。
2. 每个地图条目至少写清：业务问题、owner、精确相对路径、方法签名、上游、下游、已确认行为、未确认推断、APK 身份和验证方式。
3. `source/amap-9.5.0.600013/` 是源码真值；`apk-work/` 是施工副本；`.tmp/` 只提供已标记的历史线索，不能替代当前源码。
4. 发现新的高价值入口时，同一轮更新 `docs/code-map/主链索引.md`；发现地图与源码不一致时，先修正文档和根因，再施工。

## 7. 正式验收不变量

1. 包身份、版本、签名和输入基线可由静态工具复核。
2. 启动首帧直接进入全屏分屏展开态，不出现其它本体页面闪现或透明遮掩。
3. 默认内容/地图宽度为 `1/3 : 2/3`，比例参数可计算、可扩展，收放时地图面板宽度不变。
4. 手势条只响应横向拖动，展开态和收起态均可操作，地图导航状态持续存在。
5. 内容背景正确跟随亮暗主题，手势条保持中性色。
6. 三种视角均无由 Surface 布局、buffer 或裁剪引入的相机偏移。
7. 比例变化、地图收放和再次展开后，两条 Surface、native 视口和地图状态保持一致。

## 8. 当前施工边界

1. 不修改用户提供的原始 APK，不修改正式源码快照，不把临时构建产物写入 Git。
2. 不修改包名、商业服务授权链、车辆控制接口或 native `.so`，除非后续形成独立且有证据的施工方案。
3. 不恢复历史 `480×480` 悬浮布局作为当前主链，不引入固定地图缩放级数或透明本体窗口方案。
4. 不把外部 `03歌词` / `03投屏` APK 嵌入高德；只在本项目内重写其逻辑和适配边界。
