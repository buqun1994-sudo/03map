# 验证矩阵

> **职责：** 规定当前全屏动态分屏的静态、构建、安装、启动、日志和最小人工证据。实现细节见代码地图，历史包结果见进度或归档。

## 1. 默认验证策略

用户没有另行要求时，完成工程行为变更后按以下顺序由 AI 主动执行：

1. 文档 / 语法级检查。
2. 与改动直接相关的最小构建或 APKTool 回编。
3. 保留数据覆盖安装、启动、进程检查和最小日志 / 窗口证据。
4. 若改动涉及界面、窗口、手势、导航或启动，再执行当前候选包的运行级分屏 smoke。
5. 只有设备连接、系统弹窗、缺失输入或具体个人风险超出已明确目标时才请求用户介入；已有授权不逐步骤重复确认。

用户当次要求优先；不得以默认策略覆盖用户明确的验证范围。

### 按改动选择本机验证

统一入口为 `node scripts/validate-content.mjs`，参数、报告及缓存边界见[构建与验证入口](<../operations/构建与验证入口.md>)。先使用 `--plan`查看所选模块；默认根据当前 Git 已跟踪／未跟踪改动和实际 Gradle 依赖图选择，不固定“三／四模块”。

| 改动 | 开发中最小检查 | 收敛或整合检查 |
|---|---|---|
| 文档、规则、索引 | 相关静态自检与diff；`--scope docs` | 不要求Gradle、APK或设备 |
| 模型、循环、解析、Store／Port | 先编译相关测试，再执行定向合同；`--module`可精确重跑失败owner | 共享契约按实际消费者扩展；`--scope model`包含下游 |
| UI状态、主题、绘制、动效 | 相关测试类与必要实际帧 | 相关模块测试／Lint；几何、字体、主题或native改变时选择密度／双主题／API矩阵 |
| Host、生命周期、模块／依赖配置 | 宿主与受影响消费者 | 稳定整合一次 `--scope all --lint`，包含所有当前模块 |
| 打包脚本／资源／DEX注入 | 脚本专用测试和正式构建／包核验 | 同一稳定源码核对最终签名APK；不隐式重复源码回归 |

编译错误先重跑对应测试编译，断言错误先重跑失败类，Lint错误先验证受影响Lint；通过后才扩大到上述相关范围。日常保留Kotlin增量与Gradle有效缓存，不为获取fresh XML执行clean或强制rerun。报告区分“本次执行／缓存复用／未执行”；过滤用例不称整个模块或全工程通过。

源码回归绑定源码／构建配置指纹，包级核验绑定最终APK SHA-256。`bash scripts/test-content-host.sh "$SIGNED_APK"`仅核验签名／包身份／DEX等，不启动Gradle、不执行车机地图；源码在执行期间改变时报告失效并重新从稳定快照验证。下文专项按改动信号触发，历史轮次的全量数量与门槛不累加为每轮默认要求。

## 4. 默认运行检查

默认由发现脚本获取当前车机 serial，核对目标身份、`device` 状态和覆盖兼容后使用 `adb install -r`。失败后诊断，不自动卸载、清数据或降级；旧 IP 或 serial 需重新核验身份后才能用于设备操作：

```sh
VEHICLE_ADB_SERIAL="$(node scripts/find-vehicle-adb.mjs --serial-only)" || exit 1
"$ADB" devices -l
"$ADB" -s "$VEHICLE_ADB_SERIAL" install -r "$SIGNED_APK"
"$ADB" -s "$VEHICLE_ADB_SERIAL" shell am start -n "$ENTRY_COMPONENT"
"$ADB" -s "$VEHICLE_ADB_SERIAL" shell pidof com.autonavi.amapautolite
"$ADB" -s "$VEHICLE_ADB_SERIAL" shell dumpsys window windows
"$ADB" -s "$VEHICLE_ADB_SERIAL" exec-out screencap -p > "$RUNTIME_DIR/分屏首帧.png"
"$ADB" -s "$VEHICLE_ADB_SERIAL" logcat -d -v threadtime -t 300 \
  | rg 'FATAL EXCEPTION|AndroidRuntime|amap|SplitPanel|WindowManager'
```

证据至少包括：目标进程存活、真实地图界面可见、分屏窗口 / Surface 信息和无致命启动异常。原始日志和截图先留本机，需要入库或分享的片段按实际内容脱敏；普通错误摘要、截图和路径不自动作为敏感数据。

是否确认取决于具体个人风险和已有任务范围，见 [安全与密钥边界](../security/安全与密钥边界.md)。保留数据安装、Release、instrumentation 和广播不按名称设门槛；数据损失、导航中断、实体车辆误动作等超出已明确目标时才说明后果并确认。用户已要求的实车控制验证及恢复不逐项重新授权。

以下按本轮改动涉及的行为选择检查。声明整个分屏能力已验收时须有完整证据；单项修复或纯文档任务不额外执行无关全量验证：

1. **冷启动首帧：** 直接进入展开态，没有其它本体页面、透明遮掩或延迟搬运。
2. **默认几何：** 内容区约 `1/3`、地图区约 `2/3`；两条 Surface 与内容层一致。
3. **地图收起：** 手势条横向拖动后，地图保持固定宽度整体移出，内容区露出全屏。
4. **地图恢复：** 从最右侧反向拖动，地图完整拉回，导航、定位和控件状态保持。
5. **中途接管：** 动画过程中再次抓取，从当前视觉位置继续，不跳回端点。
6. **手势边界：** 单击、长按、垂直拖动和错误方向不触发地图收放或系统动作；单击提示只出现一次。
7. **主题来源：** 内容区主题跟随高德自身主题回调，不读取系统 `uiMode`，切换不影响地图 Surface。
8. **页面和内容：** `shortcuts → lyrics` 页面吸附、媒体 / 空调切换、Dock 入口和默认主页符合产品基线；两页两卡在每次切换、面板收放和宽度变化后回读实际 viewport 与项宽，二者相等；外层无边距，内容边距在项内，稳定态当前项右侧不裁断且邻项 `0px` 外露。
9. **地图视角：** 依次验证 `2D 车首`、`2D 北上`、`3D 车首`，确认没有由分屏裁剪导致的相机偏移。
10. **重入：** 收起、恢复、Activity 重建和再次启动后，页面、偏好、地图状态和主题不丢失。
11. **底层证据：** 条件允许时记录 View frame、Surface 回调尺寸、Layer / buffer、裁剪区域和 native layout 参数；不能只凭父容器动画下结论。
12. **按钮反馈：** 在本轮目标覆盖的控制范围内分别观察按下当刻的触控／动画反馈、等待提示、真实状态回流及失败／超时；反馈不得等待服务返回才启动，也不得在回读前假定成功。设备离线时只记静态风险，不冒充实机交互通过。
13. **充电只读：** 同一候选包先在未插枪及已插枪场景观察连接、BMS、预约原始值变化和顶栏文案；实际充电仅在车机自然进入充电状态时核对，`BMS=3` 才显示充电中，`6/1` 的预约等待需现场状态对照，未知组合保留原始值和待确认，不进行充电车控写入。
14. **SVG 内容区复刻专项（2026-09-29 交互返工，本机通过、车机待验）：** 本机定向宿主分别触发默认／插枪／预约／充电／未知状态，单行顶栏不得重叠、换行或以 `kWh` 表示功率；默认时间的可视中心落在内容区几何中线（640px 参考帧偏差 `≤4px`），右侧显示真实剩余里程数值／无数据 `--` 并附弱化 `km` 单位和电池，**无“续航”前缀**；温度、时间、里程采用较高字重，单位弱化；非默认时间最左，状态位于数值前。快捷页不得出现“设置暂不可用”横条和页码圆点；亮度／音量滑条的文字位于图标下方，填充从底部到顶部，松手一次提交目标值，拖动和取消不写入；座椅通风／加热／按摩点击立即显示 pending 目标档位，连续点击可从 pending 档位继续发下一条命令，回读只确认／失败，不阻塞 UI；滑条不与按摩命令共用。五种音乐来源逐项核对原厂图标与完整名称，来源弹层统一竖向热区、图标在上文字居中在下；快捷卡、滑条、控制卡、来源按钮、Dock 底座均有统一轻阴影，36px 图标按下背景为 72px 平滑圆角；Dock／快捷按钮长按不弹未定义列表，后续编辑态另行施工。左侧按系统密度复核原型四列间距和留白，地图 125% UI 密度不得改变左侧物理尺寸，主题跟随高德回调并在重建后重新同步。五种音乐来源菜单、按钮、滑条／顶栏及主题动画核对起中末帧、重复状态与停播。
15. **SVG 视觉门槛（必须先在本机通过）：** 同画布渲染两张原型与同候选的关闭／展开帧，并排及半透明叠图核对顶栏位置与字重、浅灰／白底、柔和阴影、没有逐卡 `1dp` 轮廓、唯一媒体内分隔线、一体式横向媒体卡、整体 Dock 与选中底色。固定媒体卡／Dock 外边和顶栏中线在 640×1080 参考帧的偏差 `≤4px`；排除示意数据、图标、重复占位功能后的可比区域，仍须逐项记录视觉差异，**不能只凭“能显示”“不重叠”或 12/12 自动化通过**。再按实际 `DisplayMetrics` 与 `640/960/1280px` 内容宽度核对触摸热区和可读性；高密度窄幅帧中的短状态和来源名称不能因横排压缩而消失，本机图不冒充车机截图。任何统一外框、双排媒体卡、多余设置横条或页码点均判失败，不得把视觉验证推给用户上车后才发现。设备在线且任务包含运行验证时执行新包检查，真实车控按本轮目标及个人风险口径处理；[本轮本机验收](SVG内容区视觉返工验证记录.md) 与 [旧哈希视觉失败](SVG内容区复刻验证记录-20260928.md) 分别保留。
16. **当前自动动效、副驾与快捷交互专项：** 本机状态矩阵覆盖方向盘关闭／2／1／AUTO、主副驾加热各自关闭／3／2／1／AUTO、字段失效与断连；所有循环经过默认正式Port、真实Adapter＋独立命令码／回报Binder替身，副驾只发0x213／area0，auto0x34a只读。验证自身实际确认、主副独立能力／复制、拒绝／权限／断连／6秒超时／迟到及唯一pending，不能借主驾或预览确认副驾。自动实际热级变化保持AUTO；按钮只发送自身目标，通风／加热处理归原车。快捷页及六项Dock核对完整名称、左右专用资源、四列／纵向控件布局及48dp热区；五类多态只在0↔on边界Ripple，锁底色保持。主副AUTO与wheel采用同一skin家族Lottie，各mode初中末帧都可实际绘制，one-shot结束保留尾帧；同Composition日→夜→日核对resource／asset／ready／playing及像素，不重播。按摩第二wave在各档中帧必须功能紫，原厂透明度／几何保留；车锁真实点击→pending→unknown／known回报→确认以及UP／时钟／调色更新不能提前跳尾，历史有效播放器与当前代码对照。独立palette与原有Ripple／冷加载／生命周期合同持续回归，实际Canvas帧不能当作车机截图。新包用户上车步骤、候选与证据见[动效与副驾修正](<自动加热动效与副驾入口修正验证记录-20261004.md>)；上一整合结果保留在[真值架构记录](<车控真值架构与主题重构验证记录-20261003.md>)。


车控是正式产品能力，按研究文档中的已验证入口逐项施工和验收；每项能力的验收须形成以下闭环。入口是否可用由当前连接、自身有效模式、已实现目标和pending决定，现场待验记录在证据中，不作为永久禁用：

1. **读取 / 订阅：** 正式 APK 通过 `VehicleAdapter` 获得目标状态、有效性和变化回调。
2. **命令执行：** 页面只发送稳定业务命令，由 `VehicleCommandPort` 选择 `CarPropertyManager`、车机 Binder 或其它已验证入口。
3. **结果回流：** 成功、拒绝、权限不足、服务断连和超时都回到统一状态，UI 不以调用返回值直接判定成功。
4. **可逆恢复：** 写入测试记录初始状态、目标请求、车辆状态回流和恢复结果；无法安全恢复时不得继续扩大测试范围。
