# 验证矩阵

> **职责：** 规定当前全屏动态分屏的静态、构建、安装、启动、日志和最小人工证据。实现细节见代码地图，历史包结果见进度或归档。

## 1. 默认验证策略

用户没有另行要求时，完成工程行为变更后按以下顺序由 AI 主动执行：

1. 文档 / 语法级检查。
2. 与改动直接相关的最小构建或 APKTool 回编。
3. 在安全门禁内保留数据覆盖安装、启动、进程检查和最小日志 / 窗口证据。
4. 若改动涉及界面、窗口、手势、导航或启动，再执行当前候选包的运行级分屏 smoke。
5. 只有设备离线、系统弹窗、签名 / 包身份冲突或明确高风险动作需要用户确认时，才把最后一小段交给用户。

用户当次要求优先；不得以默认策略覆盖用户明确的验证范围。

## 2. 文档与基线检查

```sh
node --check scripts/check-project-docs.mjs
node --check scripts/check-skills.mjs
node --check scripts/check-code-map.mjs
node scripts/check-project-docs.mjs
node scripts/check-skills.mjs
node scripts/check-code-map.mjs
git diff --check
```

必须确认：

- 当前主线仍是全屏动态分屏，历史 `480×480` 不进入当前验收。
- 输入 APK、包名、版本、证书和 `ac6033c` 中的原始解包快照与 [基线清单](../code-map/基线清单.md) 一致；当前 `source/amap-9.5.0.600013/` 是持续演进的可版本化施工源码，不再要求与原始快照哈希相同。
- 新源码入口已写入 [主链索引](../code-map/主链索引.md)，证据等级没有被夸大。

## 3. 静态与构建层

| 用例 | 动作 | 必须证据 |
|---|---|---|
| 输入身份 | 核对归档 APK SHA-256、包名、版本、ABI、权限、证书和快照边界 | 与基线清单一致 |
| 施工归档边界 | 可在被忽略 `apk-work/` 实验，但提交前全部有效 Java / Smali / Manifest / 资源改动进入正式 `source/`；生成物不入库 | `diff` / 哈希回读、`git diff --cached`、忽略规则；原始基线仍能从 `ac6033c` 回读 |
| 可重建性与强制签名 | `bash scripts/build-content-apk.sh` 只从正式 `source/` 编译 Java / D8、回编 APKTool、对齐并签名；缺密钥 / 证书或证书不匹配时预检失败 | 只交付 `signed.apk`；Manifest、`classes.dex`、`classes2.dex`、包身份、63 个 `.so` Deflate、单 signer、v2 和已测试证书 SHA-256；无未签名交付包 |
| 业务锚点 | 按主链索引回读启动、分屏几何、手势、两条 Surface 和 native layout owner | 文件 / 方法签名匹配 |
| 语法 / 资源 | APKTool 回编或对应最小编译，回读 Manifest、Smali、资源 | 无汇编、资源和项目包含错误 |
| 包身份 | `zipalign`、`apksigner verify`、`aapt2 dump badging/permissions`、签名后 round-trip | 包身份、签名和原生库压缩符合本轮授权 |
| 启动静态链 | 核对 launcher、全屏根布局、`map_surface`、`ui_surface`、手势热区和配置分支 | 不依赖透明页面、延迟搬运或固定缩放伪装分屏 |

## 4. 安全门禁内的默认运行检查

以下属于默认低风险检查：设备处于 `device` 状态、候选包身份允许覆盖安装、使用 `adb install -r`，不卸载、不清数据、不降级：

```sh
"$ADB" devices -l
"$ADB" -s "$VEHICLE_ADB_SERIAL" install -r "$SIGNED_APK"
"$ADB" -s "$VEHICLE_ADB_SERIAL" shell am start -n "$ENTRY_COMPONENT"
"$ADB" -s "$VEHICLE_ADB_SERIAL" shell pidof com.autonavi.amapautolite
"$ADB" -s "$VEHICLE_ADB_SERIAL" shell dumpsys window windows
"$ADB" -s "$VEHICLE_ADB_SERIAL" exec-out screencap -p > "$RUNTIME_DIR/分屏首帧.png"
"$ADB" -s "$VEHICLE_ADB_SERIAL" logcat -d -v threadtime -t 300 \
  | rg 'FATAL EXCEPTION|AndroidRuntime|amap|SplitPanel|WindowManager'
```

证据至少包括：目标进程存活、真实地图界面可见、分屏窗口 / Surface 信息和无致命启动异常。完整日志、截图、设备 serial 和个人信息只留在临时目录。

以下动作不是默认动作，需当次明确授权：卸载、清数据、降级、改包名或正式签名、重启车机、安装 Release、instrumentation、暂停无障碍、执行车控写入或恢复历史悬浮广播。车控写入还必须满足车辆处于可控状态、单目标变更、状态回读、可逆恢复和最小日志留证。

## 5. 当前分屏运行级 smoke

以下是当前全屏动态分屏的必须通过项；失败任一项都不能宣称本轮完成：

1. **冷启动首帧：** 直接进入展开态，没有其它本体页面、透明遮掩或延迟搬运。
2. **默认几何：** 内容区约 `1/3`、地图区约 `2/3`；两条 Surface 与内容层一致。
3. **地图收起：** 手势条横向拖动后，地图保持固定宽度整体移出，内容区露出全屏。
4. **地图恢复：** 从最右侧反向拖动，地图完整拉回，导航、定位和控件状态保持。
5. **中途接管：** 动画过程中再次抓取，从当前视觉位置继续，不跳回端点。
6. **手势边界：** 单击、长按、垂直拖动和错误方向不触发地图收放或系统动作；单击提示只出现一次。
7. **主题来源：** 内容区主题跟随高德自身主题回调，不读取系统 `uiMode`，切换不影响地图 Surface。
8. **页面和内容：** `shortcuts → lyrics` 页面吸附、媒体 / 空调切换、Dock 入口和默认主页符合产品基线。
9. **地图视角：** 依次验证 `2D 车首`、`2D 北上`、`3D 车首`，确认没有由分屏裁剪导致的相机偏移。
10. **重入：** 收起、恢复、Activity 重建和再次启动后，页面、偏好、地图状态和主题不丢失。
11. **底层证据：** 条件允许时记录 View frame、Surface 回调尺寸、Layer / buffer、裁剪区域和 native layout 参数；不能只凭父容器动画下结论。

## 6. 车控适配验证

车控是正式产品能力，按研究文档中的已验证入口逐项施工和验收；每项能力必须形成以下闭环后，才可从不可用 / 预览提升为可用：

1. **读取 / 订阅：** 正式 APK 通过 `VehicleAdapter` 获得目标状态、有效性和变化回调。
2. **命令执行：** 页面只发送稳定业务命令，由 `VehicleCommandPort` 选择 `CarPropertyManager`、车机 Binder 或其它已验证入口。
3. **结果回流：** 成功、拒绝、权限不足、服务断连和超时都回到统一状态，UI 不以调用返回值直接判定成功。
4. **可逆恢复：** 写入测试记录初始状态、目标请求、车辆状态回流和恢复结果；无法安全恢复时不得继续扩大测试范围。
5. **证据边界：** 研究探针证据可以指导施工，但不能替代正式 APK 的权限、生命周期、错误回流和 UI 运行证据。

## 7. 交付记录格式

每轮交付只记录：候选包身份、实际执行的检查、结果、证据位置、客观阻断和剩余最小人工项。历史 `480×480` 验收、S191 静态样本和旧候选包只能作为参考，不能替代当前候选包证据。
