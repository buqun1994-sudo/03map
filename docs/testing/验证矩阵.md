## 3. 用户手动安装后的运行级 smoke

以下项目由用户安装候选包后手动执行；AI 不在本轮自动安装、卸载、清数据或修改设备状态。每一项均为当前分屏目标的**必须通过**项：

1. **冷启动首帧**：从车机入口启动，直接出现全屏分屏展开态，没有其它本体页面、透明遮掩或延迟搬运。
2. **默认分屏几何**：内容区为屏幕宽度约 `1/3`，地图区为约 `2/3`；内容区背景正确跟随当前亮/暗主题。
3. **地图整体收起**：向右拖动 03桌面式透明触摸带中的手势条，手势条位于地图边界的内容侧并随边界连续移动；地图保持原面板宽度整体移出，地图不压缩、不重建，内容区露出全屏。
4. **地图整体恢复**：从右侧手势条向左拖动，手势条与地图面板同步跟手，地图完整拉回；地图导航、定位、控件和相机状态保持。
5. **手势边界**：手势条只响应横向拖动；单击、长按和垂直滑动不触发其它系统动作，也不误触地图。
6. **单击提示**：展开态单击显示“向右拖动收起地图”，收起态单击显示“向左拖动展开地图”；渐变底托与文字同步淡入，文字缓慢左右往返约 3 次后渐隐，不触发收放或系统动作。
7. **速度/距离收放**：慢速长距离拖动、快速短距离拖动、短距离慢速释放分别验证吸附方向；最终只停在展开态或收起态。
8. **中途接管**：动画进行中再次抓取手势条，从当前视觉位置继续拖动，不跳回端点。
9. **地图视角**：分别验证 `2D 车首`、`2D 北上`、`3D 车首`，确认分屏裁剪没有造成相机中心或方向偏移。
10. **Surface 证据**：条件允许时记录两条 Surface 的 View frame、回调尺寸、Layer/buffer、裁剪区域和 native layout 宽高；不能只凭父容器动画判断地图正确。
11. **再次打开**：收起、拉回、重新启动各至少一次，确认比例、地图状态、手势条、提示和主题背景保持一致。

任一必须通过项失败，不能宣称当前分屏目标完成；桌面打包通过只代表候选包可安装解析，不代表交互验收通过。

### 3.1 `fix4` 人工验收结果（2026-09-24，未通过）

1. 默认分屏拖拽时，可见手势条异常消失；地图收起后不可见，重新展开后恢复。不可见期间透明热区仍可点击；点击后可见条恢复，后续同类拖拽暂不复现。
2. 展开态点击提示缺少预期柔光渐变；文字渐显/渐隐存在，但左右弹跳出现疑似双层残影，且最右侧弹跳位置会与手势条重叠。
3. 收起态点击手势条会在两个固定位置同时出现提示文案。
4. 本次结果否定“可见条、热区、提示和地图位移已经由同一主链统一控制”的验收结论；下一轮施工必须先提交唯一状态机、唯一几何源和动画实例生命周期设计，再进入代码修改。

### 3.2 `fix5` 当前验证状态（2026-09-25，用户实机通过）

1. **静态通过：** 已回读 `main_map_view.xml` 的唯一 `hintText`、唯一 `gestureNode` 触摸入口和唯一 `panelHost` 位移 owner；`applyDividerX(F)` 的 `[expandedDividerX, screenWidth]` 边界、预测吸附分支、状态编号和提示动画取消链均已核对。
