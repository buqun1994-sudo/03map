# 巡航红绿灯沉浸顶栏验证（2026-10-11）

## 1. 本轮范围与产品合同

用户要求复用当前高德的巡航主链，在看不到地图的沉浸式全屏中显示下一路口的灯色和有效倒计时；普通分屏不显示灯组。原生地图、实际物理路口和内容区须对照同一批次，秒数接近不能证明状态正确。

状态栏设置的“沉浸式全屏”组保留“下个路口红绿灯”，默认开启，使用现有偏好文件的独立 `top_bar_show_cruise_signals` 键，schema 9 不变。只有“显示状态栏”开启时可设置；关闭状态栏置灰并保留选择。UI 与 Binding 接受事件处均检查门禁，并沿共用点击音效路径工作。

只有沉浸式全屏、状态栏开启、显示开关开启且收到新鲜有效巡航灯组时，灯组才进入既有时间／车况顶栏同一行；空批次不占位，顶栏分屏／全宽偏好继续有效。

## 2. 已确认根因与完整地图合同

修复前的 `ContentPorts.CruiseSignalSnapshot.fromMapRaw` 接受地图 DTO，却按 `0/1/2` 解码状态：原生红灯2被显示成黄色，红3／绿4、5、6／黄8被丢弃；未知方向被兜底为直行。这是确定的实现缺陷。旧测试也用旧协议的0/1/2验证地图 DTO，没有验证实际地图枚举。

本轮车机发现核验到 `S56_HQX / SDK28` 后，拉取现装包 SHA-256=`1c178e817cfe9ffb33095e40c51d1f748a2e8e48a8829af7a6624f26bcf31c6d`，与[对应构建报告](<../../apk-work/9.5.0.600013/source-build.OSsg1x/build-report.json>)一致。其 `libGbl.so` SHA-256=`e97c9a9b563c2b82d7a882a6e3952ee5229278471a8df8d3cd16ba1de2cfa63d`，匹配旧v1四字段桥；对应构建源码指纹为 `a95372b05ba41e113d7d2bdf8273371400c66c375e8048d93434c28d8bdc998b`。将本轮修复前的适配器方法恢复到只读内存后，完整 `ContentPorts.java` SHA-256=`5524449a1aa09852ba077c3ae1b656f8b4e3aaaa848dfdad33169d862a56b161`，与该构建输入记录相等，因此缺陷已绑定到现装包的构建输入。原始包、日志与比对结果保存在[修复前证据目录](<../../.tmp/cruise-device-before.uo7040ev/>)；当前读取的日志无信号批次，不能将此取证视为某次现场红灯的原始状态记录。

当前唯一生产主链：

`libGbl CruiseTrafficSignalLightDisplayInfoToJsonObject → native-patches/cruise-map.S → content-cruise-map.bin → ContentCruiseMapBridge Sink → ContentRuntime.acceptCruiseMapBatch → ContentStore.acceptCruiseMapSignals → ContentState → ContentUiMapper.cruiseSignals → ContentBinding / BoundContentPanel → ContentPanel / CruiseSignalBar`。

- 同步复制原生 DTO `+0x40 lightCount`、`+0xa8 sdType` 和 `+0x48/+0x50` vector，每项stride16：`showType / crossManeuverID / lightCountdown / status`。原 converter 重放首指令后无链接回跳 `0x19820c8`，继续原地图处理。
- 文件协议为小端v2、32字节头：magic `0x43534d31`、version2、pid、vectorCount、`CLOCK_MONOTONIC` ns、lightCount、sdType；随后最多16项四整数。原子临时文件替换；reader校验版本、长度、pid、模式、新鲜度和生命周期代际，不解释v1。
- 地图方向仅接受 `1=左、2=右、8=直`；原生状态 `2/3=红、4/5/6=绿、8=黄`。未知值及同方向歧义不猜测。内部0红／1绿／2黄仅是归一化后的UI合同。
- `showType=2` 为次灯且仅直行，`3` 为主灯。lightCount为1可接受主／次灯；lightCount≥2只显示主灯，lightCount0清空。
- 主灯status8只显示黄灯、不显示数字；主灯status6在 `sdType=false`（车道级）只显示绿灯，在 `sdType=true`（普通SD）保留正秒。次灯6/8保留正秒。倒计时≤0仅保留灯色，UI门禁统一为>0；999/99资源阈值是形状选择，不能据此删除秒数。
- 黄色绘制原先以绿色PNG乘黄色 `BlendMode.Modulate`，不能增加缺失的红通道。现以颜色矩阵将绿色强度映射为 `#FFB020`，保留原图透明度、环和明暗，方向箭头独立保持白色。红／绿与三方向原厂PNG不变；不将这份黄色变换称为原厂黄灯资产。
- legacy `CameraLightInteract → ContentRuntime.onCruiseSignalBatch` 仅用于诊断，旧HMI方向1左／2直／3右及status0红／1绿不得进入地图适配器。未调用且缺少完整显示资格的public地图回调已删除。
- 模式门禁仍使用 `AndroidWidgetNavi.isInCruise()`；不读语音缓存、悬浮窗文字或另建云接口。秒数和状态只跟随原生更新，不自行减秒，不因数字到零猜切灯。
- 空／null批次、导航模式转换、关闭偏好、停止绑定或销毁均清空；恢复只接收新批次。3000ms未更新整组隐藏是本地新鲜度保护，不是上游服务时延保证。
