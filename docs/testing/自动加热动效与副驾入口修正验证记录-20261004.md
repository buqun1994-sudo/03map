## 1. 用户反馈与根因

1. 座椅自动图标与手动档造型不同：旧`seatIcon()`自动分支选SystemUI的`ic_carset_seat_l_hot_auto_00_r_o` Vector，而手动档消费Launcher `ico_skin_seat_heat_l` Lottie，两者都来自车机，但属于不同原厂图标家族。原厂Launcher已有同源左／右AUTO动画，上一包遗漏了这两套自动资源。
2. 座椅自动与方向盘没有路径动效：旧`ShortcutOemIcon()`对整个SteeringHeat以及所有AUTO模式提前返回`animationAsset=null, animateOnAction=false`，静态旁路绕开共享Lottie消费者。原厂实际owner与帧段需以本轮资源核对为准，不能把静态Vector名称中的数字当作动画帧。
3. 副驾新增独立控制：既有研究14.4有副驾三档HAL值4的独立现场证据；本轮静态确认右按钮位置0／1／2／3／4分别调用`setRightSeatHeatVent(1／4／3／2／8)`。准确复合函数`0x213`、自动回报`0x34a`，area0、INT32，与主驾函数区分，禁止用主驾函数改区域猜副驾。
4. 名称统一为“座椅通风”“主驾座椅加热”“副驾座椅加热”“座椅按摩”；沿共享领域标签投影，不在页面与Dock分开维护一组简称。
5. 按摩第二条波浪线在动画中变白：旧消费仅改`color1/**/填充 1`的座椅轮廓，波浪线位于`color2..color11`的`描边 1`。其中2档第二条线t30黑→t31白→t37紫、3档第二条线t60黑→t61白→t67紫；仅改轮廓不能约束这些帧，全球中性色主题回调也不能决定功能紫色。修复须针对波浪线描边，保留原厂alpha／宽度／trim／路径，不把全图单色化。
6. 车锁路径动效消失：已读取Git `73693ca`有效播放器版本并与上一工作树对照，锁定／解锁资源及默认Lottie映射仍在。此前播放Effect把完整targetFrame调色配方作为key，同一业务动作遇调色变化会重启并跳尾；本机受控红对照只把最终时间轴key临时换回targetFrame，明暗两项中帧playing断言都复现失败，记录[validation.hqstkz](<../../apk-work/validation.hqstkz/report.json>)，随后已恢复源码SHA `43fd85a7e5a5035360073aee1546eeb3149ab8be7460a74ad03782da2bc7e7ee`。最终拆开asset／frames／mediaGlyph时间轴与调色配方，车锁只由displayed目标变化触发，按压／Ripple保持。正常已知actual→立即target→ACK→自身确认和未知pending→已知调色两条链均加入双向真实点击／中间进度／尾帧回归；普通已知确认并不必然调色，无现场逐帧trace不能把本机复现宣称为唯一实车根因。
