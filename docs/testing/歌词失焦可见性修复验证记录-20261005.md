# 歌词失焦可见性修复验证记录（2026-10-05）

## 1. 目标与边界

本轮只修复歌词呈现把窗口焦点误当作可见性的错误。`LyricsBodyTransition.rememberLyricVisibility()` 现在按四类事实决定歌词工作门禁：宿主生命周期至少为 `STARTED`、当前仍在歌词页、承载 View 已附着且 `windowVisibility == View.VISIBLE`、View 自身及祖先链 `isShown`。窗口焦点不再参与歌词呈现门禁；Ripple、OEM 动效、QuickControls 和氛围背景沿既有焦点语义保持。

API 28 没有公开的窗口可见性监听器，因此实现使用现有 Android traversal 的 `ViewTreeObserver.OnPreDrawListener` 采样，不请求额外帧、不 invalidate、不 post，也不创建 ticker。View 脱离窗口时立即清除可见状态并解绑旧 observer，重新附着时绑定当前 observer。窗口焦点状态只在回归夹具中建立 native 事实，用来证明失焦不会停止歌词。

本轮不打包、不安装、不连接车机；另一对话的设置、媒体和运行时施工保留在主工作树，不能用本次隔离回归替代整合树或车机验收。
