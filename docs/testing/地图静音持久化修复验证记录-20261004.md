## 2. 实现与唯一偏好

源码入口为[原生静音补丁](<../../source/amap-9.5.0.600013/native-patches/map-mute.S>)的 `map_mute_set`／`map_mute_init`／`map_mute_read_user`／`map_mute_save_user`，以及[有声选项补丁](<../../source/amap-9.5.0.600013/native-patches/map-mute-menu.S>)的 `map_mute_select_style`；原调用链与配置后端证据见[研究](<../research/地图播报静音持久化研究-20261004.md>)和[主链索引](<../code-map/主链索引.md>)。

唯一持久用户偏好是现有native Config用户层的 `icar03_user_mute`。原合并键 `mute` 可能被OEM功能／路径配置占用而拒绝写入，因此不把它当作可保证写入的用户owner；没有显式新偏好时完全沿用原来的配置／系统默认。两份用户偏好不会同时维护，运行时 `this+0x131` 仍由原播报引擎负责。

实际菜单静音回调 `0xa0cd64` 只把observer0标记为私有 `0x303`。静音hook消费标记、检查 `SetBool` 接受结果、`GetUserConfigBool`存在性和值、`Config::SaveData`结果，再以原observer0调用原函数；保存成功／配置未就绪／用户层拒绝／保存失败／已被新选择取代分别写 `IcarMapMute` 状态日志，不含路线或位置。真正失败仍执行当次用户动作；setter接受后回读已是新用户值时标记superseded并跳过旧运行状态。已接受RAM但写盘失败仍执行当次动作并复核更新选择，不把磁盘失败与新选择取代混合。同值点击仍重试保存。

四种有声选项的实际 `PlayStyle` 写点 `0xa08458/0xa0a3d4/0xa09e9c/0xa0996c` 进入明确意图wrapper：先执行原style写入，再保存普通静音false并解除；原写返回值保持。即使当前已经有声，也更新用户选择。旧UI随后重复发false是幂等动作，不以RAM相等跳过保存。

`InitSoundLevel()`先完成原初始化，再恢复存在的用户偏好。`SetMute`针对系统回流observer2、导航初始化observer4的false请求，在已保存true时直接阻止；系统零音量的true请求保留。observer6配置应用按存在的true／false投影。临时静音函数未打补丁，其他未标记协议不保存用户偏好；其当次运行状态允许沿原行为变化，之后的配置同步仍可能按用户偏好恢复。

用户动作保存成功及自动请求放行后会回读最新偏好，处理已验证的过时请求交错；最多四次原setter调用，持续变化时记录限次日志并退出。不跨原GAI／observer回调持锁，不把该有界收敛机制宣称为任意并发操作的完整排序保证。未标记临时／协议状态与连续真实重入仍需车机观察。

## 3. 可重建原生边界

[构建器](<../../scripts/build-map-mute-native.mjs>)仅在忽略产物目录编译ARM64汇编，原63个正式so输入未改。[补丁锁](<../../source/amap-9.5.0.600013/native-patches/map-mute.lock.json>)固定原SHA、入口原字节、调用地址、汇编SHA、payload大小／SHA／符号偏移、最终SHA。构建和包级核验共同重组预期ELF字节并比较，receipt不作为允许变化的授权。

| 目标 | 原库SHA-256 | 修复库SHA-256 | 新RX布局／payload |

PHDR迁入新增文件映射RX段，9项扩为10项；同步ELF头与PT_PHDR，完整表位于file-backed LOAD，按原0x4000对齐并越过完整BSS。保留原LOAD／NOTE／GNU_STACK／GNU_EH_FRAME／RELRO／dynamic／GOT；无W+X、新增DT_NEEDED或运行时重定位。两条hook的原函数首条栈指令由trampoline重放后跳原+4；其他原字节全部保持。其余61原库逐SHA保持，新增graphics-path JNI仍按既有锁SHA核验；64个so全部Deflate。

## 5. 最小车机验收与边界

1. 重新发现并核验在线S56_HQX／SDK28、已安装包签名兼容后保留数据覆盖安装此同SHA包，正式入口启动。确认真实地图／双Surface／进程和无linker或native致命异常。新增代码范围尚未经过目标Android linker实际装载；异常跨wrapper栈展开未验证，未新增通用异常处理。
2. 安装后重新选择一次“静音”，确认普通运行状态true且 `IcarMapMute user mute=1 persistence=saved`，此日志同时意味着setter接受、用户层回读正确和SaveData返回成功。旧版本未保存的RAM选择无法从空偏好推断。
3. 停止进程再启动，观察 `restored user mute=1`、菜单静音及首条地图播报被抑制；随后实际车辆下电上电复测。进程重开与实体上电分开记录，不以Activity warm resume代验。
4. 开始／恢复导航和后续系统非零音量回流仍保持普通静音；零媒体音量时可沿原行为静音，不把导航自动升音量路径称为已取消。分别选择四种有声风格，确认 `user mute=0 persistence=saved`、相应风格与再次冷启动有声；再选静音后重新启动保持。
5. 来电／临时静音恢复、导航／巡航切换与用户所述两项设置、交通灯播报逐项观察；与音乐和歌词同时使用，确认地图选择未改变媒体音量或来源。

原Config后端已静态追到serialize／AES、临时文件write／flush、可选sync、close及rename；`SaveData(true)`本身不控制sync标志，也不检查每个flush／sync／close返回，未见rename后目录fsync。因此本机替身保存和返回true不能代替真实磁盘读取／上电，也不承诺任意瞬断下的掉电原子性。用户两项off控件的完整场景语义仍按研究边界，不用它们替代全局普通静音。
