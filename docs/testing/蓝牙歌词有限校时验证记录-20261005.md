## 实现与合同

- 事件 owner 仍是[媒体适配器](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentMediaAdapter.java>)。新sequence仍发布真实媒体事实，播放状态不因位置重复而丢失。对应位置的PlaybackState含非零原始更新时间时，独立传递样本时间；原始位置字段缺时间或与Parcelable位置不符时使用接收时间。过期／未来的原始位置不通过新接收时间洗成新样本，状态仍按本次接收事件处理。
- 准入 owner 仍是[唯一时间线](<../../source/amap-9.5.0.600013/content-compose/runtime/com/icar03/content/runtime/lyrics/MediaSessionTimelineTracker.kt>)：同录音、连续正速播放内，同值位置在350ms短窗口不重锚，重复不能延长这个窗口；位置capture严格早于最新已接纳capture时拒绝。同毫秒的有效seek仍兼容。既有同sequence、来源／录音、0—1500ms年龄及MediaSession排序门禁保留。
- 将新位置按名义速度投影到同一now，与当前已呈现位置相减。绝对差不超过250ms时，从旧轨迹当前sample建立有限校正；至少1000ms且校正斜率不超过名义速度的8%，到期自动正常速度，无新增ticker。250ms包含现场已观测145ms负校正并留余量；350ms和8%是本轮工程起点，未称为平台参数。
- 超过250ms的跳转、有效零点、初始化、曲目／来源更换及播放模式／速度变更立即定位或冻结；恢复检查点和reset清校正。微小seek与采样噪声仅凭位置不可完全区分，微小seek会在有限校正期内收敛，1x最大250ms误差约3.125秒；不能宣称任何微小seek都瞬时对齐。
- [PlaybackTrajectory](<../../source/amap-9.5.0.600013/content-compose/model/com/icar03/content/model/PlaybackTrajectory.kt>)只是不可变采样／截止时间表达式，不接收事件、不保存第二状态机。canonical [LyricsPlaybackAnchor](<../../source/amap-9.5.0.600013/content-src/com/autonavi/amapauto/content/ContentPorts.java>)持有它，经Mapper传给UI，Store语义边界与绘制／词间唤醒消费同一表达式。结束／切歌旧正文冻结时清除活动轨迹，保留最后sample；无校正的速度及整数边界合同保留。

## 用户手动核对

另一对话打包并由用户安装后，按同一手机和同一录音核对：

1. Apple Music连续播放密集逐字段，观察已亮前沿是否还短距撤回；QQ／网易云用同录音对照。当前车机事实不能确认手机App身份，不声称Apple专属分支已验证。
2. 分别向前／向后拖动约5秒并回到0，应立即切至对应句和词；很小拖动允许上述有限收敛，不锁住旧高亮。
3. 校时期间暂停，应冻结；恢复继续推进。切歌、下一曲及蓝牙→本机→蓝牙，应清旧校正并沿既有录音身份交接。
4. 观察一句跨到下一句和真实间奏时，当前句、三点与逐字进度一致；蓝牙暂停回报一段时间时，不能持续偏速累积漂移。
