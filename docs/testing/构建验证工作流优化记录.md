# 构建验证工作流优化记录

本轮按已批准的施工效率分析修改本机工具链和工作流，保留并行中的车控、歌词及预览改动；没有提交、安装、启动车机或执行车辆写入。本记录验证工具行为，不替代当前整合产品的全量或车机验收。

## 1. 已落实

- [源码验证入口](<../../scripts/validate-content.mjs>)依据当前Git改动与Gradle依赖图动态选择模块，包含新增model；支持定向模块／测试和可选Lint。先编译所选测试，失败后不启动测试。文档范围只做静态检查，缓存复用与本次执行分别记录。
- [APK核验入口](<../../scripts/test-content-host.sh>)只检查指定签名包及其相邻原primary DEX，报告绑定APK SHA；移除隐式源码全量回归。
- [正式构建入口](<../../scripts/build-content-apk.sh>)增加早期结构检查、单调阶段计时、源码／公开工具输入指纹与稳定性校验，恢复默认Kotlin增量；保留既有最终签名、资源、DEX和native门禁。
- [Compose构建](<../../scripts/build-compose-content.mjs>)使用[Java批处理helper](<../../scripts/ComposeBuildTools.java>)及逐文件SHA验证的固定输入缓存；R、资源链接、R8与最终核验继续当次执行。
- [共享协调及缓存](<../../scripts/content-workflow.mjs>)覆盖正式构建、源码验证和独立Compose诊断。死亡owner恢复通过原子恢复目录串行并重新读取owner，避免删除另一个进程刚建立的活锁；不阻止编辑器直接写源，所以指纹仍必要。

操作方法与复用边界见[构建与验证入口](<../operations/构建与验证入口.md>)。
