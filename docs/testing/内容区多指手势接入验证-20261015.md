# 内容区多指手势接入验证（2026-10-15）

## 需求与输入

沿正式高德9.5／125%工作树实现2／3／4指各上／下／左／右共12项手势。用户确认默认二指右滑进入沉浸式全屏、二指左滑退出，其余无；仅支持全屏的页面可执行，当前为歌词页。设置首页“其它”增加“手势操作”，二级页按二指／三指／四指三组配置三种动作。当前工作树已有歌词、巡航、图标及研究改动均保留，不借历史包结果代验收本轮。

## 真值与实现

- `GestureCommand / GestureAction / GesturePreferences`拥有稳定身份、动作值和默认映射；`ContentPreferenceStore` schema10与唯一`ContentStore`持久化，State不可变快照经Mapper／Binding投影至UI。
- `MultiFingerGesturePolicy / Core / Modifier`按既有[最终方案](<../plans/内容区多指方向手势最终施工方案-20261010.md>)实现；官方Foundation1.7.6处理pan、centroid size、zoom、rotation，纯核心固定触点ID与群组，首次UP冻结最后完整有效MOVE，全抬后只提交一次。
- 根Initial接管，多指所有权同步提供给跨控件子树；Quick／Dock丢弃草稿，Boundary取消反馈，歌词／Pager放弃候选；单指已拖动的序列不可升级。手势意图静音，接受的按钮及无障碍点击仍沿既有点击声路径。
- 根仅形成`GesturePerformed(command)`离散意图，Binding `currentPresentationState()`从唯一Store的同一次最新不可变快照叠加其真实模态owner；未运行时返回空，不发布Flow、不保存偏好、不读取系统服务。`canDispatch()`以此拒绝无映射和无能力意图。BoundPanel交Host后，`MultiFingerGestureRouting.resolve()`与页面／生命周期资格共用同一接受快照，调用既有Enter／Exit及MapPresentationPort；准备完成时再次检查新页面／模态。原SplitPanelController保持唯一Divider与动画真值。
- 后台Store先reduce、主线程UI稍后coalesce发布时，旧UI的“无”不能提前丢弃新命令，旧UI的“进入”也不能绕过最新取消绑定。新增实际PAUSED Looper＋worker join的正／反映射、页面和合并发布测试；API读取前后StateFlow保持原引用，服务读取及偏好写入计数不变。
- 专门核对真实Compose1.7.6取消路径：`onCancelPointerInput()`派发已消费的合成Release；适配器在自身消费前归一为Cancel，不能误当正常全抬而提交已冻结动作。
- 手势只随输入事件计算，无后台轮询、速度采样器、持续帧时钟或新运行时依赖。每组最多4点；默认参数尚不代表车机触感标定或量化FPS通过。

## 验证中纠正的事实

首轮整合UI1162项有2条既有播放图标冷加载像素断言失败：原测试把glyph左上像素当成背景，而前轮32px图标已按可见墨迹收紧边界，实际两点均在实心三角内。已复用同文件的区域形状核验，中心填实比例1.0、右上外部0.0，继续保留原资源／未就绪语义、冷加载时序及反向逐像素保留，图标生产实现未改。Host旧48dp来源测试同步为已存在的100px物理热区；模态用例经唯一Binding真实打开设置，不再手改投影或向未具能力的来源发送打开事件。修正后均纳入最终稳定全量通过。

实际Compose1.7.6回归核对还纠正了两项输入假设：Final为祖先先行，子层门禁变化应在Main关闭；坐标全不变的MOVE会被`Node.buildCache()`过滤，最新非Compose门禁测试需注入真正移动的帧。菜单Back由原生Popup窗口的物理按键入口派发，不绕过窗口向内层ComposeView注入。文字布局检查读取实际Text子节点，不向clickable容器索取不存在的布局语义。后台Store已新、StateFlow仍旧的实际时序缺口则通过唯一Binding接受快照及根命令语义修复，并用worker排队正反映射／页面反例验证。
