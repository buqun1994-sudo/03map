# Dock上限与歌词切歌过渡验证记录（2026-10-04）

## 1. 用户目标与范围

用户要求保留当前Dock按钮数量，但含车锁绝不能超过7；新增快捷页功能不得自动进入Dock。前奏／间奏三点放大到Apple Music式比例；歌曲结束／切歌时旧歌词原位渐隐，新曲首行定位后渐显，同歌逐字、译文和完整正文补齐无需重开渐显。继续沿用增量事实投影、唯一时间线与低开销文档／纹理worker。

本轮仅改正式内容链与相关回归、产品／owner文档，保留会话开始时已有的构建流程优化和摄像头探针。签名候选完成前沿用上一轮离线、自行上车测试边界；随后用户明确“车机在线，可以直接装”，本轮改为重新发现车机、核对原安装签名并保留数据覆盖安装／启动检查，实际结果见第3.4节。

## 2. 已定位问题与实现

- 快捷页和Dock原来都枚举`ShortcutId.entries`；新增快捷项会自动增长Dock。当前由`DockShortcuts.items`显式列出原七项，限制含车锁最多7、去重及唯一车锁居首，Dock自身宽度／遍历仅消费此清单；状态／事件／原厂图标／按压仍共用既有owner。
- `LyricsPage()`原先正文为空立即销毁视窗、按transport recordingKey重建。正常端点的业务游标保留末行；不能把问题归因于端点游标回首行。先收到旧元数据对应的合法零位置、后收到新歌metadata时，旧视窗有可能先450ms滚到首行／前奏，这是源码可复核的条件链，本轮没有实车回调序列证据。
- 呈现交接由新`LyricsBodyTransition()`持有，消费既有Timeline tracker的稳定录音代际与Store明确next意图；transport key继续隔离迟到结果。旧歌词保留最后已绘制的文档、源位置、词墨与实际偏移，停止travel／媒体帧／worker／拖动回跟，180ms原位淡出后才挂载新录音文档；新曲在透明阶段首行／真实前奏定位并260ms淡入。唯一可信游标不改写，进入后继续正常跟随。
- 同歌元数据后补／ID补齐／时长小漂移不制造新录音；临时空正文保持原pair，新正文真正准入后按可见锚替换，不重fade。真实seek、pause及unknown保位继续由既有合同负责。应用内next在明确意图时先冻结，失败／单次6秒超时恢复实际歌词，generation真变才确认。
- 三点直径从6dp增至12dp、圆心间距从14dp增至22dp，总宽56dp；64dp原等待槽、真实gap准入、半开区间、普通LRC禁止猜间奏保持。绘制与可见门禁使用同一radius。
- 淡化直接乘入现有Paint alpha，覆盖单纹理、逐字／彩色cell批次、cold StaticLayout fallback和等待点；未新增viewport saveLayer、截图冻结、Bitmap淡化缓存、轮询或第二媒体ticker。切歌交接最多一个歌词renderer；同歌异步升级暂留last-painted缓存／切片／focus／强调引用，下一次实际绘制即更新，沿用每缓存12MiB预算而不将它当进程峰内存。转场帧只在有限180／260ms窗口活跃，后台／失焦取消travel与worker、不补播；手动浏览恢复时重排单次4秒回跟。
