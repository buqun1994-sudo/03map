已完成默认开启的“显示歌词注音”开关，位于“显示歌词翻译”之后。所有来源的真实注音沿既有字段、录音证明、Store时间线、缓存及渲染主链处理，普通分屏与沉浸式全屏共用门禁。本轮完成稳定正式源码快照的运行库完整回归、相关UI合同、原生帧、Lint、正式签名构建及独立包级核验；未能连接车机，未安装或宣称在线注音验收。

统一事实为 `LyricsResult.romanizedLyrics → timedLines() → ParsedLyricLine.romanization → ContentPorts.LyricsLine.romanization → LyricLine.romanization`。显示偏好独立保存在`content_preferences_v1` schema9的`lyrics_show_romanization`：默认、旧版本缺键、错误类型均开启，显式false持久化，副本隔离。Store／Binding／Mapper投影到`LyricRenderStyle.showRomanization → LyricMetrics.showRomanization → LyricInkRenderer`，关闭后不对注音轨做排版或保留其行高；翻译、原文、真实词轴、背景词、声部和缓存仍保留，切换不重启检索。

Apple新TTML只有部分注音／翻译时，复用既有LRC一对一对齐在同一正文轴逐行“新值优先、旧值回填”，避免同一时刻合成矛盾附轨。结构化TTML缺轨时才构造回填轴与按时刻索引；不逐行扫描全部附轨、不重挂主TTML时间。附轨700ms、词轴120ms容差沿现有Parser。完整TTML不新增回填工作，歌词测量与纹理生成仍在既有worker。

CJK实际正文缺足够注音时可在指定来源自身阶段结束后补强：注音覆盖阈值为50%，拉丁主体不额外发仅为注音的请求，缺声部不触发。质量仍为真实逐字＞有效翻译逐句＞普通逐句＞纯文本；辅助升级保留已有能力、同录音proof和原时长门禁。汉语拼音、注音字母、日／韩罗马音及其它有效字母附轨可计入覆盖，同脚本正文改写无注音能力信用。原20秒整轮、1800ms目录、正文两路／增强一路及共享8线程预算保持。

自动缓存质量版本由4升5，quality4正文继续显示并按原策略后台复核；人工优先、1GiB预算、失败不计有效刷新与事务准入保持。
